## Исторические документы — не текущие задачи

- `docs/plans/PROJECT_KNOWLEDGE_BASE_SPEC.md` и PROJECT_DOCUMENTATION_SYSTEM.md
  уже обозначены архивными; ссылки на них есть в plans/README.md и PLAN_SOURCES_AUDIT.md.
- `docs/plans/ADMIN_UX_UNIFICATION_SPEC.md` уже архивный. Его прежние решения
  используются при подготовке нового этапа, но не подтверждают качество визуала.
- `docs/knowledge-base/modules/catalog/planned.marketing-catalog.md` уже архивная
  карточка прежней границы, принадлежит marketing.analytics в registry. Действующий
  модуль — marketing.analytics, не второй planned module.

Эти файлы не нужно перечитывать для штатной разработки вместо канонов. Удаление
архивных Markdown освобождает мало места; прежде нужно решить, нужна ли история,
и убрать ссылки/ownership. В этом проходе файлы, копии, ветки и задачи не удалялись.

## Порядок следующей работы

1. Завершить передачу VSL; получать отдельные разрешения на конкретные свободные копии.
2. Разобрать уникальные остатки старого корня по владельцам: голосовые/отзывы,
   каталог контента, AI-исследования. Не публиковать приватное и незавершённое.
3. Довести общую локальную папку до рабочего последовательного режима; не
   переключать грязную основную ветку вслепую ради новой схемы.
4. По ADMIN_VISUAL_CONSOLIDATION провести сверку и согласовать общий вид админок.
5. Далее отдельными проходами сверять коммерцию/права/юридические документы,
   Telegram/MAX, курсы и приложения, маркетинг/атрибуцию, эксплуатацию/backup.
   Точные владельцы берутся из modules.toml, а не из этой очереди.

Видео и Писарь имеют входы/каноны после прежних проходов; это не доказательство
идеальности всей реализации или завершённости всех новых черновиков.
