# Аудит глобальных скиллов

Дата: 25.08.2026  
Статус: `current`

## Фактический состав

Активно установлены 13 скиллов из комплекта Малянова и 15 reviewer-агентов. Комплект
скопирован полностью: названия исходных и установленных пакетов совпадают. Markdown был
адаптирован конвертером Claude → Codex, поэтому побайтовое отличие ожидаемо. Дополнительно
установлен наш `sergey-development-workflow`, которого в исходном комплекте нет.

Старых активных копий в `~/.codex/skills` и проекте не найдено. Исходный checkout
`molyanov-ai-dev-review` остался в служебной папке старой визуализации, но не участвует в
skill routing и не загружается новым чатом.

## Что оставить

| Группа | Скиллы | Решение |
|---|---|---|
| Обычная разработка | `code-writing`, `code-reviewing`, `test-master`, `security-auditor` | Оставить; дают пропорциональную реализацию и независимые проверки. |
| Интерфейсы | `layout-writing`, `layout-reviewing` | Оставить; запускаются только при фактической работе с интерфейсом. |
| Большие задачи | `user-spec-planning`, `sergey-development-workflow` | Оставить; AGENTS ограничивает их средними и крупными задачами. |
| Документация и инфраструктура | `documentation-writing`, `infrastructure-setup` | Оставить как специализированные, не запускать для обычной правки текста/кода. |
| Редкие явные задачи | `project-initialization`, `prompt-master`, `skill-master`, `methodology` | Оставить: их узкие descriptions не вызывают заметного расхода без подходящего запроса. |

Наличие скилла само по себе почти не расходует контекст: постоянно видны только name и
короткий description; полная инструкция загружается после срабатывания. Поэтому удаление
редких, но корректно маршрутизированных скиллов не ускорит обычные задачи заметно.

## Что исправить

1. Несколько адаптированных инструкций всё ещё считают отсутствующий `~/.claude` источником
   истины и требуют Bash-скрипт `sync-to-codex.sh`. На этом Windows-компьютере такого каталога
   и Bash/WSL нет. Это реальная нерабочая ветка.
2. `user-spec-planning` содержит только Bash initializer. Нужен portable Python/PowerShell
   путь либо явно описанный ручной fallback.
3. `documentation-writing` направляет проектную документацию только в
   `.claude/skills/project-knowledge/`, тогда как этот проект уже имеет канонический `docs/`.
   Проектный `AGENTS.md` должен иметь приоритет, а скилл не должен создавать второй набор.
4. Тяжёлые review/subagent-процессы должны оставаться пропорциональными риску; проектное
   правило уже ограничивает их средними и крупными задачами.

## Что не делать

- не удалять reviewer-агентов: они не запускаются сами и полезны для свежей проверки;
- не переносить их тексты в `AGENTS.md`;
- не создавать проектные копии глобальных скиллов;
- не чистить служебную папку старой визуализации как часть проекта: это не активный дубль и
  её удаление не влияет на routing.

## Выполненная очистка

- `user-spec-planning` получил нативный PowerShell initializer для Windows и Python-вариант для
  сред с Python; повторный запуск не перезаписывает существующие файлы.
- `documentation-writing` теперь сначала следует project `AGENTS.md` и существующему docs-router;
  он не создаёт параллельную `.claude`-базу рядом с каноническим `docs/`.
- `skill-master`, `infrastructure-setup` и `methodology` больше не считают отсутствие
  `~/.claude`/Bash ошибкой Codex-native установки; `methodology` и
  `documentation-writing` используют проектный `AGENTS.md` и уже выбранный docs-router,
  а не навязывают `CLAUDE.md`/`.claude` вторым источником.
- PowerShell initializer проверен созданием и повторным открытием тестовой feature-папки;
  placeholders даты и slug были заменены.
