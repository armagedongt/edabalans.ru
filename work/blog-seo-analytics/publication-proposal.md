# Пакетная публикация Markdown: предлагаемый маршрут

Статус: `draft`. Владелец: `platform.blog`. Реализация и импорт не выполнены.

## Реально ли без deploy каждой статьи

Да. Публичный renderer остаётся существующим; MD, metadata и immutable media
публикуются административным API. Развёртывание понадобится при изменении
renderer/компонентов, но не для следующей статьи в поддерживаемом формате.
Нельзя просто добавить PUT поверх текущего Git-reader: это даст две истины.

## Переиспользование и единый источник

Использовать существующий `managed_document_versions`, optimistic expected_version,
hash и rollback как новую версию; новый параллельный движок версий не нужен.
Текущий public-site API имеет другой whitelist и не является готовым API блога.
Блог получает свой сервис публикации и минимальный административный маршрут,
общий require_admin и тот же безопасный Markdown renderer.

Перед переключением девяти активных материалов проверить backup и восстановление,
сравнить все тексты, metadata, media hashes, URL и writer artifacts. После импорта
reader имеет только один активный источник. Исходные Git-файлы становятся
зафиксированным архивом переноса, а не вторым оперативным редактором.
Импорт/смена источника требует отдельного подтверждения владельца.

## Публикационный пакет

Одна статья: стабильные source_id/slug; pure Markdown; metadata автора, проверенных
дат, excerpt/category/topics; editorial CTA отдельно от текста; media/provenance;
related override или auto; validation/review pass именно текущего hash.
Raw HTML/script и неизвестные директивы отклонять. Не добавлять медицинские
изменения автоматически. Дата исходника отдельно от даты blog edition.

Сначала upload immutable media с hash и безопасным MIME/size/path, затем проверить
весь пакет; активировать article bundle атомарно. Если media/validation не прошли,
старую публикацию не менять. Конфликт expected_version возвращает 409, не затирает
чужую редакцию. Повтор запроса с тем же idempotency key не создаёт дубль версии.

Batch возвращает результат **для каждого** source_id: published, unchanged,
conflict или rejected с причиной. Не объявлять всю партию готовой при частичном
успехе. Каталог, related и sitemap читают только активные publish-ready bundles.
Откат сохраняет старые media URLs и восстанавливает metadata/тело согласованно.

## Related без ручного выбора под каждой статьёй

Предлагается детерминированный подбор из опубликованных: общие редакционные
topics, продолжение вопроса, практический следующий шаг; category — вторичный
сигнал. Исключать себя, drafts, повторы и дубли одного произведения. Не более
трёх, без искусственного добивания нерелевантными материалами при малом каталоге.
Ручной override приоритетнее алгоритма, причины выбора видны в preview.
Пересчёт после публикации не переписывает авторское тело. Просмотры могут стать
tie-breaker только после реальной аналитики, а не выдуманных рейтингов.

## Приёмка

Проверить admin access, sanitizer, stale write, повтор запроса, media failure,
partial batch, атомарную активацию, rollback, cache и неизменность прежних URL.
Проверить writer hash gate и запрет публикации pending/fail. Новые130материалов
не импортировать из каталога автоматически: карту и редакционные версии
сначала выбирает владелец.
