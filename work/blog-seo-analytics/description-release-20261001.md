# Выпуск description — 01.10.2026

Статус: `draft`. Модуль: `platform.blog`.

## Согласованное поведение

Если в начале Markdown есть отдельный description, используем его. Иначе —
первые два предложения авторского текста, максимум 300 символов с сокращением
по границе слова. Заголовки, картинки и конечная компонентная CTA не являются
началом описания. Смысл текста не переписываем и ключевые слова не добавляем.

Ручной формат для существующего Markdown-редактора:

```markdown
---
description: "Ваш собственный анонс статьи."
---

Начало статьи.
```

Поле можно изменить вручную; сохранить — оставить на модерации, опубликовать —
обновить публичную страницу. Смена только черновика не меняет поисковое описание.
Один источник описания используется для карточек, related, meta description,
Open Graph и Article JSON-LD. Старое поле excerpt манифеста не имеет приоритета.

## Последовательная production-проверка

`verify-descriptions-20261001.py` читает текущий опубликованный Markdown на
сервере, затем по одной проверяет публичные статьи. JSON-ledger записывается
после каждой проверки; после обрыва успешные неизменившиеся строки сохраняются.
Проверяются meta description, og:description и canonical. Нет записей в БД,
доступа к приватному хранилищу или вывода credentials.

Результат хранится в `descriptions-production-20261001.json`.
Его scope — только `description_only`: это не полный pass медиа, первичных
научных утверждений, редакционной структуры, аналитики или всего SEO статьи.
