# Измерения блога: предложение, не подключённая аналитика

Статус: `draft`. Дата: 17.09.2026. Владельцы: `platform.blog` и
`marketing.analytics`. Сверено с ответом задачи «Я.Директ!» и main `f458798`.

## Подтверждённое состояние

Существующий счётчик Метрики — **97331502**, часовой пояс Europe/Moscow.
В блоге загрузчик Метрики сейчас отсутствует. Цели `blog_*` не созданы.
Атрибуты `data-tracking-key` сами события не собирают. Действующие bot_start и
purchase_paid имеют исторические дубли целей; этот проект их не исправляет.

Нужен узкий общий загрузчик существующего счётчика с защитой от повторной
инициализации, а не копирование всего runtime интенсива. Перед включением
проверить настройки доменов/фильтров счётчика с владельцем Директа.
Cookie-плашка — уведомление, а не CMP; её закрытие не является идентификацией.

## Предлагаемый контракт

Общие поля: `event_id` UUID, `occurred_at` ISO, `page_id=blog_article`,
`article_id` из manifest.source_id, `article_slug`, `content_version`,
`session_id` одной загрузки страницы, `page_path` без query, `placement`,
`target_type`, при необходимости `target_article_id`, `progress_pct`,
`active_seconds`. Использовать внешний адрес `/articles/slug`, а не backend rewrite.

| Событие | Когда и что означает |
|---|---|
| `blog_article_view` | один раз на загрузку статьи; не дополнительный pageview hit |
| `blog_read_progress` | пороги 25/50/75/100% только авторского тела; не hero/CTA/related/footer |
| `blog_cta_click` | фактический клик, продукт и placement; не Start и не покупка |
| `blog_related_click` | исходная и целевая статья, один event на клик |
| `blog_popup_view` | только реально показанная плашка интенсива |
| `blog_popup_close` | способ закрытия; переход по CTA не считать отказом |
| `blog_popup_click` | переход по CTA popup; не начало прохождения |

Активное время считать только в видимой вкладке с ограничением idle, не обычный
wall-clock. Предложенное «вероятное дочитывание»: 90% тела плюс треть расчётного
времени чтения. Методика ещё ожидает ответа владельца и не доказывает прочтение.

Нельзя отправлять email, телефон, CRM user_id, токены E/U или signed source_context
в анонимные события/Метрику. ClientID — идентификатор браузера, не пользователя CRM.
Общий homepage collector принимает только события главной: блог в него не писать.

## Переход в бот и покупка

Сохранять существующий U journey: клик → подтверждённый Start → доступ/покупка.
Подготовленный URL не считать кликом, клик — Start. Идентификатор статьи/placement
добавлять к существующему attribution context совместно с его владельцем, не
затирая рекламные utm_content/ad_id/yclid. Текущий startlink API новые произвольные
поля молча не сохраняет: это требует изменения контракта, не одной ссылки.

Покупка подтверждается существующим платёжным callback, не возвратом браузера.
Текущий offline export использует yclid; передачу органических конверсий по
ClientID пока не считать подключённой. Не связывать посещение с человеком по email.

## Проверка перед выпуском

- Ни двойных pageview/событий, ни цели на каждом проценте прокрутки.
- Фоновая вкладка, idle и footer не увеличивают чтение.
- Реальный CTA/related/popup клик отражён с верной статьёй и версией.
- Закрытый popup не появляется чаще утверждённого интервала; ошибка identity
  не становится доказательством отсутствия человека в боте.
- Отчёт отличает «не подключено» от нуля; неизвестный этап остаётся неизвестным.
- Collector имеет явный разрешённый route: blog Caddy сейчас не открывает `/api/*`.

Настройка целей и включение аналитики **не выполнялись**. Общий consent-порядок
не менять побочно. [ClientID](https://yandex.ru/support/metrica/ru/objects/get-client-id)
и [UserID](https://yandex.ru/support/metrica/ru/objects/set-user-id) — разные интерфейсы.
