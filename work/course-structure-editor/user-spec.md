# User-spec: редактор структуры курсов

> **Executor instruction.** If the project has Project Knowledge, first read its main `SKILL.md`,
> then only the materials it routes to for this task. Read `decisions.md` if it exists. Work from
> the root of the project this spec belongs to. Implement the entire user-spec. Use the execution
> skills appropriate to the work.

## What We Are Building

В общей защищённой админке появляется модуль **«Курсы → Редактор структуры
курсов»**. На первом этапе в нём доступен один курс — `masterclass-21`.

Редактор управляет только структурой курса и короткими атрибутами страниц дней.
Тела статей, содержимое приложений, правила допродаж и Telegram-сценарии сюда не входят.

Страница курса — одна вертикальная лента из 21 раскрывающегося дня. Интерфейс
намеренно простой, без отдельного дизайн-проекта.

## Why

Сейчас программа хранится в `content/masterclass/course/course.json`, а старый
`/admin/masterclass-course-preview` является автономным устаревшим прототипом и
показывает ложную структуру. Нужен один понятный экран, где изменение названия или
короткого текста сразу применяется во всех клиентских местах, читающих этот атрибут.

## Constraints

Входит:

- защищённый каталог курсов и редактор структуры Мастер-класса;
- редактирование атрибутов дней, материалов и задания;
- скрытие любого материала без физического удаления;
- добавление, редактирование, перестановка и скрытие пунктов задания;
- немедленная публикация одной кнопкой с версионной историей;
- динамическое чтение активной структуры runtime без перезапуска backend;
- исправление поведения галочек и сохранение уже полученного открытия дня;
- удаление старого тупикового предпросмотра.

Не входит:

- редактор тела статей;
- загрузка изображений и видеофайлов — только URL/ID;
- изменение порядка материалов, дней и системных шагов;
- добавление и удаление материалов, дней и системных шагов — это пока выполняется
  владельцем через отдельную задачу в чате;
- создание системных шагов, приложений, офферов и триггеров;
- редактирование цен и Telegram-логики;
- универсальный каталог названий продуктов и тарифов. Общий фундамент редактора
  должен позволить подключить такой документ отдельной схемой позже, но сам каталог
  сейчас не создаётся и действующую страницу цен не дублирует.

## Expected Behavior

Администратор открывает один защищённый экран, редактирует атрибуты всех дней в
длинной ленте и одной кнопкой атомарно публикует целую новую версию. Клиентский
курс и серверные проверки начинают читать её без restart. Структурные операции,
способные изменить порядок, в UI отсутствуют.

### Экран и поля

### Навигация

- `/admin` содержит раздел **«Курсы»**.
- `/admin/courses` показывает список доступных редакторов курсов.
- `/admin/courses/masterclass-21/structure` открывает редактор Мастер-класса.
- Старый `/admin/masterclass-course-preview` перенаправляет на новый редактор.

### Лента дней

Каждый день показан раскрывающимся блоком. В заголовке видны номер, название,
статус наполнения и число материалов. Переключателей «вперёд/назад» нет.

Поля группируются в порядке их использования на странице дня:

1. Название и навигация: номер и стабильный ID только для чтения; slug только для
   чтения; лозунг; название; необязательное короткое название для оглавления;
   краткое описание в оглавлении; вводный текст.
2. Медиа шапки: тип `нет/видео/изображение`; video ID/URL или image URL;
   продолжительность; комментарий о содержании видео; текст над и под медиа.
3. Материалы в фактическом порядке: ID и системный тип только для чтения; название;
   необязательное короткое название; краткое описание; примерное время;
   предусмотренный типом media/content URL или ID. Любой обычный или системный шаг
   можно скрыть и вернуть. Системный шаг можно переименовать и изменить описание,
   но нельзя переместить или изменить его тип, код, событие и привязку.
4. Текст после материалов и перед заданием.
5. Задание: заголовок, подводка и пункты с постоянными ID. Пункт можно добавить,
   изменить, переместить вверх/вниз, скрыть и вернуть.
6. Превью следующего дня: краткий тизер. Название берётся из следующего дня;
   отдельная копия `nextTitle` не редактируется.

Пустое необязательное короткое название означает «использовать основное название».
У неочевидных полей есть краткая подсказка «где используется».

### Сохранение и версии

- Одна кнопка **«Сохранить и применить»** проверяет весь курс целиком.
- При успехе сервер создаёт неизменяемую ревизию и атомарно делает её активной.
- Отдельных черновиков и отдельной публикации нет.
- Runtime использует одну активную ревизию; изменения видны без deploy и рестарта.
- Две вкладки не перезаписывают друг друга: устаревшая ревизия получает `409`.
- Ошибка сети, БД или валидации не применяет ни одну часть. Введённые значения
  остаются на экране, явно указано, что публикации не было.
- После успеха видны номер ревизии, дата и время.
- Хранятся последние 20 ревизий документа. Активная ревизия никогда не очищается.
- История скрыта в компактном блоке. Возврат создаёт новую активную ревизию из
  выбранного снимка, а не изменяет старую запись.

### Минимальный переиспользуемый фундамент

- В PostgreSQL создаётся общий минимальный механизм версий управляемых документов:
  тип схемы, стабильный ключ документа, номер, JSONB-снимок, hash, автор, время и
  признак active. В первой версии к нему подключён только документ структуры
  `course/masterclass-21`.
- Схема полей и серверная валидация выбираются по типу документа. Это позволяет
  позже подключить такой же курс или централизованный справочник названий и цен без
  переписывания хранения и механизма публикации, но не превращает первую версию в
  универсальный конструктор произвольных форм.
- Отдельные таблицы-справочники курсов, продуктов и тарифов сейчас не создаются.
- `course.json` используется для первичного seed и экспорта, но после миграции не
  является вторым runtime-источником.
- Все backend-проверки порядка, обязательных шагов, приложений, офферов, контента и
  галочек читают тот же активный снимок, что и frontend manifest.

### Совместимость пользовательского прогресса

- Редактор не меняет порядок материалов. Стабильные ID материалов не редактируются.
- Существующий позиционный `step_index` сохраняется: редактор не добавляет, не
  удаляет и не переставляет материалы, поэтому индексы существующего прогресса не
  меняются. Стабильный ID используется в структуре и снимке обязательности, но не
  требует рискованного преобразования исторического прогресса.
- Пункты задания получают стабильные ID; текущие числовые галочки однократно
  сопоставляются пунктам текущего active baseline по индексу. Уже сохранённые
  `true/false` переносятся, но неизвестную более старую редакцию текста или порядка
  восстановить невозможно и такая историческая идентичность не обещается.
- При первом открытии дня сохраняются revision и снимок стабильных ID обязательных
  материалов и пунктов задания. Редакционные тексты всегда берутся из active.
- Добавление материала через чат оформляется отдельной миграцией с явной проверкой
  влияния на позиционный прогресс. Редактор первой версии такую операцию не выполняет.
- Скрытый материал или пункт задания немедленно исключается из обязательности у
  всех, включая уже начавших день. Его прогресс и ID не удаляются.
- После повторного показа элемент снова обязателен для всех незавершённых дней, а
  уже завершённые дни не пересчитываются.
- Сервер хранит служебную revision последнего возврата элемента: обычный новый
  элемент не блокирует уже открытый день, но после явного цикла `скрыть → вернуть`
  становится обязательным для всех незавершённых дней.
- Завершённый день никогда не становится незавершённым из-за редакционной правки.
- Галочку можно поставить и снять после открытия задания.
- Задание открывается только после прохождения обязательных видимых материалов.
  Когда после этого все обязательные видимые галочки были поставлены хотя бы один
  раз, фиксируется необратимое завершение дня. Таймер отдельно определяет время
  открытия следующего дня. Последующее снятие галочки меняет её визуальное
  состояние, но не отменяет завершение, таймер и уже полученное право открытия.
- Убирается текущая ошибка `day_already_completed` при снятии галочки.

### Валидация и защита

- Страница и каждый API endpoint требуют действующую общую admin-сессию.
- Клиентский email Tilda не используется для административной авторизации.
- Сервер проверяет уникальность ID, 21 последовательный день, допустимые типы,
  длины, число элементов и неизменность защищённых системных полей.
- Форматируемые поля очищаются whitelist-фильтром; script/iframe и обработчики
  событий запрещены.
- Изображения принимаются только как допустимые HTTPS URL; video ID/URL — только в
  разрешённом формате.
- `contentAsset` разрешает только известные безопасные имена внутри каталога.
- Размер запроса ограничен.

### Ошибки интерфейса

- Невалидное поле подсвечивается рядом с конкретным днём и полем.
- Общая ошибка публикации показывается сверху и у кнопки сохранения.
- При потере сети введённый текст остаётся; повторное сохранение разрешено.
- При конфликте ревизий локальные данные не теряются до осознанной перезагрузки.
- При уходе со страницы с несохранёнными правками браузер предупреждает.

### Удаление старого прототипа

- Удалить только `backend/app/static/masterclass-course-preview.html`.
- Удалить старые ссылки, ведущие на него.
- Старый URL оставить redirect на новый редактор.
- Не удалять действующие `masterclass-first-days-preview.html`,
  `masterclass-preview.html` и `masterclass-admin.*`.

## Acceptance Criteria

- [ ] В общей админке открывается каталог курсов и редактор `masterclass-21`.
- [ ] Все 21 день показаны одной вертикальной раскрывающейся лентой.
- [ ] Редакционные атрибуты доступны, защищённые системные поля только читаются.
- [ ] Материалы нельзя добавлять, удалять или переставлять в редакторе; эти операции
      выполняются через чат с отдельной проверкой прогресса.
- [ ] Скрытие материала не сдвигает его и соседние индексы, не удаляет прогресс и
      исключает материал из клиентского интерфейса и обязательных условий.
- [ ] Системный шаг нельзя добавить, переместить или изменить его тип, но его можно
      скрыть и вернуть по общему правилу обязательности.
- [ ] Пункты задания можно добавлять, редактировать, переставлять и скрывать без
      потери ранее поставленных галочек.
- [ ] Первичный backfill галочек переносит их по индексам зафиксированного baseline;
      после перехода дальнейшая перестановка использует стабильные ID.
- [ ] Скрытый required-элемент сразу исключается из условий; повторно показанный
      снова обязателен только для незавершённых дней.
- [ ] Save создаёт и активирует целую ревизию; frontend и backend используют её без
      рестарта.
- [ ] Ошибка или конфликт не применяет изменения частично и не теряет текст формы.
- [ ] История позволяет вернуть прежний снимок; retention соблюдается.
- [ ] После однократного завершения снятие галочки не выдаёт ошибку и не отбирает
      следующий день.
- [ ] Старый статический прототип удалён, его URL ведёт в новый редактор.
- [ ] Неавторизованный пользователь не может читать или менять структуру.

## Testing

Минимальные надёжные границы:

- **Unit:** нормализация и валидация документа, вычисление обязательности и
  retention. Эти решения чистые и не требуют HTTP/БД.
- **Integration:** версии PostgreSQL, optimistic conflict, admin auth, миграция
  галочек на стабильные ID, атомарная публикация и runtime active snapshot. Риск
  возникает на границе сервиса и БД, поэтому unit недостаточен.
- **Journey/API:** последовательное прохождение дня, hide/re-show, галочки и
  необратимое открытие. Здесь совместно
  работают manifest, API и сохранённый прогресс.
- **Browser smoke:** форма из 21 дня, отсутствие reorder, сохранение и понятная
  ошибка. Полный новый E2E-фреймворк не добавляется: критическая логика проверяется
  на API/БД.

- Manifest: схема, enum, уникальные/защищённые ID, URL, HTML, content paths.
- Versions: seed, атомарная активация, hash, conflict 409, rollback, retention.
- Admin API: session required, полный save, отсутствие частичного применения.
- Runtime: активная ревизия видна manifest и проверкам без рестарта.
- Progress: числовые галочки мигрируются по ID; перестановка пунктов не меняет смысл.
- Journey: hide/re-show меняет обязательность по согласованному правилу и не меняет
  позиционные индексы остальных материалов.
- Journey: завершить день, снять галочку, сохранить завершение и следующий день.
- Routes/assets: редактор защищён; старый URL редиректит; старого HTML нет.

## Ручная проверка владельцем

1. Войти в `/admin`, открыть редактор Мастер-класса.
2. Изменить безобидный короткий текст и нажать «Сохранить и применить».
3. Проверить изменение в клиентском курсе без рестарта.
4. Вернуть предыдущую редакцию через историю.
5. На тестовом профиле завершить день, снять галочку и проверить отсутствие ошибки
   и повторной блокировки.

## Verification

### Agent Verification

- Запустить точечные unit/integration-тесты сервиса версий, admin API и прогресса:
  эти риски зависят от БД и серверных контрактов, поэтому одного DOM-теста мало.
- Запустить существующий journey Мастер-класса и новые сценарии галочек,
  hide/re-show и required snapshot: это минимальная граница, где совместно работают
  manifest и сохранённый прогресс.
- Запустить тесты маршрутов и admin auth для нового экрана и redirect.
- В браузере проверить загрузку всех 21 дней, сохранение, отображение применённого
  текста и отсутствие кнопок перестановки.
- После deploy проверить migration head, `/health`, защищённый editor URL и manifest
  реального курса.

### User Verification

Достаточна ручная проверка владельцем из предыдущего раздела. Она нужна только для
оценки удобства длинной формы и подтверждения фактического текста в клиентском UI;
целостность данных и правила прогресса должны быть доказаны автоматическими тестами.

## Risks

- Любое runtime-чтение старых глобальных `COURSE_*` создаст рассинхрон. Миграция
  завершена только после поиска всех обращений и journey-теста.
- Редактируемый HTML может создать XSS; очистка выполняется на сервере.
- Save влияет на production сразу; обязательны транзакция, конфликт версий и rollback.

## Accepted Decisions

- Сохранение и публикация — одно действие.
- Видимых черновиков нет; история скрыта и автоматически очищается.
- Порядок материалов и системных шагов в редакторе менять нельзя.
- Добавлять и удалять материалы в первой версии редактора нельзя; это отложено и
  выполняется вручную через чат.
- Крупная перестройка выполняется через чат отдельной задачей.
- Редактор материалов откладывается.
- Это первый экземпляр общего редактора курсов, но без преждевременного объединения
  с продуктами, тарифами и ценами.
