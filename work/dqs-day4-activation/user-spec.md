# DQS: раскрытие в четвёртом дне и постоянная ссылка

## Цель

Купленный вместе с Мастер-классом DQS становится доступен только в своём шаге
четвёртого дня. Клиент нажимает одну кнопку, сразу открывает дневник и получает
постоянную браузерную ссылку в Telegram, если Telegram уже связан.

## Пользовательский сценарий

1. До шага `day-04-dqs` в ЛК видно: «Куплено. Откроется в четвёртом дне
   Мастер-класса.» и «Продолжить Мастер-класс».
2. В материале дня 4 основная кнопка называется «Открыть мой DQS».
3. Сервер проверяет entitlement, legal, день, шаг и предыдущие обязательные
   материалы.
4. Допустимый запрос идемпотентно создаёт `app_revealed_dqs` и открывает DQS.
5. При связанном активном Telegram одна notification доставляет сообщение с
   `https://edabalans.ru/dqs`.
6. Повтор reveal не создаёт второе автоматическое сообщение.
7. Если Telegram не связан, DQS всё равно открывается.
8. После reveal в ЛК доступны «Открыть DQS» и небольшое действие «Не нашли
   ссылку? Отправить ещё раз».

## Не входит

- Telegram Mini App и service-auth для Mini App;
- MAX-доставка;
- изменение правил strength, recipes и metabolism;
- отдельная авторизация DQS;
- перенос или перезапись существующих дневников.

## Критерии приёмки

- [x] DQS с entitlement, но без reveal закрыт по прямому API и показан в ЛК как
  `entitled_locked`.
- [x] Преждевременный или подделанный reveal отклоняется.
- [x] Первый допустимый reveal открывает DQS.
- [x] При Telegram создаётся одна notification со стабильным deduplication key.
- [x] Повтор reveal не создаёт дубль.
- [x] Без Telegram reveal не откатывается.
- [x] Отдельная отправка убрана из материала и доступна только в ЛК после reveal.
- [x] Telegram использует обычную ссылку и кнопку на `https://edabalans.ru/dqs`.
- [x] Непустое прежнее пользовательское состояние сохраняет доступ; клиентское
  `dqs_opened` и `admin_open` его не создают.
- [x] Ручная повторная отправка ограничена одним запросом в минуту.
- [x] Каноническая документация описывает ровно этот контракт.
