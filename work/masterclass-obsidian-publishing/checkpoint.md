# Публикация МК из Obsidian — подготовка

Дата: 16.09.2026. Статус: исследование, не реализация.

Владелец согласился на explicit publish без автопубликации при сохранении и
попросил весь МК связать с существующим ЛК. Кнопка Obsidian — запрошенный интерфейс,
не установленный компонент. Существующий editor package найден в
`.codex-worktrees/masterclass-markdown-canon-20260912/content/masterclass/editorial`:
program.md, 20 файлов дней и 52 Markdown-материала. Не объявлять это последней
утверждённой редакцией до сверки с названным владельцем старым чатом.

Проверены доступные карточки, publisher/validator и доступная версия origin/main.
Фокус code-researcher — существующие API, source mapping, special types, media,
конфликты и сохранение прогресса; только code-research.md принадлежит исследователю.
Root грязный, ветка codex/markiting; чужие изменения и Git lock не трогаем.

Уже установлено: отдельные статьи публикуются по HTTP API с версиями, общий
editorial publisher использует SessionLocal напрямую, а не HTTP. Markdown
access-gates не обрабатывает; вопросы анкет остаются в коде. Локальные assets
требуют отдельной загрузки, преобразование пути не является загрузкой файла.

До реализации требуется один пакет ответов: окончательный source/старый чат,
охват текста анкет, выбор поведения кнопки. Сохранить вопросы и ответы в
logs/userspec/interview.yml. Затем полнота интервью, ТЗ и пропорциональные reviews.
Исходники/production не изменены, plugins не установлены, публикация не запускалась.

## Изменение поручения владельцем

Кнопки Obsidian и новая API-автоматизация отложены. Сначала найти прежний чат,
показать source на утверждение, затем каталогизировать материалы по дням и дать
владельцу редактировать их. Первый выпуск будет ручным через Codex по отдельной
команде. Вопросы анкет/подсказки включены в будущую Markdown-редактуру. Целевых видов
материала два: статья и комбинированный. DQS и его код исключены.

Направлены вопросы «Я.Директ!», «VSL», «Дизайн». Ответы записаны в
source-confirmation.md. Найден единый кандидат source, но авторство конкретного
чата не доказано; подтверждение источника владельцем ожидается.

Независимо создаётся demo/: исходный MD, лаборатория дополнительной Obsidian
разметки, карта переноса и read-only localhost preview. Настоящий program.md
не получает случайного step_id: тест дня 1 существует только в песочнице.
Три узких теста прошли: изображения/позиция, renderer/якоря, whitelist HTTP/no POST.

## Проверка локального прототипа

Финальные три теста прошли повторно, включая два GET после смены сохранённого
MD-источника без перезапуска сервера. Сняты полные страницы материала и первого
дня на 360/430/619/620/621/768/1440px; у материала подтверждены Inter 400/600/800
и загрузка медиа. Проверено раскрытие содержания и переход к #section-1 на 360px.
Снимки — внешние временные артефакты, не новые канонические документы.

Code review выявил расхождение актуального ARTICLE_STANDARD и обработчика
исторической ревизии 99051db. Исправлены только заявления карты/README: `>` и
`:::note` стенда теперь явно обозначены историческим поведением, не текущими
редакторскими правилами. Актуальные callout-red/green/blue не реализовывались
и production не проверялся. Стенд — сравнение и согласование, не готовый
универсальный публикационный конвертер.

Запуск: python work/masterclass-obsidian-publishing/demo/serve_demo.py;
http://127.0.0.1:8794/day-1. Процесс локальный, без автозапуска. Из root-vault
Obsidian: Ctrl+O → «01-99 — Тест переноса Markdown» / «Возможности Obsidian — лаборатория».
Ссылка на demo README добавлена в work/obsidian-source-catalog/catalog/Старт.md.
Настоящий editorial worktree повторно проверен: чистый. Каталог по дням
ожидает прямого подтверждения Сергеем найденного источника.

## Новый локальный этап: образец в настоящей оболочке курса

По новой просьбе владельца образец больше не открывается отдельным белым полотном.
serve_demo.py отдаёт существующий course shell из фиксированной ревизии f151218;
локальная виртуальная программа добавляет первый тестовый шаг в день 1, исходные
шаги блокирует и не загружает их contentAsset. Сам program/seed не переписан.
Bootstrap только задаёт localhost context, отдельный localStorage и маршрут теста;
не выдаёт native identity, не обращается к production API. CSP разрешает точными
хешами доверенные inline scripts оболочки; авторский MD приходит отдельным JSON.

В образце оставлены h1+h2, h3 удалён. Штатный configureArticleToc собирает h2
при >=3 разделах: desktop вертикальная кнопка/popover, mobile центральная кнопка
в sticky header. Пройден браузерный путь на 360/1440: 8 ссылок, раскрытие/закрытие,
перевод фокуса к section-2; мобильное меню открывается, после анимации sidebar
занимает 0..327.59px. Ошибок JS не обнаружено. Три unittest повторно прошли.

Code review и layout review нового этапа — clean. Layout проверен на
360/430/619/620/621/768/899/900/901/1440px, обе картинки разрешились, Inter
400/600/800 подтверждён. documentWidth=viewport на всех десяти ширинах.
Ограничение evidence: capture stable/mutationQuiet/evidenceComplete=false на
странице с обновлениями оболочки, несмотря на resolved assets/completed scrolling;
нельзя утверждать полную quiescence capture pipeline. Это не доказанный дефект UI.

«Дизайн» отдельно подтвердил canonical файл/route и отсутствие внешней desktop
шапки: desktop sidebar, mobile topbar. Он подтвердил также, что CSS .editorial-note
ещё отсутствует в самой canonical оболочке. Сохранённый в lk-preview.css единый
визуал плашки остаётся локальной договорённостью, не объявляется production-каноном.
Действующий локальный ARTICLE_STANDARD в другой Git-ветке отличается от main;
правила не сводились и не откатывались. Editorial worktree снова чистый.

Test review нового этапа выявил неприкрытый контракт virtual manifest. Исправлен
только тест: HTTP GET course.json проверяет один доступный article первым в дне 1,
блокировку/отсутствие assets всех настоящих шагов и загрузку связанного demo JSON.
Три теста прошли. Повторное test review — clean; повторный запуск code review
второй волны блокируется лимитом agent threads. Runtime и UI после их clean
проверок не менялись; не выдавать это ограничение за новый полный review set.
