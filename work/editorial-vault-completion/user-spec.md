## What We Are Building
Довести постоянную папку Obsidian/Codex до публикации выбранных материалов с локальными картинками. Подключить действующие рецептурные исключения и заменить оставшиеся HTML-оригиналы редактируемым Markdown с сохранением содержания и вставок. Создать адресный API/CLI добавления, перестановки и переноса обычных статей существующих курсов.

## Why
Сейчас публикатор отправляет только текст, а часть файлов с расширением .md содержит HTML. Сергей должен редактировать тот же файл без Codex для обычных правок, а структурные поручения Codex должен выполнять быстро по готовому протоколу, сохраняя прогресс участников.

## Expected Behavior
Сергей меняет материал в D:/Codex/work/edabalans-materials и вставляет PNG/JPG/WebP обычной Markdown-ссылкой или ![[путь]]. Существующее окно показывает изменения текста и байтов вложений. По кнопке публикуются только выбранные материалы и их изменённые вложения. Локальные ссылки остаются рабочими; серверный оригинал содержит адреса принятых картинок.

Codex редактирует тот же постоянный файл. Для структуры использует preview/apply ограниченной операции с точными IDs и expected_version. Добавление статьи включает её тело в той же транзакции; перестановка не пересылает тела. Названия меняются через прежний файл названий.

## Acceptance Criteria
- [ ] Новый локальный файл и замена байтов файла под прежним именем обнаруживаются и отображаются на сайте после публикации выбранного материала.
- [ ] Относительные пути, пробелы и Obsidian-вставки поддерживаются; кодовые примеры не преобразуются. Неоднозначный basename и выход за корень отклоняются до записи материала.
- [ ] Конфликт основы проверяется до загрузки. Изменение текста/байтов во время загрузки отменяет публикацию исходника. Повтор того же scoped digest не создаёт дубликат; потеря ответа разрешается по readback версии/hash.
- [ ] Локальные Obsidian-ссылки сохраняются после публикации/refresh. Одновременный черновик другого материала не меняется.
- [ ] Блог сохраняет manifest-владение CTA/названиями/правами и допускает проверенные загруженные картинки в публичном тексте. Черновик не открывает картинку миру.
- [ ] Картинки курсов выдаются по фактическому доступу к конкретному материалу, включая исключения прямых ссылок ACCESS_RECIPES до открытия дня15. Публикация Git-черновика интенсива не открывает изображение до runtime release.
- [ ] Главная позволяет менять существующие фото через фиксированные asset slots в том же MD; размеры, CSS, порядок блоков сохраняются. Произвольная перестройка главной не добавляется.
- [ ] Два обзора рецептов ошибочно заблокированные substring проверкой становятся обычными редактируемыми материалами. Восемь архивов сохраняются для чтения; пять актуальных рецептов подключаются только по доказанному полному original hash и HTML equality, без подмены calculator metadata.
- [ ] В подключённом рецепте можно добавить/заменить обычную фотографию тем же публикатором. Recipe PUT принимает проверенные scoped вложения этого recipe ID; защищёнными остаются calculator comments/cards, recipe_card и другие исполняемые вставки, title и материальные ссылки. Фото и полный source сохраняются одной редакцией с обновлением source_hash/version namespace при неизменных точных calculator cards.
- [ ] Действующие HTML-материалы преобразованы в Markdown с тем же текстом, ссылками, изображениями, таблицами, рецептами, DQS, spoiler, audio/video и другими специальными вставками. Пустой HTML не заполняется придуманным текстом. Принятые предыдущие версии сохраняются.
- [ ] Structure API/CLI поддерживает add_article, reorder внутри существующего unit и move обычной статьи/целой parent-children группы между существующими units. Обязательность новым/ранее открывшим участникам задаётся явно; специальные runtime шаги не перемещаются между units этой операцией.
- [ ] Структура, тело добавленной статьи, координаты прогресса и completion events изменяются атомарно. Completed_at, стабильный ID и обязанности уже открытого этапа сохраняются по явному договору операции. Старый completion/reveal с прежним ID/индексом/версией возвращает 409 без записи.
- [ ] Клиент установлен, сохранены локальные правки, инструкции и пример в постоянной папке и C:/Как пользоваться.md обновлены; CI и runtime проверены.

## Constraints
Единственная редакционная рабочая папка — D:/Codex/work/edabalans-materials. Worktree используется только для кода. Текст Сергея не переписывать. Сохранить уникальный визуал интенсива и главной. Не создавать новые кабинеты, права, Telegram engine, SaaS/расход или второй контентный сервер. Курс тренировок не трогать по прямому ответу владельца; полный охват логики бота и уведомлений отложен.

Reuse существующих API, FastAPI/Pydantic, SQLAlchemy, Pillow и ManagedDocumentVersion; DDL не требуется. Ограничения raster: до1MiB/файл, до4MiB/материал, до6000px/25MP, PNG/JPEG/WebP. Бинарные записи scoped и immutable; без нового host/volume. Проверки доступа выполняются на каждом чтении, опубликованность определяется действующим оригиналом. Не менять Tilda/payment hooks/реальные цены и не тестировать перестановки на живых участниках. Production structural apply использует штатный backup/restore договор.

## Risks
- **Private image leak:** наследовать фактическую авторизацию материала и проверять опубликованную ссылку; не использовать публичный старый course-assets для новых закрытых вложений.
- **Потеря оригинала/вставок:** адресная конверсия с сохранённой основой и сравнением текста и всех компонентов, а не автоматическая перепись.
- **Progress race:** стабильный course shared/exclusive transaction guard до User lock, атомарный stable-ID remap и проверка revision/ID клиента.
- **Расхождение локальных ссылок и сервера:** нормализованный wire source для hash, сохранение локальной ссылки и снимка байтов; conditional replacement того же файла.

## Accepted Decisions
- Пользователь поручил реализацию пунктов2–5; повторная просьба разрешить тот же объём не требуется. Ответ о training: «пока этот курс не трогай».
- Обычные правки и фото — прежняя кнопка; структура — Codex и API/CLI, отдельный структурный GUI не нужен.
- Сервер хранит принятые оригиналы, Obsidian/Codex редактируют одну внешнюю рабочую копию.
- Archive не становится текущим рецептом; calculator original не реконструируется по PNG/HTML.
- Обязанности существующих участников задаются явным параметром каждой будущей операции, не выбираются инструментом. Завершённый день не становится незавершённым автоматически.

## Testing

**Unit tests:** преобразование HTML/компонентов сравнивается с прежним render на уровне функции, поскольку риск — потеря текста/узла при детерминированной конверсии; для этого не нужны браузер/production.

**Integration tests:** настоящий временный filesystem + публикатор проверяют пути, кодовые примеры, замену байтов, локальные ссылки, selective publication, lost response и одновременную правку: эти риски зависят от сохранения файлов и API взаимодействий. TestClient + изолированная БД проверяют raster store, draft/public/private выдачу, recipe image+calculator сохранение и transaction/remap/events/rollback/stale body: нужны реальные версии и commits. Изолированный PostgreSQL concurrent proof проверяет shared/exclusive lock и два structural writers: SQLite не доказывает PostgreSQL блокировки.

**E2E tests:** общий курсовой HTML в браузере отправляет актуальные structure_version/step_id и после 409 обновляет manifest вместо слепого повтора прежнего индекса. Это браузерная граница, поскольку MK/calories/recipes используют общий HTML и строковые адаптеры. После deploy один runtime smoke проверяет реальное отображение принятой картинки и установку настольного клиента; не повторяет локальные validation сценарии и не переставляет живые курсы.
