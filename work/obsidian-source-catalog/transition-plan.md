# Подготовка единой структуры: по контурам

Дата: 16.09.2026. Статус: draft. Это уточнение поручения владельца после исходного
user-spec.md: целевое решение — понятные реальные источники, не постоянная витрина
из копий. Серверная БД полностью исключена. Миграции ещё не разрешены этой подготовкой.
При расхождении с прежним ТЗ эта новая граница имеет приоритет для текущего этапа.

## 1. Быстрый доступ к текстам — без ожидания миграции

Подготовлена catalog/Главная.md. Для МК открыть настоящий editorial-пакет и
program.md: это уже оглавление с прямыми ссылками, без копирования статей.
Для интенсива дать найденные файлы страниц и сообщений с явными версиями.
Исторические и непринятые сборки не объединять. При неизвестной актуальности
отметить спор, а не назначать канон.

Новые входы не изменяют исходники. Открытие каталогов как vault — отдельное
действие пользователя; настройки работающего Obsidian не переписывать.
Требуется честная проверка: путь существует, ссылка ведёт к нему, файл входит
в vault. UI-доступ без проверки не считать настроенным.

## 2. Навыки — начать с происхождения, а не перемещения

Сейчас 19 пользовательских пакетов установлены в C:/Users/Segey/.codex/skills.
Создано 00 — Навыки.md с реальными ссылками на файлы пакетов.
Это пригодный временный просмотр, но не доказательство исходного происхождения.

Писатель source: content/author-voice/skill/edabalans-writer/ в edabalans.
Библиотекарь source: content/knowledge/skill/edabalans-librarian/ в edabalans.
Они присутствуют в origin/main репозитория github.com/armagedongt/edabalans.ru.
Runtime устанавливается из этих источников managed copy. Другие локальные
изменения не становятся GitHub-backup без commit/push.

У писателя installed совпадает с проверенным origin/main (273 строки), но
исходник старого dirty root отличается. Нельзя запускать установку из root,
пока не установлена правильная версия исходника.

Для каждого пакета подготовить source ownership table:

- canonical source и доказательство происхождения;
- фактическая installed location и загрузка текущим Codex;
- пользовательский/проектный source отдельно от глобального scope установки;
- authored/generated/vendor, manifest и установщик;
- связанные references/scripts/assets и внешние жёстко заданные пути;
- Git tracking/проверенный remote snapshot и неизвестная резервная копия;
- кто сейчас меняет пакет и можно ли безопасно переносить.

Часть пакетов имеет Generated by sync-to-codex / Do not edit directly: найти
генератор/источник, не объявлять runtime исходником. Не создавать второй master.

Целевая структура: одно стабильное место редактирования собственных source
packages, одна согласованная схема размещения и backups. Runtime копии, если
нужны загрузчику, только устанавливаемые артефакты без самостоятельной редактуры.
Физический путь и способ подключения выбрать по подтверждённым ограничениям
loader и existing source dependencies; не перемещать всё одной командой.

Правило в AGENTS само по себе не перенастраивает автоматическую загрузку skills.
Сначала проверить реальную загрузку/обновление на одном безопасном пакете,
затем предложить миграцию остальных. Не менять instructions во время переноса.

## 3. Модули сайта — готовый существующий реестр

Использовать docs/modules.toml и существующие карточки, не заводить новую
классификацию модулей. Подготовлен вход к 53 module_id origin/main с прямыми
ссылками на физические карточки root; различие веток явно обозначено.
Для целевого vault оставить эти настоящие docs, при необходимости улучшить
только группировку навигации. Новые owners и размещение согласовать до изменения
registry; в первой фазе ничего не править в правилах сайта.

## 4. Последующие тексты

После МК и интенсива адресно подключать existing calories/training version maps,
готовые тексты и черновики. Полные MD уже существующих материалов не переписывать.
Подключение welcome/postpurchase только по файловым источникам и existing exports.
Без запросов серверной БД; если full text только там, показать этот пробел,
не включать серверный экспорт скрытно и не создавать вымышленный текст.

## Запреты и контроль

Не менять/переносить/удалять оригиналы, не редактировать skills, не обновлять
installed packages, не переключать dirty checkout, не deploy/push.
Не сканировать личное здоровье, /srv/edabalans-private, auth/config/историю .codex.
Не делать junctions и не менять настройки Obsidian автоматически.
Проверять относительные ссылки, существование файлов и неизменность входов.
Размещение новой навигации пока work; это не долговременный канон фактов.

## Условие готовности подготовки

Быстрые входы созданы; проверены файлы/ссылки; непроверенный UI обозначен.
Показаны текущие source/install различия и безопасный порядок миграции.
Исходники не изменены. Реальная консолидация путей, единый vault и правила
создания новых packages — следующий согласованный этап, не объявлять завершённым.
