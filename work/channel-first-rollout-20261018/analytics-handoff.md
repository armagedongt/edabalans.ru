# Передача VSL и Я.Директ: канальные входы

Модули: messaging.telegram.attribution, marketing.analytics, products.intensive.
Решение Сергея: после выпуска входа владельцы аналитики проверяют разметку
переписанной статьи и завершают статистику. Новую рассылку не делать.

## Готовая зависимость

Сайт один: https://похудение-это-есть.рф. Нынешняя статья — `/intensive`, источник
`content/masterclass/editorial/weight-loss-roadmap.md`, адаптер `intensive_onepage.py`.
Архивные четыре дня не считать текущей статьёй. `/podgotovka` и
`/preview/direct-intensive` — рекламная посадочная, не сама статья.

Конструктор: `/admin/channel-links`, API `/admin/api/channel-links`, отчёт
`/admin/api/channel-links/report?from=YYYY-MM-DD&to=YYYY-MM-DD` с `platform`/`link_id`.
Старый `/bot#links` сохранён. За стабильным кодом хранятся площадка, размещение,
пост и запрос разрешения. Пример: `https://t.me/Fitness_Talks_bot/channel?startapp=yt`.
Переключатель отключает запрос разрешения, переход остаётся автоматическим.

Telegram посадочной использует alias `ya`, прежний POST `/api/messaging/start-link`
и U-сессии отдельно для кнопки и QR: yclid/UTM, browser_context, entry/device и
ранее разрешённые tag_id сохраняются. Перед проверкой рекламы открыть список
конструктора для создания профильных кодов. MAX сохраняет BMB6Y и bot-start:
канальный Mini App MAX пока не зарегистрирован.

## Собираемые факты

- `channel_entry_open`: проверенный initData, Telegram ID, снимок link/source/placement,
  конфигурации и visit, известность контакта, подписанное allows_write_to_pm.
- `channel_permission_requested/result/unavailable`, `channel_open_requested`:
  клиентские наблюдения. true не обязательно новое разрешение, false не доказывает
  явный отказ, отсутствие callback — неизвестность. Запрос открытия не равен подписке.
- `channel_write_allowed`: серверный webhook, server_granted=true,
  automatic_message_sent=false; согласие само не запускает приветствие.
- `channel_membership`: webhook собственного канала, subscribed/joined, без invite
  также сохраняется. Join request не считается вступлением.
- Поздний Start восстанавливает последний наблюдаемый Mini App источник через
  first-touch, не заменяя прежний источник клиента. Доставка статьи —
  temporary_intensive_entry с delivery_status=sent.
- У известного user_id есть intensive_onepage_* в course_events и связанный
  browser_page; новый отчёт использует их без второй копии данных.

Канон: `docs/knowledge-base/modules/telegram/LINKS_AND_ATTRIBUTION.md`, раздел
«Канальные ссылки и наблюдения —19.10.2026». Код: backend/app/channel_entry_*.py,
telegram-bot/service/app/channel_entry.py. Тесты: backend/tests/test_channel_entry.py.

## Что закончить владельцам аналитики

1. Проверить текущие заголовки, редакцию и кнопки статьи, onepage-tracking.js:
   открытие, реальный процент, активное время и действия. Декоративный прогресс
   не превращать в аналитический процент.
2. Проверить появление событий на новом домене у известного читателя и отчёты.
   Анонимного посетителя не угадывать по email или площадке.
3. Подключить персональную глубину чтения главной к существующему browser journey
   и user_id. Сейчас public_homepage_events анонимны, отчёт показывает «не подключено».
   Проверить также путь с разрешением писать без /start: рекламный browser_context
   сохранён в Mini App событии, поэтому появление лида не должно требовать Start.
4. Свести путь: посадочная → Mini App → разрешение/членство → Start → доставка →
   чтение статьи → главная. Текущий отчёт ограничивает действия следующим входом
   либо концом периода; это хронология, не причинная модель продаж.
5. Проверить yclid/clientID и действующий offline upload Метрики; предложить Сергею
   конкретные цели для новых этапов. Кампании, расходы и объявления не менять попутно.

Готовность: видны фактические события и время, неизвестность отделена от отказа,
повторный вход не удваивает конверсии, MAX не выдаётся за Telegram, есть разрезы
дат, ссылок и площадок.

## Границы

Покупателей исключает общий блок; >75% вместе с подпиской скрывает его,
>75% без подписки показывает только подписку. Приоритет from=tg|max сохранён.
Тексты и URL централизованы в public-site-content/reader-subscription.
Счётчик подписчиков отменён. Закрепы каналов Сергей меняет вручную позже;
это не блокирует техническую работу. Новая 14-дневная рассылка и тарифы отложены.
