# Исследование: карта страниц, аналитика и cookie

Дата: 2026-09-10

## Проверенный текущий контур

- Общая плашка и её годовое подтверждение принадлежат
  `backend/app/static/site-cookie-notice.js`.
- Серверная главная находится в
  `backend/app/static/homepage-preview/mobile.html`, подключается также через
  `backend/app/static/homepage.js` и технический Tilda shell.
- Видеоплеер главной хранит анонимный `viewer_id` в localStorage и отправляет
  события просмотра в `/api/public/video-analytics`.
- Бесплатный интенсив находится в `backend/app/static/intensive/`. Его
  `runtime.js` независимо выполняет две задачи:
  - сохраняет функциональный персональный прогресс через `/api/intensive/*`;
  - сразу загружает Яндекс Метрику `97331502` и отправляет цели.
- Блог обслуживается `blog_routes.py` и шаблонами `static/blog/index.html` и
  `article.html`. Собственного счётчика Метрики в текущем серверном коде нет.
- ЛК и приложения (`/lk`, `/training`, `/dqs`, `/metabolism`, `/recipes`) читают
  и записывают данные аккаунта и приложения. Рекламные счётчики им не нужны.
- Юридические и платёжные страницы не подключают общий cookie-компонент и не
  должны запускать маркетинговые счётчики.

## Важная граница

Функциональные данные и маркетинговая аналитика — разные контуры. Вход, покупки,
доступы, учебный прогресс, состояние приложений и события, без которых работает
сам продукт, не должны блокироваться cookie-плашкой. Яндекс Метрика и рекламные
пиксели должны подчиняться сохранённому выбору пользователя.

Cookie может быть общей для одного корневого домена и его поддоменов, но не для
двух независимых корневых доменов. `edabalans.ru` и
`похудение-это-есть.рф` не могут напрямую читать cookie друг друга. Поэтому во
временном двухдоменном контуре отсутствие плашки на интенсиве означает: у прямого
посетителя из бота работает внутренний прогресс, но Метрика не запускается, пока
на `edabalans.ru` нет ранее сохранённого согласия.

## Пользовательские страницы

В карту включаются страницы, на которые может попасть посетитель или клиент.
Статические ассеты, JSON API, health/readiness, sitemap/robots и административные
экраны не являются отдельными пользовательскими страницами.

| Группа | Маршруты |
| --- | --- |
| Серверная главная | `/preview/homepage-mobile`; после переноса — `/` |
| Блог | `/blog`, `/blog/articles/{slug}` |
| Бесплатный интенсив | `/intensive`, `/intensive/day-1` — `/intensive/day-4`; legacy `/intensive/start` |
| Личный кабинет | `/lk` |
| Приложения | `/training` (`/strength`), `/dqs`, `/metabolism`, `/recipes` (`/recipe-calculator`), `/max-app` |
| Вход из Telegram | `/telegram-login` |
| Юридические документы | `/legal`, `/legal/{privacy|offer|consent|disclaimer|messages}` |
| Платёжные результаты | `/payments/robokassa/success`, `/payments/robokassa/fail` |
| Технические платёжные проверки | `/robokassa-test`, `/robokassa-live-probe` и их result pages — только по флагу |
| Персональные переходы | `/m/{token}`, `/p/{post_number}/{token}` — записывают разрешённое внутреннее событие и перенаправляют |
| Рекламный preview | `/preview/direct-intensive` и сохранённая A1-версия — `noindex`, не общий публичный shell |

## Архитектурный вывод

Не нужно вручную встраивать реализацию аналитики в каждую страницу. Нужны единый
`site-analytics.js`, единый реестр типов страниц и одно событие принятия из
`site-cookie-notice.js`. Страница только объявляет свой тип либо получает его от
общей оболочки; правила запуска определяет центральный модуль.
