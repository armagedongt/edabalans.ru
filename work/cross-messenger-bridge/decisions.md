# Решения: единый разговор Telegram и MAX

## Каналы публикуют, чаты разговаривают

**Что решили:** Telegram-канал остаётся источником постов, MAX-канал получает
копию. Обсуждение ведут отдельные обычные чаты практики, связанные друг с другом.
**Почему:** MAX принимает медиа от людей в обычных чатах, в отличие от комментариев
к постам канала.

## Пара состоит из четырёх точек

**Что решили:** одна настройка хранит Telegram-канал, MAX-канал, Telegram-чат
практики и MAX-чат практики.
**Почему:** это даёт одну независимую единицу для основного канала и каждого
спринта; новую пару не надо программировать отдельно.

## Telegram-бот не создаём

**Что решили:** пересылку из Telegram выполняет `@TetrisgfgfgfBot`.
**Почему:** это уже подключенный технический бот; новый видимый бот в Telegram
не даёт продуктовой пользы.

## Отдельный MAX-бот

**Что решили:** MAX-пересылку выполняет созданный бот `Ответ из чата`.
**Почему:** существующий MAX-бот ведёт пользовательские сценарии и не должен
перемешиваться с технической пересылкой.

## Что не автоматизируется в первом выпуске

**Что решили:** бот не сочиняет ежедневные темы и не закрепляет их сам. Сергей
пишет короткую навигацию в Telegram-чате практики; она зеркально приходит в MAX.
**Почему:** это оставляет живую редакторскую механику у Сергея, не добавляя второй
сценарий публикации и лишние правила закрепления.

## Ограничения API, которые нельзя выдумать кодом

**Что решили:** не обещать симметричное удаление после удаления сообщения в
Telegram и не считать нативный MAX voice готовым до живой проверки.
**Почему:** Telegram Bot API не присылает события удаления чужих сообщений, а
MAX в своём актуальном API иногда присылает voice update без message, chat_id и
файла. Это ограничения входящих событий платформ, а не маршрутизации сервера.
