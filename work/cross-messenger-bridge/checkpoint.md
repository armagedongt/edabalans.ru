## Проверенная защита и надёжность

- MAX-канал никогда не становится источником сообщения Telegram-чата: обратное
  направление принимается только из MAX-чата практики.
- MAX/Telegram сообщения от ботов внутри чатов практики не запускают обратную
  пересылку, даже если webhook придёт раньше ответа API.
- Неудачная отправка сохранена отдельно; повтор того же Telegram update или MAX
  webhook повторит её максимум три раза, не создавая новую карту сообщения.
- Telegram webhook без настроенного секрета никогда не активирует пересылку для
  пары, поэтому поддельный public request не может опубликовать текст в MAX.

## Уточнение по внешним API

- Telegram Bot API отправляет `edited_message` и `edited_channel_post`, но не
  даёт update об удалении чужого сообщения или поста. Поэтому зеркальную копию
  после удаления в Telegram нельзя автоматически удалить честным Bot API путём.
- MAX schema документирует `message_created.message`, включая audio attachment,
  но в актуальном публичном issue SDK зафиксирован native voice update без
  `message`, `chat_id` и media URL. Нужен живой прогон после модерации; обхода
  без входящего идентификатора у сервера нет.
