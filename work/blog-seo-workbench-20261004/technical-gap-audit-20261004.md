# Технический этап: проверенные пробелы перед изменениями

Основа: локальные backend-файлы на HEAD 91405c5 и origin/main 205b5d11. Между ними нет diff по blog_content.py, blog_routes.py, blog_draft_service.py и assets/blog.js. Это аудит прочитанного кода, не доказательство состояния каждого production endpoint и не реализованный этап 5.

## Что уже есть и не требует второго механизма

- Description в начале Markdown; fallback первых двух предложений, опубликованная версия имеет приоритет над Git-основой. Одно описание используется в поисковых metadata и карточках; редактор/версионное хранилище уже существуют.
- Публичный renderer, canonical статьи, Article/Person, sitemap и robots, три конечных related, local media. Это не доказательство полноты SEO.
- В интерфейсе каталог разбит по 15. Сервер пока отправляет все карточки, JavaScript скрывает лишние и создаёт кнопки. Настоящих серверных страниц с прямыми ссылками пока нет.

## Подтверждённые изменения этапа 5

1. Строгий parser поддерживает только description. Расширить существующий контракт seo_title без смены H1/slug/body, не вводя произвольный YAML; старый формат оставить совместимым. В существующем editor/preview/API/public одна логика и штатная история версий.
2. Article использует только имя Person, нет стабильной ссылки на авторский профиль; дата публикации/изменения не передаётся в этой схеме. Добавить авторство/даты только с проверенной provenance и согласованным текстом; не вычислять исходную дату по догадке и не проставлять всем фиктивное обновление.
3. Серверная пагинация и рубричные ссылки по существующим адресам/параметрам, 15 карточек, прямые ссылки, корректный canonical. Не создавать новый блог и не менять адреса статей.
4. Sitemap сейчас содержит адреса без lastmod. Добавлять lastmod только при достоверном событии изменения публичного материала. Изменение черновика не событие public.

## Перед кодом

Полностью прочитать изменяемые файлы и связанные тесты/шаблоны, установить baseline. Изменения parser, renderer и API проверяются профильными тестами и свежим code/security review; новые тесты — по test-master. Ревью редакционных вариантов не заменяет техническое.

В следующую единицу работы брать поддержку seo_title как один законченный срез. Авторство, даты и пагинация — отдельные последующие срезы. Код сейчас не изменён. Независимая подготовка разрешена; выбранные SEO-поля в production не переносить до решения владельца. Поисковые кабинеты остаются последним этапом.
