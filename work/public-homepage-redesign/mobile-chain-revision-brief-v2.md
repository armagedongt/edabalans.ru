# Цельная mobile-preview: темы страницы, цены и внешний VSL

Дата: 31.08.2026
Статус: `implemented` — выбраны `boost = 7`, серверное хранение и четыре фоновые схемы
Модуль: `products`

## Граница задачи

- Меняется только тестовая страница `/preview/homepage-mobile` и вложенный внешний VSL.
- Действующая главная Tilda, checkout, продуктовые данные и production-T123 не переключаются.
- Согласованные внутренние блоки не редизайнятся: меняются только общий фон и переходы между ними.

## Почему финальный блок сейчас находится в синем контейнере

У принятого финального CTA уже есть собственная синяя карточка `.final-card`. При сборке
цепочки внешний контейнер `.chain-block--final` дополнительно окрасили в `#087aca`, чтобы
визуально соединить CTA с таким же синим подвалом. Это решение сборки, а не обязательная
часть принятого блока. В новых вариантах внешний контейнер наследует общий фон страницы;
синей остаётся сама карточка, а подвал рассматривается отдельно.

## Белая основа и три форка общего фона

Содержание, порядок блоков и интерактив во всех вариантах одинаковы. Меняется только
общая подложка страницы и её связь с блоками. Собственная голубая подложка тарифного
блока удаляется.

### Основа `white`

- Общий фон страницы белый.
- Принятые белые блоки остаются белыми.
- Тарифы стоят непосредственно на общей белой подложке без собственного цветного
  прямоугольника и без отдельного переходного градиента.
- Внешний контейнер финального CTA белый; синяя только карточка.

### Форк 1. `blue-mist`

- Очень светлая холодно-голубая база.
- Под смысловыми акцентами появляются большие размытые голубые пятна разной плотности;
  между ними сохраняются почти белые участки.
- Пятна относятся к общей подложке и не выглядят отдельными карточками или секциями.
- К концу страницы фон становится немного насыщеннее и соединяется с синим подвалом.

### Форк 2. `blue-rhythm`

- Подложка меняет светлоту по ритму блоков: белое поле → лёгкая голубая дымка → более
  заметное голубое поле → снова почти белое.
- Отдельные принятые блоки подсвечиваются размытым ореолом, но сами блоки и их карточки
  не перекрашиваются.
- Насыщенность нарастает только в нижней трети страницы; тёмных зон нет.

### Форк 3. `blue-crescendo`

- Первый экран почти белый.
- С каждым крупным смысловым этапом общий фон постепенно получает больше голубого;
  переходы длинные, без границы секции.
- У тарифов фон уже явно голубой, но не принадлежит самим тарифам.
- FAQ и финальный CTA стоят на насыщенной синей общей подложке, которая без шва
  продолжается в подвал. Белыми остаются только внутренние читаемые поверхности.

На test-preview основа и три форка доступны на одном URL через служебный переключатель темы.
Переключатель является только инструментом сравнения и не попадает в production.

### Верх тарифов

- Заголовок, плашка и строка `Выберите формат участия` выносятся из узкой внутренней
  карточки/оболочки тарифов.
- Они располагаются на общей подложке страницы и используют ширину общего контентного
  контейнера.
- Внутренняя оболочка начинается непосредственно с тарифных карточек и подробностей.

## Цены и тарифы

- Источник названий, доступности и сумм — опубликованный серверный каталог
  `/api/pricing/site` с кодами:
  - `site.masterclass.basic`;
  - `site.masterclass.recipes`;
  - `site.masterclass.consult`.
- Тестовая публичная страница не показывает локальный черновой snapshot и не хранит
  собственные актуальные суммы.
- Текущая цена, зачёркнутая цена и процент скидки отрисовываются из ответа каталога;
  процент вычисляется из `compare_at_amount` и `sale_amount`.
- На время загрузки показывается нейтральный skeleton. Если каталог выключен или
  недоступен, устаревшие числа не подставляются: тарифы заменяются сообщением о временной
  недоступности цен.
- Эта задача не включает server checkout: CTA тестовой главной сохраняет действующий
  контракт покупки через Tilda.

## Внешний VSL: состояния и управление

### 1. `autoplay-muted`

- После загрузки видео автоматически воспроизводится без звука.
- Пока пользователь не включил звук вручную, ролик автоматически повторяется по
  кругу; это одинаково для основного VSL и видеоотзыва Ани.
- Поверх него видна только исходная плашка-призыв включить звук.
- Беззвучный автоплей не считается началом осознанного просмотра и не записывается в
  статистику просмотра.

### 2. `first-engagement`

- Только первый клик по плашке:
  1. навсегда убирает плашку-призыв для этой загрузки страницы;
  2. возвращает видео на `0:00`;
  3. отключает зацикливание, включает звук и запускает воспроизведение;
  4. создаёт событие `video_engaged` и начинает учёт просмотренных интервалов с нуля.
- Клик по фону видео или нижним контролам до первого engagement не должен запускать
  альтернативный сценарий без сброса на начало.

### 3. `playing`

- После начала осознанного просмотра интерфейс автоматически исчезает.
- Через 1 секунду после начала воспроизведения интерфейс скрывается.
- На desktop он временно возвращается по движению указателя или фокусу; на mobile — по
  одному касанию. Через 1 секунду бездействия снова скрывается.
- Визуальная шкала прогресса остаётся индикатором и не является ползунком перемотки.

### 4. `paused`

- На стоп-кадре показывается одна стандартная центральная кнопка Play.
- Призыв включить звук больше не появляется.
- Нажатие продолжает с текущего места и не создаёт повторное событие engagement.

### 5. Содержание и перемотка

- Произвольная перемотка по шкале, жестом и клавишами отключена.
- Кнопка `Содержание`, список глав и переходы по главам полностью удаляются именно из
  продажного плеера на главной.
- В текущей версии главной пользователь не может перематывать видео никаким способом.
- Конфигурация глав может оставаться внутренним неактивным источником для будущих версий,
  но не выводится и не влияет на управление.

## Статистика просмотра

- Используется существующий модуль режима `engagement` из оригинального внешнего плеера.
- После первого осознанного запуска он считает просмотренные интервалы по 5 секунд,
  максимальную позицию и события `video_engaged`, `video_progress`, `video_complete`,
  `video_exit`.
- Текущее состояние сеанса сохраняется в `localStorage`, публикуется браузерным событием
  `mvp:analytics` и отправляется в `/api/public/video-analytics`.
- Сервер хранит одну агрегированную строку на одну загрузку страницы: позиции,
  объединённые пятисекундные интервалы, состояние и число событий.
- Постоянный случайный `viewer_id` хешируется до записи; IP, email, телефон, user_id и
  другие персональные данные endpoint не принимает.

## Ускоренная визуальная шкала

Шкала не меняет скорость видео. Вместо ломаной интерполяции между контрольными точками
используется одна плавная гиперболическая кривая:

`shown = real × (1 + boost) / (1 + boost × real)`

`boost` — единственная изменяемая переменная. Чем она больше, тем быстрее шкала уходит
вперёд в начале и тем плавнее замедляется дальше. Кривая непрерывна, не имеет щелчков и
всегда приходит ровно в `100% → 100%`.

Выбрано `boost = 7`: при 5% реального просмотра шкала показывает примерно 30%.

В test-preview служебная панель шкалы не нужна. После выбора `boost` значение хранится в
одной именованной настройке исходника плеера; production-интерфейс её не показывает.

## Проверка перед показом

- Белая основа и три фоновых форка сравниваются на одном mobile viewport и на desktop без
  изменения контента.
- На реальном телефоне нет резких бело-голубых швов и синего внешнего контейнера у
  финального CTA.
- Тарифы подтверждают `data-pricing-source="database"`; числа совпадают с публичным
  каталогом на момент открытия.
- Первый engagement VSL один раз сбрасывает ролик на начало и только тогда запускает
  статистику.
- После pause видна стандартная Play, после resume интерфейс снова скрывается.
- Кнопки и списка `Содержание` нет; перемотка полностью недоступна.
