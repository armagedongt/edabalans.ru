# Точка входа в визуальные референсы

Статус: `draft`; использовать после принятия смысловой карты

## Что уже не должны менять референсы

- Мастер-класс остаётся главным первым шагом.
- Рецепты — первый дополнительный продукт.
- Калории и тренировки — короткие усилители с отдельными страницами; тренировки
  пока `planned`.
- Консультация — заметный человеческий маршрут.
- Главный CTA — выбор тарифа МК; вторичный — бесплатный интенсив.
- Отзывы первой версии остаются изображениями.
- Структура mobile-first предшествует desktop-композиции.
- Цены, checkout, login и footer не принадлежат визуальному макету.

## Какие референсы полезны

Референс можно прислать целым сайтом, скриншотом или отдельным блоком. Для каждого
достаточно одной короткой пометки: что именно нравится.

| Задача | Что ищем в референсе |
|---|---|
| Первый экран | масштаб заголовка, баланс текста/медиа, характер CTA |
| Длинная аргументация | ритм, смена плотности, способ не превращать текст в карточки |
| Четыре области навыков | понятная система/последовательность без инфографического шума |
| Программа МК | раскрытие четырёх этапов и полной программы |
| Экосистема продуктов | иерархия главного продукта и вторичных направлений |
| Консультация | ощущение личного контакта, фото/голос/формат разговора |
| Тарифы | сравнимость состава, выделение рекомендуемого варианта, mobile stack |
| Отзывы-картинки | удобная галерея и увеличение без визуального мусора |
| Общий язык | типографика, палитра, радиусы, контраст, характер движения |

## Как я буду разбирать каждый референс

1. Фиксирую конкретный приём, а не оценку «красиво».
2. Привязываю его к одной функции нашей смысловой карты.
3. Проверяю mobile, доступность и совместимость с длинным русским текстом.
4. Отделяю переносимый принцип от чужого бренда, структуры и контента.
5. Помечаю: взять, адаптировать, проверить фрагментом или не использовать.

## Как будет приниматься направление

Сначала показываются не две полные страницы, а один цельный вертикальный фрагмент:

1. header + hero;
2. один аргументный блок;
3. одна карточка этапа МК;
4. карточка вторичного продукта;
5. фрагмент консультации;
6. одна тарифная карточка.

На этом фрагменте можно принять типографику, цвет, поверхности, плотность и
движение без дорогой пересборки всей страницы. После выбора система переносится
на полный wireframe.

## Что не требуется от Сергея

- собирать палитру и размеры;
- объяснять термины дизайна;
- искать референс для каждого блока;
- вручную выгружать текущие картинки/тексты;
- выбирать технический способ T123 или server loader.

Достаточно прислать всё, что нравится, и при возможности написать простыми
словами: «здесь нравится первый экран», «вот так хочу тарифы», «нравится общий
характер, но не цвета».
