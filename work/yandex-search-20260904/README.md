## Разграничение органического Telegram и web-UTM

Для органических переходов из Telegram-канала на бесплатный интенсив действуют
ровно два bot-start правила:

1. pin alias для окна публикаций №260–264: закреп №260 и четыре следующие
   публикации;
2. один общий alias для всех остальных органических постов после этого окна.

Номер поста в эти aliases не кодируется. Отдельный alias создаётся только для
рекламной площадки/кампании либо явно назначенного владельцем сценария. Неизвестный
start payload ведёт в базовый сценарий без атрибуции.

Прямые ссылки из Telegram-канала на Мастер-класс относятся к другому маршруту:
они ведут сразу на сайт и получают `utm_content=post_N`. Поэтому отчёты разделяют
две разные единицы наблюдения:

- organic bot-start aliases образуют когорту лидов от запуска бота и могут быть
  связаны с дальнейшими событиями интенсива;
- `post_N` относится только к web-визитам на Мастер-класс и анализируется в Метрике
  по UTM, а не как alias запуска бота.

Текущая таблица `/admin/marketing` создаёт пользовательские строки только от
зарегистрированных start-событий. Прямой `post_N` web-визит сам по себе не создаёт
`bot_start`, first-touch лида или пользовательскую строку, поэтому эти два маршрута
в отчёте не смешиваются. Связь такого web-визита с последующей оплатой потребует
отдельно реализованной browser-to-checkout идентификации.
