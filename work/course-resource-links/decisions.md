# Решения: course-resource-links

## Право, prerequisite и прогресс не объединяются

**Что решили:** хранить покупку в `user_accesses`, ручной режим в существующей
`user_course_policies`, а прогресс — в runtime каждого курса.
**Почему:** «куплено», «разрешено войти» и «дошёл до материала» — разные состояния.
**Отклонение от user-spec:** нет.

## Стабильная ссылка не содержит product code

**Что решили:** публичный ключ содержит только `course_code:step_id`; нужное право и
товар resolver выводит из канонической структуры.
**Почему:** иначе редактор может связать материал с неправильной продажей и создать
второй источник правил.
**Отклонение от user-spec:** нет.

## Тренировочный курс без выдуманного runtime

**Что решили:** реализовать общий prerequisite для `ACCESS_STRENGTH`, но не создавать
экран или структуру ещё не готового курса.
**Почему:** будущий курс отмечен planned; существующий силовой дневник — другой экран.
**Отклонение от user-spec:** только инфраструктурная часть до появления программы.
