# User-spec: универсальные ссылки и условия открытия курсов

## What We Are Building

Единая серверная перелинковка на материалы курсов по стабильному ключу
`<course_code>:<step_id>`. Она различает покупку, prerequisite курса, прогресс и
готовность материала; в CRM добавляется отдельное ручное полное открытие уже
выданного курса.

## Why

Обычная прямая ссылка не знает, куплен ли продукт и открыт ли нужный этап. Из-за
этого ссылка либо ведёт в закрытый экран, либо требует вручную подбирать разные
адреса покупки. Новая механика позволяет ставить одну ссылку сейчас и сохранять её
при будущих изменениях порядка материалов.

## Expected Behavior

1. Автор ставит ссылку `/lk?open=<course_code>:<step_id>`.
2. После входа сервер находит материал и проверяет публикацию, право, prerequisite,
   открытие этапа и предыдущие обязательные шаги.
3. Открытый материал показывается сразу; при отсутствии права показывается единый
   сфокусированный блок покупки; купленный закрытый материал показывает причину и
   продолжение курса.
4. После покупки исходная ссылка разрешается повторно.
5. Калорийный и тренировочный курсы в обычном режиме открываются только после
   завершения Мастер-класса.
6. Администратор может включить для конкретного действующего права «Открыть весь
   курс сразу», не создавая покупку и не раскрывая черновики.

## Acceptance Criteria

- [x] URL сам по себе никогда не выдаёт продуктовый доступ.
- [x] Мастер-класс и Калорийный курс зарегистрированы в общем resolver-е.
- [x] Отсутствующее право ведёт в существующий сфокусированный блок покупки.
- [x] Купленный, но закрытый prerequisite или прогресс не изображается новой продажей.
- [x] `fully_unlocked` обходит prerequisite и внутреннюю последовательность курса.
- [x] Скрытые, locked, ремонтные и неопубликованные материалы не раскрываются.
- [x] CRM меняет режим только при действующем праве и пишет административный аудит.
- [x] Правила задокументированы для следующих курсов.

## Constraints

- Использовать существующие `user_accesses`, `user_course_policies` и стабильные
  `step_id`; новая таблица или миграция не нужна.
- Покупка, политика прохождения и фактический прогресс остаются тремя разными фактами.
- Курс по тренировкам ещё не имеет runtime: сейчас фиксируется prerequisite и общий
  контракт, без выдуманного экрана курса.
- Существующее приложение силового дневника не блокируется prerequisite будущего
  тренировочного курса.

## Risks

- **Обход доступа через URL.** Resolver и API материала независимо проверяют право.
- **Ручная галочка случайно выдаст продукт.** API политики требует активный доступ.
- **Черновик откроется из старой ссылки.** Resolver отклоняет hidden/locked/unpublished.
- **Неверная ссылка после перестановки.** Связь хранится по стабильному `step_id`, а не номеру.

## Accepted Decisions

- Один ключ `course_code:step_id`; product code не дублируется в Markdown.
- `fully_unlocked` открывает прохождение, но не заменяет покупку.
- Для Калорийного и тренировочного курсов prerequisite — серверное событие
  завершения последнего дня Мастер-класса, а не жёстко записанный номер дня.
- Снятие галочки возвращает `paced`; сохранённая политика не действует во время
  паузы или после отзыва права.

## Testing

**Unit tests:** отдельный чистый алгоритм не выделяется; политика покрывается через
интеграционные сценарии.

**Integration tests:** resolver, prerequisite, CRM и полный unlock проверяются на
реальных моделях и routes.

**E2E tests:** новая визуальная система не создаётся; применяется существующий
браузерный контракт кабинета.

## Verification

### Agent Verification

| Step | Expected Result |
|------|-----------------|
| Открыть ссылку на доступный первый материал | Возвращается точный маршрут материала |
| Открыть ссылку на рецепт без права | Возвращается focused offer `recipes` |
| Купить зависимый курс до завершения Мастер-класса | Карточка остаётся купленной, но закрытой |
| Включить полное открытие в CRM | Все опубликованные этапы и материалы доступны |
| Указать неизвестный/скрытый target | Контент не раскрывается |
