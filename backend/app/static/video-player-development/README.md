# Видео: главный вход, плееры и места использования

**Любую задачу о видеоплеере начинать здесь.** Это единый вход и каталог
размещений, не новый движок или копия данных. HTML/JS остаются исполняемыми
источниками; соседние документы владеют правилами продукта и аналитики.
Временные `work/`, handoff и старые preview не заменяют этот вход.

Ссылки на технические источники ведут к принятому `main` на GitHub:
основная локальная папка может быть на старой ветке, не иметь этих файлов
или содержать незавершённые изменения. Каталог не переписывает её код.

Каталог сверен с принятым `main` `0519e658` 17.09.2026. На живом
`https://edabalans.ru` отдельно проверены HTTP 200 и признаки ожидаемой разметки
RC, публичного плеера, учебного плеера, оболочки МК и интенсива.
Это проверка доступности/встраивания, не проигрывания видео, активной структуры
из БД или совпадения всей server revision. Приватные медиа и внешние
Tilda-страницы в этом разборе не сканировались.

## Правила выбора и сборки версии

«Версия» здесь — существующий плеер + его настройки + оболочка размещения,
а не новый HTML с копией движка. Любой чат может работать с этим контуром:
сначала сверить актуальный `main`, карточку владельца и активный поток по
`docs/CHAT_WORKSTREAMS.md`. Задача «Видео чисто» хранит контекст работы,
но не является единственным способом доступа к плееру.

| Задача | Что использовать | Что не делать |
|---|---|---|
| Учебное видео дня МК | Существующий `/apps/video-player.html`, профиль `standard`; данные дня: MP4, обложка, главы | Не копировать HTML на каждый день, не менять движок ради ссылки ролика |
| Учебное видео отдельного материала, если владелец позже введёт такой формат | Тот же `standard` и тот же набор возможностей: MP4, обложка, главы. Сначала отдельно реализовать передачу данных материала | Не считать нынешний `materialMedia` готовым контрактом; в рамках текущего порядка новый формат не вводится |
| Стороннее видео-пример внутри статьи | Обычная ссылка либо уже согласованный компонент встраивания конкретного места | Не превращать пример в учебное видео дня, не подключать автоматически главы, обложку, автозапуск, прогресс курса или VSL-аналитику |
| Публичный VSL / отзыв Ани | `vsl-player.html` с существующим зарегистрированным `context` | Не брать автономную заготовку и не создавать отдельный движок для страницы |
| Первое видео интенсива | Уже работающий preset `intensive-day-1` с честной шкалой и перемоткой | Не распространять это исключение на все учебные видео без решения продукта |
| Boomstream-страница / ID | Уже предусмотренный iframe провайдера | Не обещать возможности нашего MP4-плеера внутри чужого iframe |

Для сторонних примеров назначение определяется содержанием и решением владельца,
не расширением файла. Если согласованного встраивания ещё нет, оставить ссылку
или согласовать отдельную интеграцию. Самовольный iframe в Markdown запрещён:
[ARTICLE_STANDARD.md](https://github.com/armagedongt/edabalans.ru/blob/main/docs/knowledge-base/ARTICLE_STANDARD.md)
и [article_markup.py](https://github.com/armagedongt/edabalans.ru/blob/main/backend/app/article_markup.py)
блокируют его. Новый маркер вставки, провайдер или обход sanitizer не являются
настройкой плеера.

Разделять три уровня изменений:

1. **Данные ролика:** ссылка, обложка, таймкоды дня — редактор/структура курса;
   публичные ролики — существующие presets. Не вписывать данные дня в HTML движка.
2. **Поведение:** воспроизведение, шкала, главы, события — один соответствующий
   исполняемый источник из каталога. Не переключать `PLAYER_MODE` в копии файла,
   чтобы получить новый продуктовый профиль.
3. **Размещение:** размер, маска и расположение — оболочка потребителя. Она не
   дублирует логику проигрывания или контракт аналитики.

Новое размещение сначала собирать из этих уровней. Новый публичный preset нужен
только для реально отличающихся данных/согласованных настроек; его ID должен
соответствовать серверному контракту аналитики. Если нужного поведения нет,
объяснить конкретную разницу и согласовать расширение существующего источника,
а не объявлять новый плеер или module_id. Скрытые controls качества/субтитров,
резервные режимы и floating-код не означают доступные пользователю функции.

При передаче результата сообщать: место, профиль, источник настроек, изменённые
файлы и проверки. Обновлять строку размещения и затронутый контракт; результат
проверять в реальной оболочке, а не только в автономном HTML.

## Как поддерживать каталог

При добавлении/удалении размещения или изменении профиля обновлять его строку
в том же изменении: адрес/блок, исполняемый файл, профиль, функции, источник
настроек, module owner и статус (используется / legacy / заготовка / выключен).
Обновлять затронутый продуктовый контракт и ссылку карточки, не создавать
отдельный README-клон плеера в каждом продукте или рабочем дереве.
Смена ссылки ролика в данных дня не требует ручного списка всех дней здесь.

Новый публичный `context` регистрировать явно: неизвестное значение сейчас
откатывается к главному VSL. В preset задаются MP4, стабильный `videoId`,
громкость и исключения профиля; iframe/размер — в оболочке.
Короткий файл должен быть точным началом длинного, переход сохраняет одну
логическую сессию. Смена битрейта того же содержимого не создаёт новый ID.
Публичная аналитика не равна прогрессу МК и не доказывает связь с оплатой/ЛК.
Точный событийный контракт принадлежит документу аналитики.

Границы координации локальных видео, включая включение звука у уже играющего
circle-video, принадлежат [PUBLIC_SITE.md](https://github.com/armagedongt/edabalans.ru/blob/main/docs/knowledge-base/PUBLIC_SITE.md).
Наличие координатора не означает проверки всех способов включения звука.

Большие видео, приватные расшифровки, клиентские выгрузки и секреты в Git
не помещать. Старые задумки читать в [VIDEO_PLAYER_DEFERRED.md](https://github.com/armagedongt/edabalans.ru/blob/main/docs/plans/VIDEO_PLAYER_DEFERRED.md),
не выполнять план автоматически и не считать всё перечисленное отсутствующим.

## Файлы

- `player-standard-with-contents.html` — действующий учебный плеер через runtime URL.

Каждая HTML-реализация содержит свои стили и JavaScript. Нижние инструкции

## Как применяется в Мастер-классе

Внутри Мастер-класса не нужно копировать этот HTML в Tilda. Единый runtime
открывает его по адресу `/apps/video-player.html` только для прямой ссылки на
MP4. В редакторе дня есть три настройки:

- **ссылка на видео** — короткий ID Boomstream, ссылка на страницу Boomstream или
  прямая HTTPS-ссылка на MP4;
- **ссылка на картинку / обложку** — показывается как обложка у прямого MP4, а
  при пустом видео становится самостоятельным медиа дня.
- **содержание / таймкоды** — одна строка на раздел в виде
  `00:00 — название раздела`.

Если заполнено видео, оно имеет приоритет. Пустые оба поля не показывают блок
медиа. Технический переключатель `media` редактор обновляет сам: вручную выбирать
тип медиа не нужно.

Boomstream ID или ссылка на страницу просмотра остаются в его iframe. Прямая
ссылка на файл, в том числе `cdnv.boomstream.com/...mp4`, открывается в этом
плеере. Не превращайте Google Drive-ссылку на просмотр в ссылку для плеера:
сначала загрузите финальный файл в Boomstream или объектное хранилище.

Для прямого MP4 содержание становится меню плеера с переходом по главам. Для
Boomstream те же таймкоды остаются честным раскрывающимся списком под видео:
перемотку внутри чужого iframe браузер безопасно не контролирует.

## Автономная заготовка: только исторический технический справочник

Этот маршрут относится к `player-autoplay-analytics-fast-progress.html`,
не к действующему публичному VSL. Учебный `standard` требует HTTPS `src`
в URL: простое копирование HTML с заменой атрибута видео не запускает его.

Не использовать заготовку как инструкцию копирования нового плеера в Tilda
или продукт: действующие размещения выбираются по таблице выше. Нижние
константы описывают только эту заготовку, не публичный preset и не данные дня.
Новый выпуск на её основе требует отдельно согласованного поведения и проверки
контрактов. Корневой ID `modular-video-player` также не допускает простого
тиражирования одного HTML несколько раз в общей странице.

## Ссылка на видео

В автономной заготовке ссылка задаётся в теге:

```html
<video class="mvp__video" src="ПРЯМАЯ_ССЫЛКА_НА_MP4" playsinline preload="metadata"></video>
```

Нужна именно прямая ссылка на видеофайл, а не ссылка на страницу просмотра.

В runtime Мастер-класса ссылка передаётся параметром `src`; не вписывайте видео
в сам файл плеера.

## Два режима

Режим определяется одной строкой:

```js
const PLAYER_MODE = 'engagement';
```

Допустимые значения:

- `engagement` — внешний плеер: автозапуск без звука, аналитика, ускоренная шкала, отображается только текущее время, перемотка по шкале и главам запрещена;
- `standard` — ручной запуск, без аналитики, обычная шкала, отображаются текущее и общее время.

Оглавление включается независимо:

```js
const CONTENTS_ENABLED = true;
```

- `true` — показать оглавление;
- `false` — скрыть оглавление.

В автономной заготовке значение уже выставлено. В runtime МК
`CONTENTS_ENABLED` вычисляется по наличию переданных глав: без таймкодов
содержание скрыто. В публичном VSL меню глав не подключено.

## Ускоренная шкала прогресса

Параметр действует только в режиме `engagement`:

```js
const PROGRESS_CONFIG = {
  checkpoints: [
    { real:0, shown:0 },
    { real:0.01, shown:0.10 },
    { real:0.05, shown:0.25 },
    { real:0.25, shown:0.50 },
    { real:0.60, shown:0.90 },
    { real:0.70, shown:0.96 },
    { real:1, shown:1 }
  ]
};
```

- на 1% реального просмотра шкала показывает 10%;
- на 5% — 25%;
- на 25% — 50%;
- на 60% — 90%, то есть соотношение около 1,5×;
- после 70% шкала плавно сходится с реальным окончанием и не достигает 100% раньше видео.

Ускоряется только отображение заполнения шкалы. Реальная скорость и длительность видео не меняются.

## Оглавление

Разделы задаются массивом:

```js
const chapters = [
  { at: 0, title: 'Введение' },
  { at: 42, title: 'Главная мысль' },
  { at: 118, title: 'Практический пример' }
];
```

- `at` — начало раздела в секундах;
- `title` — название раздела.

Активный раздел определяется автоматически по текущей позиции видео.

## Скорость воспроизведения

Сейчас доступны:

- x 1;
- x 1.25;
- x 1.5;
- x 1.75;
- x 2.

Список находится в массиве `speedOptions`. Значения в нём можно изменить, но обе части `v` и `l` должны соответствовать друг другу.

## Качество видео

Для переключения качества нужны отдельные прямые ссылки на физические файлы каждого разрешения:

```js
const QUALITY_OPTIONS = [
  { id:'original', label:'Исходное', url:null },
  { id:'1080', label:'1080p', url:'https://site.ru/video-1080.mp4' },
  { id:'720', label:'720p', url:'https://site.ru/video-720.mp4' }
];
```

Строки без `url` не показываются. `original` использует ссылку из тега `<video>`.

Кнопка общих настроек сейчас скрыта по утверждённому дизайну, поэтому выбор качества не выводится в интерфейс. Механизм переключения сохранён в коде для будущего возвращения кнопки.

## Аналитика

В режиме `engagement` просмотр сохраняется локально в `localStorage` и создаёт событие `mvp:analytics` на корневом элементе плеера.
Тихий автозапуск служит только превью: просмотренные интервалы, позиция и
завершение начинают считаться после первого осознанного нажатия пользователя.

Для отправки данных на сервер нужно указать endpoint:

```js
const ANALYTICS_CONFIG = {
  endpoint: 'https://api.example.ru/video-analytics',
  videoId: 'main-video-001',
  bucketSizeSec: 5,
  completionThreshold: 0.95,
  heartbeatSec: 15
};
```

Если `endpoint` пустой, сетевые запросы не отправляются. Для каждого отдельного видео нужно задавать свой стабильный `videoId`.
Этот пример описывает автономную заготовку, не гарантирует совместимость
с публичным API: кроме зарегистрированного ID нужны обязательные `session_id`
и `page_path`, которых её payload не содержит. Простая замена endpoint
не подключает эту заготовку к нашему API; запрос не соответствует его схеме.
У действующего VSL endpoint уже подключён; правила принадлежат
[PUBLIC_VIDEO_ANALYTICS.md](https://github.com/armagedongt/edabalans.ru/blob/main/docs/knowledge-base/PUBLIC_VIDEO_ANALYTICS.md).

События:

- `video_engaged` — пользователь начал осознанное взаимодействие;
- `video_progress` — периодический прогресс;
- `video_complete` — достигнут порог завершения;
- `video_exit` — уход со страницы.

## Плашка включения звука

При автозапуске браузер запускает видео без звука. По нажатию на плашку:

- видео возвращается в начало;
- включается звук;
- воспроизведение продолжается;
- плашка скрывается.

Текст плашки находится в `.mvp__sound-text`, внешний вид — в CSS-блоках
`.mvp__sound-card`, `.mvp__sound-icon` и анимации `mvp-sound-arc`.

Иконка не использует системный emoji: динамик и две расходящиеся дуги нарисованы
inline-SVG. Корпус динамика неподвижен, дуги по очереди появляются, расширяются и
исчезают через `mvp-sound-arc`. При `prefers-reduced-motion` движение отключается.

## Цвета

Главный акцентный цвет задаётся переменными в начале CSS:

```css
--accent:#20aaf5;
--accent-soft:rgba(32,170,245,.84);
```

`--accent` управляет шкалой, активными состояниями и расходящимися волнами
плашки звука. Плашка `Содержание` использует полупрозрачный голубой фон того же
цветового семейства; отдельный фиолетовый акцент не применяется.

## Проверка после изменения

После изменения поведения/вида проверить затронутый профиль, не все
плееры без причины. Документационная правка не требует импорта медиа,
пересборки видео или перезапуска сервиса.
Источники проверок: [test_app_assets.py](https://github.com/armagedongt/edabalans.ru/blob/main/backend/tests/test_app_assets.py),
[test_homepage_preview.py](https://github.com/armagedongt/edabalans.ru/blob/main/backend/tests/test_homepage_preview.py),
[test_public_video_analytics.py](https://github.com/armagedongt/edabalans.ru/blob/main/backend/tests/test_public_video_analytics.py).

Для затронутого плеера проверить:

1. запуск и паузу;
2. включение звука после автозапуска;
3. перемотку согласно выбранному профилю: `standard` и `intensive-day-1` разрешают её, публичные VSL/Аня запрещают;
4. все пять скоростей;
5. открытие и закрытие оглавления;
6. для внешнего плеера — информационные названия без перехода; для внутреннего — переходы по разделам;
7. активную подсветку текущего названия; цифровые таймкоды показываются только во внутреннем плеере;
8. полноэкранный режим;
9. отображение на компьютере и телефоне;
10. отсутствие ошибок JavaScript в консоли браузера.
