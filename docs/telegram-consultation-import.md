# Импорт консультации из Telegram Desktop

Статус: `current`
Владелец модуля: `operations.imports`

## Назначение

Локальные импортёры превращают Telegram Desktop export (ZIP или папку с `result.json`)
или папку с обычными видео/аудио в проверяемую хронологию. Они не создают CRM, не делают медицинских или поведенческих
выводов и не меняют исходный export.

## Запуск

Реальные архивы и результаты хранятся вне Git. Импортёр принудительно отказывается
писать результат внутрь любого Git-репозитория. После установки ключа в переменную
окружения Windows:

```powershell
$env:OPENAI_API_KEY = "..."
python -m app.importers.telegram_consultations `
  "C:\Users\Segey\Documents\ChatGPT\private-consultations\incoming\export.zip" `
  --output "C:\Users\Segey\Documents\ChatGPT\private-consultations\imports"
```

Для папки с локальными файлами (MP4, MOV, MKV, MP3, M4A, WAV и другими типичными
форматами) используется отдельная команда:

```powershell
python -m app.importers.local_media `
  "C:\\Путь\\к\\папке\\с\\видео" `
  --output "C:\\Users\\Segey\\Documents\\ChatGPT\\private-consultations\\imports"
```

Для видео FFmpeg локально извлекает моно-аудио и делит его на 20-минутные временные
файлы, чтобы большие записи не упирались в размер запроса API. Оригинал не меняется,
а временные части удаляются после запуска.

Модель по умолчанию — `gpt-4o-mini-transcribe`. Для смены без изменения кода задаётся
`OPENAI_TRANSCRIPTION_MODEL`; язык — `OPENAI_TRANSCRIPTION_LANGUAGE` (по умолчанию `ru`).
Ключ читается только из `OPENAI_API_KEY` и не записывается в результаты.

## Что сохраняется

Для Telegram создаётся `chat-<id>`, для папки медиа — `media-<id>`:

- `client.json` — метаданные чата, количество сообщений/голосовых, длительность и путь к timeline;
- `messages.json` — нормализованные Telegram-сообщения: `chat_id`, `message_id`, дата, автор, тип,
  относительный путь media, SHA-256, статус голоса и оба варианта транскрипта;
- `media.json` — локальные медиа: относительный путь, дата файла, тип, SHA-256,
  длительность, статус и оба варианта транскрипта;
- `timeline.md` — единая хронология Telegram-текста/голосовых либо файлов папки;
- `import-summary.json` — итог запуска и ошибки отдельных аудио.

Исходное аудио и видео не копируются и не удаляются. Их путь остаётся ссылкой на export/папку, а SHA-256
позволяет сверить файл. При повторном импорте ключ `(chat_id, message_id)` не создаёт
дубликат. Уже обработанный голос повторно не отправляется в API, пока его SHA-256 не изменился;
заменённое медиа расшифровывается заново. Прерванный запрос
помечается `needs_review`, чтобы не создать неявный повторный расход.

Для защиты компьютера ZIP с более чем 50 000 файлами или с распакованным объёмом больше
4 ГБ не принимается.

## Ошибки и граница

Каждое голосовое и каждый локальный файл проходят состояния `pending`, `processing`, `success`, `failed` или
`needs_review`. Ошибка файла или API фиксируется в отчёте и не останавливает остальные
сообщения. Только аудио из voice/audio полей export или временно извлечённая аудиодорожка
локального файла отправляется в OpenAI Transcriptions API.
Следующий чат, который разбирает консультацию, читает `timeline.md` и `messages.json`, но не
изменяет исходную расшифровку.
