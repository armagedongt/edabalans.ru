# Каталог авторских материалов

Статус: `current`
Состояние внедрения: серверный редактор и migration `0029` реализованы.
Проверено: 29.08.2026
План и полный будущий scope: `plans/CONTENT_CATALOG_SPEC.md`

## Назначение

Модуль хранит авторские публикации из Pikabu и Telegram, а позже из собственного
блога. Первая версия text-first: исходный текст, структурные блоки, форматирование,
метрики, CTA, ссылки, позиции медиа и доступные комментарии.

Изображения, видео и другие файлы collector **не скачивает**. Для Pikabu в БД
сохраняются исходный URL, тип, позиция и доступный preview URL. Общая таблица допускает
медиа без публичного `source_url`, потому что будущий Telegram-импорт может располагать
только платформенным идентификатором и метаданными файла. Для каждого материала
обязательна каноническая ссылка на оригинальную публикацию.

Для Pikabu collector сохраняет доступные метрики, включая заявленное число
комментариев. Тексты комментариев, дерево ответов и комментарии автора собираются
только явным запуском `--collect-comments`; по умолчанию они не попадают в локальный
авторский корпус. Динамически скрытые или недоступные ветки не подменяются
выдуманными строками.

## Рабочий серверный каталог

Первый зафиксированный пакет содержит только уже разобранные опубликованные
источники: основной Telegram-канал, LeadTeh-бот, Pikabu, 18 авторских ответов
Pikabu и Telegraph. Контрольные числа снимка: 1 138 активных проявлений,
74 подтверждённые семьи, 961 единичный материал и 70 предполагаемых групп на
проверку. В Git тексты и локальные выгрузки не попадают.

Saved Messages, «Готовые посты», подборки апреля–мая и другие необработанные
источники не входят в первый импорт. Они подключаются позднее по одному источнику:
сначала смысловая очистка, затем поиск дублей/семей, dry-run и только после этого
идемпотентное добавление в тот же каталог.

У семьи нет «главного оригинала»: Telegram, бот, Pikabu и Telegraph являются
равноправными проявлениями. Одинаковый текст с заменой одной ссылки не создаёт
рабочую версию. Смысловые варианты сохраняются отдельными проявлениями. Удаление
из рабочей выдачи обратимо и не меняет запечатанный исходный архив.

В редакторе над текстом находятся только ссылка на опубликованный оригинал и
привязанные медиа. Назначение, темы, смысловая разметка, редакция и технический
provenance показываются после текста. `Ctrl+S` и кнопка сохранения создают новую
неизменяемую редакцию; устаревший номер редакции возвращает конфликт вместо
перезаписи чужих изменений. Повторный импорт Telegram или Pikabu добавляет новую
исходную редакцию, но не переводит текущий текст назад поверх ручной редакции.

Локальная авторская надстройка не требует production и работает на сохранённых
снимках. `tools/build_author_catalog.py` объединяет Telegram, конструктор бота,
Pikabu, Tilda и Telegraph без изменения оригиналов. `tools/build_author_voice.py`
отделяет самостоятельные авторские тексты, фрагменты, сервисный слой, точные
дубли и контекст ответов. `tools/materialize_author_voice.py` собирает приватный
evidence pack и поисковый индекс. `tools/build_rhetorical_library.py` отдельно
строит дешёвый слой `candidate_unreviewed` по всему пригодному корпусу и принимает
в рабочую библиотеку только фрагменты с пофрагментным semantic provenance.
`tools/search_author_voice.py` по умолчанию не показывает механические кандидаты и
ищет по обычной русской фразе. Отдельный `corpus`-слой индексирует 917 пригодных
авторских текстов для проверки повторов и поиска старых наработок, не повышая их
до эталонов голоса. `tools/record_author_correction.py` сохраняет
существенные правки владельца и синхронно обновляет производные счётчики. Для
новой задачи `tools/author_workflow.py` требует явный рабочий профиль, а
`tools/prepare_author_post.py` собирает пропорциональный задаче retrieval pack с маршрутом эмоции/аргумента,
эталонами, correction chains, компактной тематической историей и режимом
редактуры. `tools/validate_author_draft.py` проверяет сохранность и возвращает
`needs_fix`, `manual_review_required` или hash-привязанный `pass`; штатный CLI
публикации принимает только свежий pass-report. Нормативные режимы и проверочная политика принадлежат только
`content/author-voice/`; полные тексты и индексы находятся только в
`C:\private\edabalans-content-authoring`.

Для статьи сайта или внутреннего материала любого курса писатель дополнительно
применяет `knowledge-base/ARTICLE_STANDARD.md`; продуктовая оболочка добавляет
навигацию и прогресс, но не создаёт второй формат текста. Точные разрешения
режимов редактуры принадлежат только
`../content/author-voice/editing-modes-v1.md`.

Обычные статьи Мастер-класса используют существующие `content_items` и
`content_item_versions`, но не смешиваются с импортированными публикациями:
внутренний источник имеет ключ `masterclass-course-materials`. Текущую версию
выбирает `latest_version_id`; старая версия остаётся доступной для восстановления.

В контрольном локальном снимке 1 765 карточек: Telegram — 509, конструктор — 796,
Tilda — 44, Telegraph — 211, Pikabu — 205. Для 33 страниц, найденных через ответы,
тело исходного поста хранится как контекст разговора; голосу обучает только отдельно
атрибутированный ответ `armagedongt` (18 ответов на 18 страницах). Pikabu-маркер
«автор комментария является автором исходного поста» для этой атрибуции не используется.

Browser collector вынесен в отдельные зависимости
`backend/requirements-collector.txt`; production backend не устанавливает Chromium.
Реальная выгрузка должна находиться вне Git-репозитория.

Локальный запуск collector-а по умолчанию text-first: он собирает статьи, ссылки,
медиа-URL и метрики, но не сохраняет тела комментариев. Для отдельного импорта
комментариев нужен явный флаг `--collect-comments`. Для голосового корпуса один
раз выполнен узкий проход `--owner-comments-only` по 33 страницам из архива
ответов: сохранены только доступные комментарии `armagedongt`. Полный сбор веток
и комментариев читателей остаётся отложенным по `plans/PIKABU_COMMENTS_DEFERRED.md`.

## Telegram Desktop JSON

Реализованный этап T1 импортирует только историю публичного канала. Он не читает
discussion export, не импортирует комментарии и не подключает бота/TDLib.

Устойчивая внешняя идентичность имеет вид
`telegram:<channel_id>:<first_message_id>`. Для каждой публикации сохраняются обычная
ссылка `https://t.me/<username>/<message_id>` и вычисляемая API ссылка приложения
`tg://resolve?domain=<username>&post=<message_id>`.

Telegram Desktop не отдаёт `grouped_id`. Parser объединяет только последовательные
медиа-сообщения одного автора с одинаковым временем. Неоднозначные пачки остаются
отдельными публикациями и учитываются как `review_clusters`.

В текущем контрольном экспорте `@Fitness_Talks` обнаружено 703 записи, 694 сообщения,
509 консервативных публикаций и 73 альбома. Дублей и неизвестных полей нет. Views,
forwards и число комментариев в файле отсутствуют и не подменяются нулями. Просмотры
и реакции дополняются отдельным публичным collector. Число репостов и комментариев
публичная HTML-страница канала не отдаёт; поля интерфейса остаются пустыми до появления
подтверждённого источника.

Текст, entities, ссылки, опросы и метаданные вложений входят в неизменяемую версию.
Счётчики реакций и голосов хранятся отдельными metric snapshots, поэтому их изменение
не создаёт ложную новую версию публикации. Фото и видео из export package не читаются
и не копируются.

## API

Все методы требуют действующую административную сессию:

```text
GET /admin/api/content/summary
GET /admin/api/content/items
GET /admin/api/content/items/{id}
GET /admin/api/content/items/{id}/comments
GET /admin/api/content/authoring/summary
GET /admin/api/content/authoring/groups
GET /admin/api/content/authoring/groups/{group_key}
PUT /admin/api/content/authoring/items/{item_id}
GET /admin/api/content/authoring/candidates
POST /admin/api/content/authoring/candidates/decision
```

В `/admin/content` источники Pikabu и Telegram разделены вкладками и не смешиваются.
Внутри источника доступны поиск, сортировка по дате, просмотрам, лайкам/реакциям,
рейтингу, комментариям и числу ссылок, а также фильтр наличия ссылок. Карточка сохраняет
жирный/курсивный текст и кликабельные ссылки, показывает маркеры вложений в позиции
исходного блока, заметную ссылку на оригинал, CTA-текст вместе с конечным URL и все
доступные метрики. Для Pikabu под карточкой показываются импортированные комментарии.

## Граница безопасности

- migration не применяется автоматически;
- collector ничего не публикует и не редактирует на Pikabu;
- export JSON и browser profile запрещено создавать внутри Git-репозитория;
- Telegram discussion export не принимается T1-командой и остаётся будущим T2;
- `--apply` требует явный `--backup-confirmed`, а повторный запуск не создаёт
  вторые карточки, редакции, семьи или кандидатов;
- до production migration выполняются backup и test restore;
- PostgreSQL и collector не публикуются наружу.
