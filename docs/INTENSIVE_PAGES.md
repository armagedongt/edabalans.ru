# Бесплатный интенсив «Последнее похудение»

Статус: `current`

Главная интенсива доступна по адресу `/intensive`, четыре части — по адресам
`/intensive/day-1` — `/intensive/day-4`. Страницы закрыты от поисковой индексации и
используют единый визуальный язык интенсива, общую шапку и общий подвал.

Ссылка из бота ведёт через `/intensive/start`: она открывает текущую доступную часть,
а после прохождения четвёртой части — меню. Прямой `/intensive` всегда открывает
именно меню и не выполняет автоматический переход. Если персональной серверной
сессии нет, меню и все четыре части доступны сразу: публичный вход не отправляет
человека в бота и не создаёт персональный прогресс. Те же страницы можно открыть
во встроенном браузере Telegram как Mini App; персональная ссылка из бота при этом
восстанавливает серверную сессию и сохраняет индивидуальный порядок прохождения.

Источник истины для времени первого входа, открытых частей, переходов к обязательному
посту и источника мессенджера — PostgreSQL. Подписанная HttpOnly cookie только
восстанавливает связанную серверную identity, а `/intensive/runtime.js` хранит в
браузере технический session id, атрибуцию и уже показанные уведомления. Следующая
часть в персональном режиме открывается через 23 часа и только после перехода по
кнопке к обязательному посту. Анонимный публичный режим этих ограничений не
применяет. Вход идентифицированного участника в ещё закрытую часть возвращает в
меню. После первого открытия четвёртой части
время персонального предложения фиксируется один раз и передаётся в ссылку на
Мастер-класс; повторное открытие страницы его не перезапускает.

Runtime переносит `utm_*`, `yclid`, `from` и `alias`, а также отправляет согласованные
цели в Яндекс Метрику `97331502`. Telegram и MAX используют один web-контракт;
конкретные публикационные адреса постов поставляет владелец messaging-сценария.

После редактируемой статьи оболочка страницы подключает общий публичный подвал из
`/site-footer.js`. Юридические ссылки не входят в сохраняемый HTML статьи и не
копируются отдельно между четырьмя днями.

Версионные API редактирования четырёх дней сохранены как отдельная возможность.
Текущая собранная публичная версия страниц выпускается из статических источников в
Git, чтобы сложная блочная разметка и механики не разрушались обычным rich-text
редактором.

Редактор остаётся обычным белым полотном. Компактная панель позволяет превратить
текущий абзац в текст, заголовок, важное выделение или акцент, а также добавить
жирное/курсивное начертание, ссылку, маркированный или нумерованный список и картинку
по прямой HTTPS-ссылке. Произвольные стили, скрипты и небезопасные адреса картинок
сервер не сохраняет.

Сохранённый HTML проходит серверную очистку и записывается как внутренняя версия в
существующий каталог авторских материалов (`content_sources`, `content_items`,
`content_item_versions`). Статические файлы в `backend/app/static/intensive/`
являются источником публичной блочной разметки. Номер версии API защищает от
незаметной перезаписи управляемого текста, если один документ одновременно открыли
в двух редакторах. Отдельной CMS и отдельной таблицы для четырёх страниц нет.

API:

- `GET /api/intensive/{day_code}` — получить общую версию страницы;
- `GET /admin/api/intensive/{day_code}` — открыть её для редактирования;
- `PUT /admin/api/intensive/{day_code}` — сохранить после проверки администратора.
