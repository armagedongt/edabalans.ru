# Единый каталог изображений

Статус: `current`
Модуль: `platform.content`
Проверено: 18.10.2026

## Канон и размещение

Карточки находятся в существующей Knowledge Library:
`knowledge://resource/image-<24 символа SHA-256 оригинала>`, `kind=image`,
`metadata.catalog=site-images`. Вход — `/admin/library`, поиск по названию,
описанию, темам и страницам использования. Новая CMS или таблица не создаётся.
Владелец медиаданных — `platform.content`; `platform.knowledge` предоставляет
поиск, версии и provenance. Идентификаторы отзывов `R…` сохранены в
`metadata.review_id` и связаны с прежними URL и манифестами.

Первый пакет: изображения действующей главной `/` и единой статьи `/intensive`.
Архивные дни, посадочные и остальной блог не входят в пакет. Логотипы, favicon,
значки мессенджеров и декоративные иконки отложены вместе с админкой.
Авторский текст не меняется.

Карточка содержит название и описание видимого, темы, тип, происхождение,
исходные URL, все обнаруженные использования в пакете, оригинал с SHA-256,
размером и форматом, версии с назначением, прозрачность/анимацию, доступ и
индивидуальное решение об оптимизации. Имена берутся из подписей материала,
не угадываются по фото. `public` означает уже опубликованное изображение,
не разрешение открывать закрытые материалы.

Размещение использует существующий media-контракт из [OPERATIONS](OPERATIONS.md):

- оригиналы и сохранённые исходные кодировки:
  `/srv/edabalans-public/reviews-manifests/site-images-20261018/originals/`;
- новые версии сайта: `/srv/edabalans-public/reviews/site-images-v1/<sha256>.<ext>`;
  публичный путь `/media/reviews/site-images-v1/…`;
- превью: `reviews-manifests/site-images-20261018/previews/`, вне публичного mount;
- локальное зеркало: `D:\Codex\private\site-images-20261018`;
- `knowledge-export.json` рядом с оригиналами — экспорт серверных карточек,
  не второй редактируемый реестр; `prepared.json` и `records.json` — снимки
  выполнения пакета, не канон последующих правок.

Хорошо подготовленные ресурсы остаются по прежним управляемым URL. Оригиналы,
фотографии людей и реальные выгрузки в Git не помещаются. Опубликованный
hash-URL не заменяется: новая редакция получает новый hash.

## Критерии оптимизации

Учитывать содержимое, размер показа и увеличение, плотность экрана, детали,
мелкий текст, прозрачность, анимацию и прежнее сжатие. Обязательного предельного
веса и единого качества для всех файлов нет.

1. Сначала проверить существующие версии. Совпадающие размеры и декодированные
   пиксели позволяют использовать общий файл без пережатия. Визуальное сходство
   само по себе не доказывает дубль.
2. PNG/JPEG со скриншотами, таблицами, мемами и мелким текстом проверить в WebP
   без потерь. В первом пакете замена оправдана при экономии одновременно не
   менее 15% и 8 KiB. Проверить совпадение декодированных пикселей и размеров,
   включая альфа-канал. Это порог полезности перекодирования, не лимит файла.
3. Для фотографий допустим WebP Q92 после сравнения деталей, лиц, цвета и
   надписей. В этом пакете так обработаны только коллаж автора и фото гранолы.
   Исходник сохраняется; Q92 не применяется автоматически к тексту.
4. Уже подготовленный WebP без доказанного выигрыша оставить. Документы,
   которые читают с увеличением, сохранить качественными, даже если они тяжелее.
5. Размеры исходников в первом пакете не уменьшаются. Карточки программы главной
   показываются примерно в 269 CSS px, отзывы — 365–380 CSS px, основной контент —
   до 760 CSS px. Полноэкранное чтение отзывов и документов требует большего
   разрешения. Маленькие оригиналы не увеличивать.
6. Для последующих маленьких версий учитывать CSS-размер и DPR до 2, сохраняя
   качественную версию для увеличения. Другую обрезку, надпись или смысловую
   редакцию не объединять автоматически.

Карточка фиксирует `keep`, `lossless_webp`, `photo_webp_q92`, `reuse_exact`,
`reuse_approved`, `relocate` либо `manual_review` и объяснение. `reuse_approved` — проверенная
существующая редакция того же изображения, а не равенство пикселей.

Два существующих встроенных JPEG тарифного блока сохранены без изменения и
зарегистрированы как `unverified` / `manual_review`: Pillow не декодирует их.
Байты извлечены из действующей страницы и сохранены; ремонт этих изображений
не входит в пакет сжатия. Они не потеряны и не объявляются проверенными.

## Обновление и сохранность

Сначала читать карточку через MCP и сверять SHA оригинала. Новую версию сохранять
через `register_knowledge_resource` с `expected_version`, сохраняя стабильный
`resource_key`, provenance и использования. У двух схем главной и интенсива
побайтно совпали декодированные пиксели; фото Натальи и отзыв Александры связаны
после визуальной проверки, обе исходные кодировки сохранены. Разные обрезки схемы
«до, после и после после» остались отдельными карточками.

После обновления серверных карточек экспортировать их через MCP `read_knowledge`
в `knowledge-export.json`, затем копировать экспорт и недостающие файлы на ПК.
Файлы адресуются хешем: совпавший SHA повторно не скачивать, несовпавший не
перезаписывать. Сверять SHA-256 на сервере и ПК. Локальные правки в экспорт не
вносить: сначала обновить серверную карточку, затем повторить экспорт.
Удаление оригиналов и очистка прежних каталогов сюда не входят.

Перед записью первого пакета выполнены backup и настоящее тестовое восстановление
обеих БД. Метаданные защищает штатный backup PostgreSQL; файлы существуют на
сервере и в локальном зеркале. Прежние каталоги отзывов не пересобираются.

Менять ссылки у владельца: HTML и `block-map.json` главной плюс активная редакция
`public-site-homepage/homepage`; Markdown единой статьи — в Git. Рабочая папка
Obsidian обновляется выборочно `editorial_vault.py refresh homepage intensive`
с сохранением черновиков. Исторические версии и старые URL сохраняются.
После публикации проверить HTTP 200, Content-Type, длину и SHA новых ресурсов,
отсутствие внешних img-ссылок этих страниц, сохранность текста и увеличения.
Экономию считать по уникальным ресурсам каждой страницы; это уменьшение загрузки,
а не освобождённое дисковое место: оригиналы остаются.
