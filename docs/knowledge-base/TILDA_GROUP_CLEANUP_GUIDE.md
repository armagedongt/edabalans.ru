# Рабочая инструкция: группы Tilda после перехода на серверный Мастер-класс

Статус: `current_transition_plan`
Для кого: Сергей и сотрудники с доступом к Tilda Members Area
Проверено: 23.08.2026
Источник чисел: одноразовый снимок Tilda от 22.08.2026; повторная синхронизация не выполняется

## Целевая структура

Для запуска Мастер-класса нужны четыре понятные категории групп:

1. `Мастер-класс — новый кабинет` — одна общая группа всех актуальных тарифов.
2. `Регистрация — нужна проверка Сергея` — люди без подтверждённого продукта.
3. `Мастер-класс. ОТКРЫТ. Не обновляется.` — старый физический курс Tilda.
4. `«Калорийный» курс ОТКРЫТ. Не обновляется.` — старый физический курс Tilda;
   существующую группу с лишней кавычкой в названии можно переименовать именно так.

Группы актуальных Калорийного курса, рецептов и записей пока сохраняются: их
серверные кабинеты ещё не заменили текущие страницы. Они удаляются отдельным
этапом после переноса соответствующего продукта.

## Проверенные числа

- `Мастер-класс`: 22;
- `Мастер-класс (Стандартный)`: 53;
- `Мастер-класс (С консультацией)`: 1;
- уникальных владельцев актуального Мастер-класса: 76, пересечений между тремя
  группами нет;
- людей хотя бы с одним актуальным продуктом Tilda: 85;
- `Добро пожаловать`: 23, из них 12 уже имеют продуктовую группу и 11 остаются
  только на ручную проверку;
- только старые необновляемые продукты без актуальной группы: 4.

Числа являются контрольным снимком, а не будущим источником доступов.

## Порядок переноса

### Этап 1. Общая группа нового Мастер-класса

1. Переименовать существующую группу `Мастер-класс` с ID `1074561` в
   `Мастер-класс — новый кабинет`.
2. Оставить в ней текущих 22 участников.
3. Добавить в неё 53 участников группы `Мастер-класс (Стандартный)` и одного
   участника группы `Мастер-класс (С консультацией)`. Контрольный итог — 76.
4. Привязать к группе актуальный курс `Мастер-класс` с ID `421325`; внутри курса
   оставить одну страницу с серверным приложением.
5. Проверить вход одним участником каждого старого тарифа. Только после проверки
   удалить этих 54 человек из двух тарифных групп.
6. Пустые группы `Мастер-класс (Стандартный)` и `Мастер-класс (С консультацией)`
   сначала переименовать с префиксом `АРХИВ —`, а удалить позднее после
   контрольного периода.

### Этап 2. Новые оплаты

1. В настройках сайта Tilda добавить приёмщик `Личный кабинет`, выбрав одну группу
   `Мастер-класс — новый кабинет`.
2. Подключить этот приёмщик и существующий webhook PostgreSQL к единственному
   блоку корзины `ST100` на странице продаж.
3. В платёжной системе оставить отправку в приёмщики только после успешной оплаты.
4. В группе разрешить добавление пользователя без ручного подтверждения.
5. Не задавать одну ожидаемую сумму группы: у трёх тарифов разные цены, а точную
   сумму, версию и состав проверяет backend по checkout-ID.
6. Все три тарифа отправляют пользователя в одну группу. Отличия тарифов в Tilda
   больше не кодируются.

Официальная инструкция Tilda по платной регистрации:
<https://help-ru.tilda.cc/membership>.

### Этап 3. Группа ручной проверки

1. Переименовать `Добро пожаловать` в `Регистрация — нужна проверка Сергея`.
2. После проверки удалить из неё 12 человек, уже состоящих в продуктовых группах.
3. В группе должны остаться 11 неопределённых аккаунтов. Сервер для них продолжает
   показывать просьбу связаться с Сергеем и игнорирует исторические права до решения.
4. Открытая регистрация без покупки, если она понадобится, ведёт только сюда, а не
   в новый Мастер-класс.

## Что пока не удалять

- `«Калорийный» курс` и одноимённый актуальный курс;
- `Книга рецептов` и `Каталог рецептов`;
- `Записи разборов`;
- обе группы и оба курса с пометкой `ОТКРЫТ. Не обновляется.`;
- `Доп. #1. Калории, рецепты, разборы.` до проверки его текущего назначения;
- `Купить доп. материалы` до проверки новой серверной допродажи;
- интенсив `Последнее похудение` — он не относится к этому переносу.

## Запреты

- не выдавать серверные права добавлением в группу Tilda;
- не переносить 9 участников старого Мастер-класса в новый автоматически;
- не удалять исходную тарифную группу до контрольного входа её участников;
- не делать новую выгрузку Tilda для PostgreSQL;
- не использовать число участников группы как число уникальных клиентов без
  проверки пересечений.
