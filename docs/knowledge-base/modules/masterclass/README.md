## Куда обращаться по дополнительным предложениям

Это постоянная карта источников для нового ИИ-чата и разработчика. Не собирать
логику предложений из переписки и не создавать параллельный каталог:

- активная ревизия `course-structure/masterclass-21` в PostgreSQL
  `managed_document_versions` — runtime-структура дней, место блока, порядок и
  обязательность открытия; `../../../../content/masterclass/course/course.json`
  служит только seed до появления первой ревизии;
- `content_items`/`content_item_versions` источника
  `masterclass-course-materials` — опубликованное тело обычных статей; локальная
  команда `tools/publish_course_material.py` меняет одну статью без code deploy;
- `OFFERS_MODULE.md` — скидочные окна, таймеры, переходы, покупки и уведомления;
- `../../PRICING_CATALOG.md` и PostgreSQL `offer_stages` — действующие цены;
- `../../../../backend/app/masterclass_offer_catalog.py` — единые названия,
  описания и состав продуктов для карточек, а также активная обратимая версия
  показа `site_short_v1`;
- `COURSE_VISUAL_SYSTEM.md` — оформление блока внутри курса;
- `../telegram/POST_PURCHASE_MASTERCLASS.md` — получение Telegram готового
  due-события без самостоятельного расчёта условий;
- `/admin/masterclass-offers-preview` — защищённый инструмент с двумя режимами:
  ручной сценарий и read-only проверка реального клиента. Варианты мест показа берутся
  из канонического `content/masterclass/course/course.json`; после поиска по email сервер работает только с `users.id`;
  состав и цены карточек рассчитывает тот же backend, а HTML карточек и CSS берутся из клиентского блока
  курса.

Страница предпросмотра не является редактором и не хранит собственных бизнес-правил.
После изменения канонических файлов или серверного каталога она обновляется вместе
с опубликованной версией приложения.

Чтобы новый чат немедленно поднял тот же конструктор, ему не нужно искать старые
переписки: открыть `/admin/masterclass-offers-preview`, затем следовать разделу
«Быстрый запуск конструктора в новом чате» в `OFFERS_MODULE.md`. Этот маршрут
обязателен и для правок: отдельную копию карточек, цен, таймеров или CSS создавать
нельзя.

## Главный принцип

Общие правила выдачи старой и новой версии, ручной проверки исторических клиентов
и отложенного открытия зависимых продуктов находятся в
`../../ACCESS_RULES.md`.

Мастер-класс существует в Tilda в одном экземпляре для всех тарифов. Не создавать
отдельные копии программы «с рецептами» и «без рецептов».

Физически в Tilda остаётся одна страница «Мастер-класс». Она загружает единое
серверное приложение со всеми 21 днями, статьями, чек-листами и интерактивными
точками. Стартовая анкета, опрос по продуктовым категориям, саморевью и привязка мессенджера являются типами обычного
материала внутри общего списка. DQS и переиспользуемый модуль дополнительных
продаж сохраняют собственную специализированную логику, но визуально работают
в оболочке курса. Прогресс и доступ проверяет FastAPI/PostgreSQL, а не
Tilda-разметка и не браузерный `localStorage`.

Покупка и открытие — разные факты:

- право на продукт фиксируется сразу после подтверждённой покупки;
- модуль может быть куплен, но временно закрыт до этапа программы;
- сервер открывает его только при выполненном условии;
- простая скрытая ссылка не является доступом и не заменяет серверную проверку.

  отправка по умолчанию выключена через `POSTPURCHASE_DISPATCH_ENABLED=false`;

По решению владельца от 23.08.2026 на переходном этапе клиентский email берётся
только из закрытой страницы Tilda Members Area без повторного почтового кода.
FastAPI по этому email находит внутренний `user_id` и каждый раз проверяет
`ACCESS_MASTERCLASS`, покупки и доступность этапа. Tilda-группа не является
источником продуктовых прав. Это осознанно более слабая идентификация, чем
подписанная серверная сессия: её принимают временно ради бесшовного входа, пока
Tilda остаётся закрытой оболочкой. Ручной ввод email внутри приложения запрещён.
Места Tilda с офферами и рецептами дополнительно получают подписанный маркер:
посетитель не может подменить этап и запросить более раннюю цену. Маркер не содержит
цен, email или других персональных данных; его готовое значение хранится только в
Tilda и не является отдельным административным источником данных.

Production работает на migration `20260823_0018`. Тестовая Telegram-отправка

## Интерактивные материалы и единый загрузчик Tilda

Мастер-класс различает обычные интерактивные материалы и специализированные
приложения:

- `questionnaire` — обычный тип материала для начальной анкеты, опроса по
  продуктовым категориям во втором дне и итогового саморевью;
- `messenger` — обычный тип материала для привязки канала;
- `masterclass-offers` — единый расчёт предложений и проверка права перед рецептами;
- `dqs` — существующее приложение DQS;
- `recipes-part-1` — первая часть рецептов (содержимое будет добавлено позже);
- `recipes-part-2` — вторая часть рецептов (содержимое будет добавлено позже);
- Telegram-модуль `postpurchase_masterclass` — уведомления между этими точками.

Материал дня 2 `day-02-current-diet` использует вид анкеты `current-diet`. Он
сохраняет черновик по 16 стабильным кодам категорий, позволяет вернуться к
заполнению и после отправки создаёт идемпотентный сигнал
`current_diet_questionnaire_completed`. Полные ответы остаются в профильной
таблице; Telegram получает их только при формировании сообщения по редактируемому
шаблону `tpl_postpurchase_current_diet`. Если Telegram ещё не привязан, задача
остаётся в очереди до появления связи.

В Tilda размещается один общий загрузчик с разными параметрами `app` и
`placement`. Значение `placement` сообщает только место лекции, например точку
дня 1, `day-15-offer`, `day-17-offer`, `day-19-offer`, `day-21-offer` или
`recipes-part-1-gate`; оно не передаёт цену и не доказывает доступ. Старые коды
`day-2-offer`, `closing-review` и `post-review` сохраняются только для
совместимости уже выпущенных ссылок.
Старый блок Tilda не может вернуть истёкшую скидку.

На страницах с оплатой добавляется одна корзина `ST100`. Серверная кнопка покупки
передаёт ей команду `#order:Название=Цена`. Отдельные платёжные URL не создаются.

Пока карточки «С дивана до тренировок» и «Записи консультаций других участников»
участвуют в модели и предпросмотре так, словно продукты доступны. Их фактическую
продажу можно выключить статусом каталога без переделки экранов. При купленной
индивидуальной консультации записи чужих консультаций не показываются.

## Согласованный путь участника

### 1. Первый день и онбординг

Первая часть мастер-класса содержит:

1. вводную видеолекцию в Tilda;
2. правила ведения дневника;
3. интерактивный материал с начальной анкетой;
4. следующий интерактивный материал для связи Telegram. MAX остаётся отдельной
   будущей интеграцией и не считается привязанным до появления серверного consumer.

После отправки анкеты сервер уже сохраняет ответы в CRM независимо от того,
перешлёт ли клиент их Сергею. Материал привязки выдаёт ссылки в боты с одноразовым
непрозрачным токеном. Токен связывает bot account с существующим `user_id`, поэтому
email не нужно просить вводить заново и нельзя передавать открытым текстом в URL.
Все пользовательские endpoint Мастер-класса получают email из авторизованного
профиля закрытой Tilda Members Area и по нему повторно проверяют серверный доступ.
Дополнительной формы входа, почтового кода и пользовательской `app_session` в
текущем ЛК нет.

После перехода бот:

- показывает найденный email; если в данных ошибка, участник пишет Сергею, а бот
  не создаёт отдельную ветку изменения email;
- показывает структурированную сводку: номер вопроса, заголовок и ответ;
- добавляет Telegram/MAX username, тариф и дату покупки;
- предлагает отправить сводку Сергею даже на самостоятельном тарифе;
- сохраняет всё в CRM, даже если пользователь не нажал отправку.

Автоматическое уведомление может прийти в служебный чат Сергея с ботом. Бот не
может от имени клиента сам создать сообщение в личном диалоге «Сергей ↔ клиент»;
после уведомления Сергей связывается с человеком вручную и при необходимости
пересылает сводку в их личную переписку.

### 2. Первое открытие DQS

Следующая серверная лекция открывает DQS. Первый подтверждённый вход или первое
сохранение данных создаёт событие прогресса. В текущей утверждаемой схеме это
событие не отправляет сообщение. Поддерживающие видеокружки и ежедневная
мотивационная рассылка проектируются позднее отдельным модулем.

### 3. Рецептурные эпизоды и дополнительные предложения

Точные дни, порядок карточек и обязательность открытия задаются активной ревизией
`course-structure/masterclass-21` в `managed_document_versions`; `course.json` —
только начальный seed. Правила скидочных ступеней, неизменяемых
окон, пересчёта ассортимента и Telegram-напоминаний задаются только в
`OFFERS_MODULE.md`. В этом обзорном документе они не дублируются.

Backend всегда повторно проверяет право на закрытый материал и не доверяет факту
наличия ссылки. Telegram не рассчитывает ассортимент, цены и срок: он получает
готовое due-событие от CRM/Core. Покупка внутри действующего окна немедленно
пересчитывает витрину сайта и отменяет Telegram-напоминание этого окна.

Содержание первой и второй частей рецептов проектируется отдельно от механики
показа и продажи.

### 4. Завершающая анкета и консультация

В конце открывается обычный интерактивный материал с итоговой анкетой:

- клиент фиксирует выводы по мастер-классу;
- при купленной консультации выбирает готовность к разбору и желаемый формат;
- одной кнопкой отправляет результат в CRM и служебный Telegram Сергея;
- при отсутствии консультации видит предложение консультации и других допустимых
  продуктов;
- исходная покупка и доступы повторно проверяются перед показом предложения.

Финальное окно и автоматический переход к последней неделе рассчитываются по
`OFFERS_MODULE.md`, а не по скорости прохождения или дню фактического открытия
финала.

### 5. Калории и тренировки

Для курсов о калориях и тренировок позже нужно описать собственные события
прогресса, доступы и коммуникации. Предварительно основное взаимодействие остаётся
на сайте; обязательные сообщения бота пока не определены.

## События, которые должна выдавать программа

Общие события жизненного цикла:

- `onboarding_questionnaire_completed`;
- `messenger_link_confirmed`;
- `dqs_opened` или `dqs_first_entry_saved`;
- `masterclass_checkpoint_reached`;
- `masterclass_completed`;
- `closing_review_opened`;
- `closing_review_submitted`.

Точные события материалов и placement-коды читаются из активной runtime-структуры
курса; правила их коммерческой интерпретации — из `OFFERS_MODULE.md`.

`masterclass_checkpoint_reached` пока не запускает сообщений: контроль темпа и
ежедневная мотивация вынесены в будущий отдельный модуль.

Повторное открытие страницы не создаёт повторную цепочку. Для маркетингового
действия учитывается первое подходящее событие и журналируется результат каждой
попытки.

Все персональные предложения образуют одну необратимую шкалу; точная логика
переходов и исключений принадлежит `OFFERS_MODULE.md`:
`welcome → early → second → review → last_week → standard`. Повторное открытие старой
лекции Tilda не возвращает более раннюю цену. Здесь намеренно не повторяются
условия запуска таймеров и состав карточек: их нужно читать в каноническом модуле
предложений.

## Важное правило для исторических клиентов

Клиентам, которые до даты перехода уже приобрели исторический стандартный тариф
мастер-класса, но не имеют отдельного права на новый каталог рецептов, нужно дать
право на **первую** часть рецептов. Вторая часть содержит новые материалы и без
отдельного права не открывается.

Предварительная дата перехода — 22.08.2026. Перед миграцией нужно уточнить, входит
ли сама дата 22.08.2026 в историческую группу, и составить предварительный список
затронутых клиентов с возможностью отката.
