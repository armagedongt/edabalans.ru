# Визуальная система единого курса

Статус: `current`  
Владелец решения: Сергей Воронцов  
Зафиксировано: 17.09.2026
Назначение: изменяемые правила внешнего вида всех курсов.

## 1. Граница документа

Визуальная система определяет цвета, шрифты, размеры, насыщенности, отступы,
геометрию карточек, иконки, состояния и адаптивное расположение элементов.

Она не определяет состав данных, порядок смысловых блоков, правила подсчёта времени,
условия завершения и источники текстов. Они находятся в
[структурном контракте](COURSE_STRUCTURE_CONTRACT.md).

Визуальные правила можно менять после утверждения структуры. Такая правка не должна
требовать новых полей в курсе, дне или материале.

### Единственный рабочий источник оформления

Каркас и утверждённое оформление курса находятся в
`backend/app/static/course-visual.css`, главной ЛК — в `account-visual.css`.
Базовый шрифт курса задан на `#masterclass-course-app`, а не унаследован от
обёртки главной ЛК: вложенный и прямой вход не меняют жирность текста.
В HTML этих экранов нет прежнего встроенного CSS, поверх которого накладывается
новая тема. История старого оформления остаётся в Git, а не подключается к экрану.
`account-theme.css` определяет только общие состояния светлой/тёмной темы.
Общие стили текста `article-typography.css` и `article-note.css` подключаются
отдельными ссылками параллельно с оболочкой, без последовательного `@import`.
Прямой адрес дня и переход через «Открыть» используют одинаковые правила.

## 2. Типографическая шкала текущего варианта

Интерфейс использует `Manrope` с системным запасным вариантом и ограниченную шкалу.
Только фирменная надпись использует `Unbounded` 800; мозг — существующее прозрачное
изображение без подложки и обводки, с небольшой тенью.
Произвольные размеры и жирности для отдельных экранов не добавляются.

| Роль | Размер | Насыщенность | Цветовая роль |
|---|---:|---:|---|
| Служебная подпись | 14 px | 600 | приглушённый или акцентный |
| Кнопка и малая навигация | 14 px | 600/800 | по поверхности |
| Основной текст и карточка | 16 px | 400/600 | основной или приглушённый |
| Вводный текст | 16 px | 400 | основной |
| Заголовок карточки или подраздела | 23 px | 800 | основной |
| Заголовок раздела | 29 px | 800 | основной |
| Главный заголовок открытого дня и открытого материала | адаптивно 32–44 px | 800 | основной |

Основная шкала насыщенностей: `400`, `600`, `800`; UI также использует `700`.

Обычный вводный текст над медиа и под ним использует одинаковый основной цвет.
HTML-абзацы под медиа и перед заданием разделяются интервалом 18 px; пробелы и
переводы строк внутри HTML-абзаца не создают дополнительные пустые строки.
Для обычного многострочного редакторского поля переносы строк сохраняются.

## 3. Цветовые роли текущего варианта

Цвет назначается роли, а не конкретному тексту или дню:

- основной текст;
- приглушённый текст;
- фон страницы;
- поверхность карточки;
- разделитель;
- основной акцент;
- завершённое состояние;
- тёмная поверхность меню;
- специальное приложение;
- служебное действие;
- предложение продукта.

Текущий канонический набор базовых токенов курса:

| Роль | Значение |
|---|---|
| Основной текст | `#17191E` |
| Приглушённый текст | `#46515B` |
| Главная ЛК / карточка | белый `#FFFFFF` |
| Фон курса в светлой теме | белый `#FFFFFF`, без отдельного белого листа внутри статьи |
| Спокойный CTA | `#27AFF5` |
| Служебная ссылка | `#118ED8` |
| Золотой акцент | `#FFC25A` → `#F39A2F`, градиент 135° |
| Максимальное внимание / покупка | `#F46A35` |
| Яркая панель | `#34BAF7` → `#27AFF5` → `#1E9FE5` |
| Текстовая плашка | `#FFF6C9`, временный цвет, устойчивый стиль |

Обозначение «ДЕНЬ N» использует основной оранжевый акцент, а стоящее рядом
«≈ X минут на изучение» — отдельный приглушённый цвет и среднюю насыщенность.
Завершённое состояние использует зелёную роль. Эти значения меняются только здесь
как единый набор токенов; отдельный экран или статья не задаёт собственный вариант
основного текста, приглушённого текста или акцента.

## 4. Карточки

- Обычные учебные материалы используют один базовый стиль.
- Анкета, мессенджер и приложение не получают разных цветов по типу.
  Есть только один дополнительный слегка оранжевый вариант `.topic.offer`.
  Состояния доступности и завершения — отдельное правило, не новые стили акцента.
- У карточек единая минимальная высота 116 px на всех ширинах; длинное название
  увеличивает высоту без обрезания текста.
- Заголовок и описание ограничиваются так, чтобы не ломать сетку.
- Номер, текст и маркер состояния выровнены одинаково для всех типов материалов.
- Предложение выделяется сильнее обычной карточки, но не получает отдельной внешней
  секции или иной структуры содержания.

## 5. Состояния и иконки

Структура передаёт смысловое состояние: текущий, завершённый, доступный или
закрытый. Визуальная система выбирает его представление:

- выбранный сейчас день — золотой номер и активная подложка независимо от того,
  завершён он или нет; доступный непройденный день не имеет дополнительного символа;
- завершённость — независимое состояние: она добавляет зелёную галочку справа,
  но не отменяет активную подложку и золотой номер выбранного дня;
- доступный материал — синий номер и круглый синий маркер;
- закрытый — замок и приглушение.

Замок один и тот же по форме: белый в оглавлении, синий в материалах дня.
Весь символ, а не его верхняя грань, центрирован по карточке. Для состояния
выделено постоянное место, ширина названия не прыгает. Закрытый материал
подсвечивается при наведении без подъёма и без курсора «стоп»; открытый — голубым
с небольшим подъёмом. Пройденный материал имеет зелёное обозначение.

Если карточка закрыта редакционно, а не последовательностью прохождения, над её
названием показывается компактная плашка состояния, например «Скоро». Карточка
остаётся в общем списке и сохраняет стандартную геометрию.

Для открытого материала используется отдельная акцентная метка внутри текущего
дня. Незавершённый открытый день не выглядит завершённым даже после просмотра
части материалов.

Конкретные символы и набор иконок можно заменить позже без изменения данных или
логики доступности.

## 6. Оглавление и шапка

- На ширине свыше `900 px` оглавление постоянно закреплено слева, `320 px`.
  Верхней шапки и возможности скрыть оглавление на ПК нет.
- Вверху оглавления мозг, надпись и мобильный крестик находятся в одной строке;
  на телефоне между надписью и крестиком находится переключатель темы.
  Переключатель и крестик одинаковые, компактные: 32 × 32 px; символ переключения
  16 px, крестик оптически того же размера. Мозг 28 × 28 px и надпись вместе
  занимают оставшуюся ширину без наложения на кнопки. Крестик скрыт на ПК.
  Ниже — полноширинная белая кнопка «Личный кабинет» с hover.
  Далее `КУРС:` жирным капсом и обычное название тем же шрифтом. «Вся программа»
  и отдельный подвал оглавления не используются.
- Ссылка «Личный кабинет» в оглавлении выглядит как белая центрированная кнопка.
- Название курса имеет среднюю, а не максимальную жирность.
- На узком экране закреплённая строка содержит только «Оглавление» слева и
  «Содержание» справа, когда содержание доступно по правилам § 7.2.
  «Личный кабинет» и переключатель темы находятся внутри оглавления.
- Открытое мобильное оглавление повторяет общую структуру широкого меню.

До `900 px` меню становится выдвижным. При обычном входе с телефона оно открыто,
за ним последний доступный выбранный день; на ПК сразу этот день. При отсутствии
сохранённого доступного дня выбирается серверный текущий день. Прямая ссылка
на материал сохраняет маршрут и не перекрывается автоматическим меню.

Все дни имеют лёгкое выделение до hover, при hover оно усиливается одинаково.
Рецепты отличаются только левой внутренней скобкой старого кабинета:
`box-shadow: inset 3px 0 #ffc25a` с существующим скруглением карточки. Нет отдельной
обводки, тёмной групповой подложки или другого hover. Нативная прокрутка остаётся,
ползунок тонкий полупрозрачный белый на прозрачной дорожке; стрелки не показаны.

### Туториал первого дня

- Туториал открывается как полноценный экран курса, а не как небольшое модальное
  окно поверх дня.
- Первый обязательный туториал — обычная текстовая статья «Как пользоваться
  Мастер-классом». Отдельный демонстрационный визуальный экран не используется;
  унаследованный код такого экрана не является референсом текущей редакции.
- Навигация остаётся заметной и доступной внизу экрана, но не перекрывает текст.
- Отдельного финального экрана с контактами нет. Туториал объясняет только работу
  курса: оглавление, состояния материалов, навигацию, сохранение прогресса,
  чек-лист и открытие следующего дня.
- Обращение ведётся от первого лица; имя автора внутри туториала не используется.

## 7. День, материалы и следующий день

- Обозначение «ДЕНЬ N» набирается акцентным цветом и прописными. Пояснение
  примерного времени — строчными, приглушённым цветом и менее жирным начертанием.
- Основное медиа занимает доступную ширину контентной колонки; на телефоне может
  доходить до краёв экрана.
- Обычная картинка дня и обычная картинка внутри материала показываются как само
  изображение в текущей адаптивной ширине: без фонового контейнера, затемнения,
  рамки, подписи и декоративной обёртки. На широком экране сохраняется ширина
  соответствующей контентной колонки, на телефоне — предусмотренный макетом выход
  изображения к краям. Это правило не меняет специальные слайдеры и приложения.
- «Далее в программе» — небольшая приглушённая подпись капсом.
- В карточке строка «День N · Название дня» чёрная; время синее. Фон голубой,
  окантовка синяя; золотая левая полоска полностью перекрывает левую окантовку.
- На широком экране карточка следующего дня группирует содержание и управление в
  две колонки.
- На телефоне те же элементы идут сверху вниз: название и время слева,
  таймер и золотая кнопка отдельно центрированы.
- Карточки на телефоне сохраняют единую компактную высоту: внутренние отступы и
  служебные иконки уменьшаются, но заголовок, краткое описание и время остаются
  видимыми.
- Таймер и единственная контекстная кнопка образуют одну визуальную группу.
- Таймер — светлая скруглённая плашка с синим текстом `#17607f`.
- Нижняя навигация внутри материала использует короткие подписи «Предыдущий»,
  «Оглавление» и «Далее», среднюю насыщенность и удобную высоту. Отдельная верхняя
  ссылка «К материалам дня» визуально легче и возвращает к исходной карточке. На широком экране кнопки не
  сжимаются до служебного размера; на телефоне остаются компактными.
- На телефоне три кнопки остаются в одной строке; поясняющие предложения внутрь
  кнопок не помещаются.

### 7.1. Открытый материал и текст статьи

Открытый материал использует одну текстовую колонку шириной не более `760 px`.
Эта же ширина применяется к заголовку, обычному медиа, тексту дня, материалам,
заданию и следующему дню. Все стоят на одной оси; специальное приложение сохраняет
свою внутреннюю компоновку. На телефоне боковые поля составляют `16 px`.

Служебная строка над материалом собирается в одну группу:

- «ДЕНЬ N» и номер материала — `14 px`, `600`, основной акцент;
- «≈ N минут на изучение» — `14 px`, `400`, строчными и приглушённым цветом;
- расстояние между частями строки — `8 px`, после строки до заголовка — `12 px`.

Главный заголовок и тело материала используют единый
[стандарт статей сайта](../../ARTICLE_STANDARD.md): одну цветную плашку, цитату с
акцентной линией, жирное выделение и синие ссылки. Курс не переопределяет их цвет,
типографику или интервалы.

### 7.2. Компактное оглавление статьи

Состав и условия показа содержания определены в `COURSE_STRUCTURE_CONTRACT.md`;
визуальная система не создаёт отдельной копии этих правил.

На широком экране справа внизу закреплена горизонтальная кнопка
«Содержание». При hover или нажатии она раскрывается вверх, не
создавая постоянную третью колонку. Закреплённое слева оглавление курса остаётся
отдельной навигацией и не заменяется содержанием статьи.

На телефоне кнопка «Содержание» находится справа в верхней строке, с заметной
синей обводкой и закруглением. Окно со ссылками раскрывается непосредственно
под этой строкой.

На ширине до `620 px` все интерфейсные размеры повышаются на одну ступень:
малый служебный текст — `13 px`, вспомогательный — `14 px`, основной — `17 px`,
вводный — `18 px`. Это относится к карточкам материалов, пояснениям, заданиям,
кнопкам и навигации. Заголовок дня и заголовки `h1–h3` внутри открытого материала
сохраняют размеры типографики дня и статьи: мобильное повышение их не затрагивает.

Перед каждой ссылкой стоит компактный маркер. При наведении ссылка получает мягкий
нейтральный фон, а активный раздел — мягкий акцентный фон. После выбора
раздела окно закрывается; оно также закрывается по клику снаружи и клавише
`Escape`. Заголовок окна — «В этом материале», текст ссылок использует стандартный
малый размер интерфейса.

### 7.3. Главный экран ЛК

- Карточки программ образуют ровную сетку: у каждого действия одинаковая ширина и
  минимальная высота, независимо от длины названия и описания.
- Статус — заметная компактная плашка над названием. Допустимые подписи:
  «Доступ открыт», «Доступ закрыт», «Скоро». Последняя используется для любого
  продукта, который ещё разрабатывается; другие формулировки разработки не выводятся.
- Для купленного открытого продукта действие — спокойная синяя кнопка «Открыть». Для купленного, но ещё
  закрытого продукта и для продукта со статусом «Скоро» показывается нейтральное
  неактивное пояснение под карточкой.
- Для доступного к покупке продукта используется заметная оранжевая кнопка
  «Купить». Она не открывает отдельный магазин: запускает единый
  модуль дополнительных предложений в оболочке ЛК.
- Смысл статуса, доступность покупки и специальный порядок карточек при таком
  входе принадлежат серверному контуру доступа и `OFFERS_MODULE.md`; этот раздел
  задаёт только их внешний вид.

Статусы: открыт — зелёный, закрыт — красный, «Скоро» — жёлтый; скругление
компактное. В приложениях недоступные кнопки читаемы и подписаны «Скоро».
Мастер-класс всегда первый; далее готовые курсы/покупаемые предложения, затем
«Скоро». Название мастер-класса жирное, тариф обычным текстом в скобках.
Новой карточки «Продолжить текущий курс» нет.

Задание на сегодня зелёное, чекбоксы оранжевые, выровнены с текстом.
Внизу одна строка статуса: красный крестик «День не пройден» либо белая галочка
«День пройден» и фактический статус следующего дня. Отдельного блока с тем же
статусом нет. Цветовое оформление не ставит галочки и не открывает доступы.

## 7.4. Реализация и источник данных

Согласованный локальный референс — главная ЛК rev 9 и курс rev 38; промежуточные
calm/mist/header=columns и старый коричнево-фиолетовый дизайн архивные, не база
новых правок. Архивные исходники не удалены.

Рабочие точки: `/lk`, `/apps/account.html`, `/apps/masterclass-course.html`.
Центральный CSS: `backend/app/static/account-visual.css` (главная ЛК),
`backend/app/static/course-visual.css` (оболочка курса). Текстовые блоки и шрифты
принадлежат `content/article-components/`, а не Tilda. `embed.js` подключает
общие CSS и в настоящем встроенном кабинете, без копирования стилей в T123.
Изменение CSS требует одного code deploy, не перепубликации всех текстов.

Главный заголовок дня и материала теперь использует одну шкалу
`--course-heading-size: clamp(32px,4vw,44px)`, Manrope 800, line-height 1.12.
Это не изменение названий в оглавлении. Внешний вертикальный интервал медиа
задаётся одним `--course-media-gap: 24px` для видео и изображения; размеры
контейнера видео резервируются до загрузки плеера. Фон под незагруженным медиа
светло-голубой, фон браузерного overscroll — белый.

Общий загрузчик и способ подключения асинхронного приложения описаны в
[стандарте приложений](../../COURSE_APPLICATION_STANDARD.md#общий-загрузчик).
Его не копируют в материал или T123. Основной экран ожидает минимальный доступ и
структуру, прямой текстовый маршрут — запрошенный текст, а не все материалы курса.

Карта MD → публикация → экран и ограничения редактуры:
[редакторский канон](../../../../content/masterclass/editorial/README.md).
Оглавление, заголовок дня и «Далее» берут название из одной активной структуры;
карточки материалов и заголовок открытой статьи — из её же `steps[].title`.
Порядок из `steps[]`, а не имени файла; прогресс связан со стабильными ID/индексами.
Имена или порядок в CSS и preview вручную не поддерживаются.

## 8. Модуль дополнительных продаж

Разговорный визуальный конструктор этого модуля не является самостоятельным
дизайном. Это производный предпросмотр фактического блока курса: он воспроизводит
общую разметку `EdabalansMasterclassOfferView.markup()` и стили
`masterclass.css`. Его нельзя править отдельно. Любое изменение визуальных правил
или runtime-блока включает в ту же задачу обновление конструктора; расхождение
считается дефектом проверки, а не отдельным вариантом дизайна. Постоянная точка
проверки — `/admin/masterclass-offers-preview`; список сценариев она получает из
`course.json`, а карточки — через тот же серверный сборщик, что и курс.

В режиме проверки реального клиента сначала идёт компактная карточка
идентификации, затем **тот же** заголовок «Можно добавить к мастер-классу», та же
вводная строка и та же витрина, что в прямом материале дополнительных предложений
курса. Отдельный заголовок вроде «То, что увидит клиент» не используется.
Рецептурные gate-материалы сохраняют собственный заголовок состояния («Рецепты
пока недоступны»): это не отдельная витрина, а объяснение закрытого раздела с теми
же карточками ниже.

- Экран дополнительных продаж продолжает визуальный язык списка материалов:
  единая спокойная поверхность, компактные горизонтальные карточки и одинаковые
  скругления без отдельного «магазинного» дизайна.
- Вверху остаются только заголовок «Можно добавить к мастер-классу», редактируемое
  короткое пояснение, полный список уже доступных продуктов с галочками и, только
  при наличии `expires_at`, срок текущей цены. Технические пояснения о сервере,
  отдельном экране и автосохранении человеку не показываются.
- Блоки «В вашем тарифе» и «Цена действует до» используют одинаковую геометрию:
  на широком экране две равные колонки, на телефоне — одинаковые полноширинные
  блоки друг под другом. При отсутствии срока остаётся только блок тарифа.
- Используются полные пользовательские названия продуктов и тарифов, а не
  внутренние сокращения вроде «МК» или «Калорийный» без указания типа продукта.
- Одиночное предложение содержит название, короткое описание, при необходимости
  дополнительный абзац, цену и действие. Блока «В составе» и галочек у одиночного
  продукта нет.
- У комплекта после названия и описания сразу раскрывается блок «В составе» со
  входящими продуктами. Дополнительной кнопки и отдельного экрана «Что входит» нет.
- Группа условий показывает зачёркнутую обычную цену, текущую цену, выгоду
  одновременно в процентах и рублях и компактное действие «Купить».
- На широком экране содержание и условия стоят в одной строке. На телефоне
  карточка становится одноколоночной, а цена и компактная кнопка образуют нижнюю
  строку.
- Кнопка «Купить» короткая, средней насыщенности и не занимает всю ширину карточки
  без необходимости.
- У каждого продукта есть компактная ссылка «Подробнее ↗»: в одиночной карточке
  она стоит **под коротким описанием** с отчётливым компактным верхним отступом; в
  комплекте — внутри строки соответствующего продукта с меньшим, но одинаковым
  отступом от его текста. Ссылка использует заметный синий служебный цвет. Она
  открывает полноэкранный экран в оболочке материала, а не отдельный магазинный
  попап. Экран использует заголовок, текст, короткие списки «Что вы получите» и
  «Программа», затем доступные действия покупки; медиа в базовый вариант не входят.
  Срок временной цены внизу экрана показывается короткой приглушённой строкой
  «Цена до …». У каждого действия сначала идёт пояснение «Отдельно» или «В
  составе …» с выгодой, рядом/ниже — короткая кнопка «Купить · цена».
- В экране «Подробнее» заголовки разделов и каждый жирный заголовок пункта списка
  начинаются с прописной буквы. Под ним идёт понятное предложение или короткий
  абзац, а не однословный тезис; списки не становятся отдельным дизайнерским
  форматом.

## 8.1. Встроенные служебные шаги

- Анкета и итоговое ревью продолжают типографику обычного материала: вопросы идут
  прямо по странице и разделяются тонкой линией, без большой карточки вокруг
  каждого поля.
- Поле ответа находится сразу после заголовка и пояснения вопроса. Скругление и
  внутренний отступ меньше, чем у самостоятельной карточки материала.
- Шапка анкеты совпадает с открытым материалом: строка «день · материал · время»
  и затем один главный заголовок. Время остаётся приглушённым, а не акцентным.
- Внизу формы остаётся одно основное действие отправки. Кнопка «Вернуться позже» не
  показывается: черновик сохраняется автоматически, а обычный возврат к материалам
  дня остаётся в шапке.
- Кнопка отправки имеет pointer, hover и видимый клавиатурный фокус. Следующий
  материал показывается сразу; снимок ответов, отправка и серверная отметка
  прохождения выполняются в фоне последовательно. Ошибка показывается участнику.
- Анкета, итоговое ревью, привязка мессенджера, рецептурные приложения и экран
  дополнительных продаж открываются внутри обычной оболочки материала: фон курса,
  оглавление, контентная колонка, навигация и общий футер сохраняются. Мессенджер
  содержит несколько понятных абзацев и отдельные действия Telegram/MAX, а не
  модальное окно поверх дня.
- DQS остаётся самостоятельным специализированным приложением и не приводится к
  этой облегчённой форме.

## 9. Подсветка и движение

- Пропущенный материал или пункт чек-листа получает краткую заметную подсветку;
  подсвечивается конкретная цель, а не весь день целиком.
- После первого перехода дня в состояние «День пройден» один раз показывается
  короткая анимация галочки.
- При `prefers-reduced-motion: reduce` анимация отключается, а автоматическая
  прокрутка выполняется без плавного движения. Состояния и подсветка остаются
  понятными без анимации.

## 10. Юридический футер

Общая оболочка отделяет футер тонкой линией и использует малый приглушённый текст.
Текст и ссылки принадлежат [глобальному юридическому компоненту](../../ACCOUNT_LEGAL_GATE.md),
а не этой визуальной системе. Runtime-владелец — режим `private` в
`backend/app/static/site-footer.js`; `embed.js` только монтирует его в оболочку.
Локальная разметка курса не создаёт отдельный вариант подвала. Один и тот же подвал
завершает главный экран ЛК, страницу дня и отдельный материал любого курса.

На широком экране подвал использует две сбалансированные колонки: имя и права
слева, контакты и юридические ссылки справа. На узком экране колонки складываются
друг под другом и центрируются. Состав и порядок ссылок от изменения ширины не
меняются.

## 10.1. Светлая и тёмная тема ЛК

Это две поверхности одной страницы, а не отдельный сайт или копия материалов.
Светлая тема сохраняет утверждённые цвета. Тёмная меняет фон, текст, карточки,
оглавление, текстовые плашки, таблицы, навигацию и загрузчик; фотографии и видео
не инвертируются. Цвета состояния и золотой акцент сохраняют своё назначение.

| Роль в тёмной теме | Значение |
|---|---|
| Фон | `#171A20` |
| Карточка | `#222831` |
| Обводка | `#3D5366` |
| Основной / приглушённый текст | `#EDF1F5` / `#BDC7D1` |
| Спокойный синий акцент | `#69C9FF` |
| Оглавление | тёмный градиент на основе `#202329` |
| Текстовая плашка NOTE | `#51472B`, текст `#FFF3CA` |
| Задание | зелёный градиент `#236442` → `#185134` |

На ПК переключатель 44 × 44 px закреплён справа, на уровне кнопки
«К материалам дня». Для него оставлен отдельный правый отступ: при прокрутке
он не перекрывает контент. На телефоне размещение определено в § 6.

Выбор сохраняется локально под ключом `edabalans-account-theme-v1`.
Без сохранённого выбора используется светлая тема. Тема применяется в
собственном `/lk` до первого экрана загрузки, а не после раскрытия материалов.
Загрузка HTML другого экрана и смена ширины не создают второй переключатель.
Общая реализация — `backend/app/static/account-theme.js` и `account-theme.css`;
редактору Markdown не нужно менять материалы или перепубликовывать их для
смены темы.

## 11. Как менять визуальную систему

Вступление страницы дня отображается одним текстовым блоком под медиа. Поля
`lead` и `intro` не разделяются видео: между абзацами один интервал 18 px,
пустые строки разметки не создают дополнительные визуальные разрывы. У блока
отступы 24 px сверху и 32 px снизу; встроенное пояснение задания отделяется
24 px. Эти правила не меняют текст и оформление тела отдельной статьи.

Визуальное изменение допустимо без пересмотра структурного контракта, если оно:

- не добавляет новый смысловой блок;
- не создаёт новый редакторский текст или поле;
- не меняет порядок прохождения;
- не скрывает обязательную информацию;
- не подменяет состояние курса локальной декоративной логикой.

Если для дизайнерского решения требуется новое содержание или поведение, сначала
отдельно решается изменение структурного контракта.
