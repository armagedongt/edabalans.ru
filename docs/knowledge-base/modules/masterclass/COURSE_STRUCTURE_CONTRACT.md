# Структурный контракт единого курса

Статус: `current`  
Владелец решения: Сергей Воронцов  
Зафиксировано: 24.08.2026  
Назначение: стабильные правила данных, содержания и построения экранов всех курсов.

## 1. Граница документа

Этот документ определяет:

- какие данные хранятся у курса, дня и материала;
- какой текст является источником, а какой представлением этого источника;
- что вычисляется автоматически;
- в каком смысловом порядке строятся оглавление, день и материал;
- как отображаются доступность, завершение и переходы;
- как рассчитывается примерное время изучения.

Документ не определяет цвета, гарнитуру, размеры, отступы, форму карточек и вид
иконок. Эти решения принадлежат
[визуальной системе](COURSE_VISUAL_SYSTEM.md).

## 2. Единственный источник данных

Для текущего Мастер-класса runtime-источником является активная ревизия документа
`course-structure/masterclass-21` в `managed_document_versions`. Файл
`content/masterclass/course/course.json` используется только как исходный seed,
если в PostgreSQL ещё нет ни одной ревизии. Редактор изменяет исходное поле один
раз, а все представления получают новое значение автоматически без restart.

Не создавать отдельные копии одного текста специально для шапки, оглавления,
карточки следующего дня или страницы материала. Дополнительное поле вводится только
когда это действительно другой редакционный текст с отдельным назначением.

Многострочные редакторские поля и пункты задания хранят обычные переводы строк.
Нажатие Enter отображается в клиентском курсе как перенос строки без необходимости
вводить `<br>` или другой HTML-код.

## 3. Уровень курса

Обязательные атрибуты курса:

| Атрибут | Назначение | Где используется |
|---|---|---|
| стабильный код | Связь курса с доступами, прогрессом и API | backend и редактор |
| полное название | Человеческое название продукта | оглавление и общая оболочка курса |
| версия содержания | Определяет актуальную редакцию манифеста | загрузка и аудит |
| упорядоченный список дней | Единственный порядок программы | оглавление и навигация |

Ссылка «Личный кабинет» и единый юридический футер принадлежат общей оболочке
личного кабинета, а не данным отдельного курса. Текущий production-владелец текста
футера — `legalFooterHtml()` в `backend/app/static/embed.js`; его изменение должно
применяться ко всем встроенным курсам сразу. Канонический состав подвала описан в
[`ACCOUNT_LEGAL_GATE.md`](../../ACCOUNT_LEGAL_GATE.md). Самостоятельный
HTML-предпросмотр повторяет глобальный состав для визуальной проверки и скрывает
свою копию при загрузке через общую оболочку.

## 4. Уровень дня

Обязательные или предусмотренные контрактом атрибуты дня:

| Атрибут | Назначение |
|---|---|
| стабильный ID или slug | Связь дня с прогрессом и событиями |
| номер | Порядок дня в курсе |
| название | Единый заголовок страницы дня, оглавления и следующего дня |
| описание в оглавлении | Необязательное краткое содержание дня в оглавлении |
| текст над медиа | Необязательный авторский текст под заголовком дня |
| основное медиа | Видео или другое главное медиа дня |
| текст под медиа | Необязательный авторский текст после медиа |
| упорядоченный список материалов | Единственный порядок карточек и прохождения |
| текст после материалов | Необязательный текст перед заголовком после материалов |
| заголовок после материалов | Необязательный заголовок перед заключительным текстом |
| текст после заголовка | Необязательный авторский текст перед заданием |
| пункты задания | Сохраняемые пункты чек-листа |

Пустое необязательное поле не создаёт место в странице: соответствующий блок не
показывается вовсе. Заголовок «Задание на сегодня» фиксирован и не редактируется.

## 5. Уровень материала

Базовые атрибуты любого материала:

| Атрибут | Назначение |
|---|---|
| стабильный ID | Прогресс, события и безопасное редактирование |
| тип | Статья, анкета, приложение, мессенджер, предложение или другой поддержанный тип |
| название | Заголовок карточки, оглавления и страницы материала |
| краткое описание | Одна строка о содержании материала |
| условие завершения | Прочитано, отправлено, сохранено, открыто или другое явное событие |
| скрыт | Исключает материал из показа и обязательности без удаления позиции и прогресса |

У импортированной статьи отдельно сохраняется защищённый технический заголовок
исходной страницы. Редактор его не показывает и не меняет: поэтому авторское
переименование карточки не разрывает связь с уже загруженным телом статьи.

Поля конкретного типа добавляются только при необходимости. Например, анкете нужен
код приложения, статье — источник текста, предложению — серверный placement. Эти
поля не превращаются в обязательные пустые колонки для остальных материалов.

Краткое описание при создании материала первоначально генерируется на основании
его фактического содержания и сохраняется в отдельном поле `summary`. После этого
оно является обычным редакторским текстом: ручная правка имеет приоритет и не
затирается автоматической повторной генерацией. Обновить описание после изменения
материала можно только отдельным явным действием редактора или автора.

Первая версия редактора не добавляет, не удаляет и не переставляет материалы. Эти
изменения выполняются отдельной задачей через чат с проверкой влияния на прогресс и
события. Скрытие сохраняет исходную позицию, поэтому соседние `step_index` не
сдвигаются.

## 6. Производные представления

Следующие значения не набираются вручную:

| Представление | Как формируется |
|---|---|
| Заголовок дня в оглавлении | Из названия дня |
| Заголовок страницы дня | Из названия дня |
| Заголовок в блоке следующего дня | Из названия следующего дня |
| Краткий состав дня | Из описания в оглавлении; при отсутствии — из названий подходящих материалов |
| Видимый номер карточки | Из текущей позиции материала в списке, начиная с 01 |
| Суммарное время дня | Сумма времени медиа и всех материалов дня |
| Количество материалов | Из фактического списка материалов |
| Предыдущий и следующий день | Из позиции дня в программе |

В краткий состав дня входят содержательные материалы, анкеты и итоговые формы. Не
входят служебная привязка мессенджера и предложение других продуктов. Это влияет
только на краткую строку: сами шаги остаются в программе и учитываются во времени.

## 7. Структура оглавления

Оглавление строится из программы автоматически. Порядок элементов:

1. ссылка «Личный кабинет»;
2. полное название курса;
3. заголовок программы;
4. дни по порядку.

Для каждого дня выводятся номер, единое название, краткий состав и смысловое
состояние: текущий, завершённый, доступный или закрытый. Конкретный цвет и значок
состояния определяет визуальная система.

Оглавление различает четыре пользовательских состояния: открытый сейчас материал,
открытый, но ещё не завершённый день, пройденный день и закрытый день. Текущий
материал определяется из фактически открытого шага, а не из декоративной метки.

## 8. Структура страницы дня

Части дня всегда следуют в таком смысловом порядке:

1. строка «День N · ≈ X минут на изучение»;
2. единое название дня;
3. текст над медиа, если он задан;
4. основное видео или другое медиа;
5. при необходимости — содержание или таймкоды медиа;
6. текст под медиа, если он задан;
7. заголовок раздела материалов;
8. карточки материалов в порядке прохождения;
9. при наличии — отдельный раздел настоящих дополнительных материалов;
10. текст после материалов, заголовок после материалов и текст после заголовка —
    только если каждое соответствующее поле задано;
11. чек-лист «Задание на сегодня»;
12. блок следующего дня;
13. навигация и единый юридический футер оболочки.

Карточка предложения других продуктов является обычным номерным материалом. Над
ней не добавляются заголовок «Дополнительный материал», объяснение необязательности
или внешний рекламный текст. Отдельный раздел дополнительных материалов создаётся
только для реальных ссылок, постов и дополнений к теме дня.

## 9. Структура карточки и страницы материала

Карточка содержит в постоянном порядке:

1. вычисляемый порядковый номер;
2. полное название;
3. краткое описание;
4. примерное время;
5. смысловое состояние или действие.

Время показывается сразу, в том числе у закрытого материала. Закрытость не заменяет
время текстом «закрыто»: она передаётся отдельным состоянием и визуальным маркером.

Страница открытого материала использует следующий постоянный порядок:

1. единая служебная строка с днём, номером материала и общим примерным временем;
2. одно название материала как главный заголовок;
3. сразу содержание статьи или основное медиа;
4. переходы между материалами, кнопка оглавления и общий юридический футер.

Краткое описание `summary` остаётся атрибутом карточки и других производных
представлений, но повторно под главным заголовком открытого материала не выводится.
Общее время материала включает видео и текст. Оно показывается одной величиной с
единой формулировкой «≈ N минут на изучение»: отдельные строки «на чтение», «на
просмотр» и «на выполнение» не создаются.

### 9.1. Структура текста статьи

- Заголовки и подзаголовки берутся из авторского текста: из явно заданной
  структуры либо из фразы, уже выражающей смысл раздела. Система не придумывает
  новые заголовки только ради оформления или оглавления. Авторская жирная фраза
  может быть оформлена как подзаголовок без изменения её смысла.
- Один абзац раскрывает одну мысль. Искусственные переносы каждой фразы на новую
  строку и сплошные полотна текста не используются.
- Маркированный список применяется для равноправных пунктов, нумерованный — только
  когда важен порядок действий или этапов. Каждый пункт начинается с прописной
  буквы. Внутри одного списка сохраняется единая грамматика и пунктуация: полные
  предложения заканчиваются точкой, короткие однородные формулировки оформляются
  одинаково.
- Вложенные списки по умолчанию не создаются. Если материалу действительно нужна
  иерархия, сначала используется подзаголовок, затем отдельный список.
- Выделение жирным подчёркивает ключевую фразу внутри текста, но не заменяет
  структуру каждого абзаца и не получает самостоятельный цвет.
- Разрешённые повторяемые смысловые блоки: «Важно», «Что сделать», «Пример», «Так
  не надо», «Что это значит» и отдельная ключевая мысль. Их количество заранее не
  ограничивается: повторяющийся формат может требовать нескольких одинаковых
  блоков. Одинаковый смысл всегда получает один и тот же тип блока.
- Изображение вставляется по заданной ссылке без обязательной отдельной подписи.
  Спойлеры и сворачиваемые части статьи не используются.
- Таблицы, формулы, сравнение «до/после», галереи, нестандартные схемы и другие
  разовые элементы не вставляются автоматически. Их можно предложить для
  конкретного места, но применить только после явного решения владельца.

### 9.2. Оглавление открытого материала

Оглавление статьи — производное представление, а не отдельное редакторское поле.
Оно автоматически строится только из фактических подзаголовков второго уровня и
не создаёт или не переписывает их. Подзаголовки третьего уровня остаются внутри
текста и в компактное оглавление не входят.

Оглавление показывается, если в материале есть не менее трёх подзаголовков второго
уровня. В нём сохраняются порядок и текст статьи, а ссылки ведут к стабильным
якорям соответствующих разделов. На широком экране текущий раздел определяется по
положению страницы и отмечается визуально. На телефоне выбор раздела прокручивает
к нему страницу и закрывает раскрытый список. Если подзаголовков недостаточно,
оглавление не показывается и новые заголовки ради него не генерируются.

Анкета и итоговое ревью являются последовательностями вопросов на поверхности
обычного материала: у каждого вопроса есть номер, заголовок, пояснение и поле
ответа. Служебный текст об автосохранении относится ко всей форме и не повторяется
после каждого поля. Привязка мессенджера, рецептурные мини-приложения и предложение
дополнительных продуктов также используют обычную оболочку материала курса и не
открываются модальным окном поверх дня. Их собственное содержание подставляется
вместо текста статьи. DQS сохраняет отдельную полноэкранную оболочку как
специализированное приложение.

Анкета, итоговое ревью и привязка мессенджера являются типами обычного материала,
а не самостоятельными приложениями курса. Они находятся в том же упорядоченном
списке `steps`, получают обычный номер и подчиняются общей навигации. Отдельным
переиспользуемым приложением остаётся модуль дополнительных продаж: его ассортимент,
цены и сценарии одинаковы для всех курсов. DQS остаётся специализированным
приложением со своим контрактом.

Кнопка «Далее» всегда открывает следующую позицию единого списка `steps`, независимо
от типа текущего материала. Нижняя кнопка «Предыдущий» открывает предыдущую позицию. У последнего
материала действие называется «К заданиям» и возвращает на страницу дня к авторскому
тексту над чек-листом. Явный верхний возврат «← К материалам дня» возвращает к карточке, из которой
материал был открыт; это удобство не является вторым источником маршрута и не меняет
порядок прохождения.

Материал привязки мессенджера считается завершённым только после фактического
`messenger_accounts.linked_at`, а не после генерации или открытия deep link. До
подтверждения кнопка «Продолжить» заблокирована. После ответа бота страница
автоматически проверяет серверное состояние и открывает продолжение. Если у
участника нет поддержанного мессенджера, он переходит по зашитой в слова ссылке в
личные сообщения Сергею; автоматического обхода обязательного шага нет.

## 10. Задание дня

Сам чек-лист всегда виден после материалов и не сворачивается в спойлер. До завершения обязательных
материалов он заблокирован, но его название и пункты остаются видимыми.

Над пунктами находится единая инструкция: «Чтобы завершить день, поставьте галочки
после выполнения этих пунктов.» Внутри чек-листа размещаются только 1–4 коротких
действия. Длинное объяснение задания хранится отдельным текстом выше или отдельным
материалом.

После завершения последнего обязательного материала пользователь возвращается на
страницу дня, а экран переводится к чек-листу. Сам факт появления чек-листа не
ставит галочки автоматически. Каждая галочка сохраняет только своё состояние, не
перезагружает страницу и не переносит пользователя наверх.

Если участник пытается продолжить с пропуском, интерфейс указывает первый конкретный
незавершённый материал или пункт чек-листа. После всех галочек показываются
состояние «День пройден» и рассчитанная сервером фраза: «Следующий день откроется
25 августа в 06:00 по вашему времени.» с фактической датой для участника.

## 11. Следующий день и навигация

После задания показываются:

1. заголовок раздела «Далее в программе»;
2. строка «День N · Название следующего дня» внутри карточки;
3. его автоматически собранный краткий состав;
4. автоматически рассчитанное «≈ N минут» следующего дня;
5. серверное состояние и точная дата открытия;
6. одна контекстная кнопка.

Если день ещё закрыт, кнопка сообщает об этом. Когда условия выполнены, она
становится «Открыть день N». Если день уже был открыт, показываются «День уже
открыт» и «Перейти к дню N» без повторного открытия на сервере.

Отдельная дублирующая кнопка «Следующий день» в нижней навигации не нужна. На
первом дне внизу остаётся «Оглавление». Начиная со второго дня доступны «Прошлый
день» и «Оглавление»; переход вперёд выполняется через блок следующего дня.

## 12. Методика оценки времени

1. Видео — фактическая длительность, округлённая вверх до целой минуты.
2. Текст без ручной оценки — количество слов, делённое на 180 слов в минуту и
   округлённое вверх; минимум 2 минуты.
3. Анкета или приложение — ожидаемое время обычного заполнения по количеству полей
   и действий; редактор задаёт его явно.
4. Короткое действие, переход или обзор предложения — 2 минуты, если фактическая
   проверка не показывает другое.
5. Явное `durationMinutes` имеет приоритет и доступно для редакторской правки.
6. Время дня — сумма медиа и всех материалов, включая анкеты, мессенджер,
   приложения и предложения.

Сервер рассчитывает открытие следующего дня по часовому поясу участника. Если день
завершён до 00:00 по местному времени, следующий открывается в ближайшие 06:00.
Если завершение произошло после 00:00, открытие назначается на 06:00 следующих
календарных суток. Перезагрузка страницы не меняет рассчитанное время. Ускоренный
тестовый профиль изменяет только интервал владельца и не меняет общий контракт.

Текст «≈ X минут на изучение» является частью структурного контракта. Его цвет,
размер и расположение внутри строки относятся к визуальной системе.

## 13. Адреса дней и материалов

- Каждый открытый день и каждый открытый учебный материал имеют собственное
  состояние адреса страницы.
- Адрес материала использует постоянный идентификатор шага из манифеста, а не его
  изменяемую позицию в списке.
- Обновление страницы восстанавливает тот же день или материал, если он по-прежнему
  доступен участнику.
- Кнопки браузера «Назад» и «Вперёд» перемещают между ранее открытыми днями и
  материалами без сброса на главный экран личного кабинета.
- Прямая ссылка на закрытый день или материал не обходит порядок прохождения:
  интерфейс возвращает участника к последнему доступному дню.

## 14. Что пока не фиксируется

До утверждения первого дня не вводить обязательную универсальную схему БД или
редакторских колонок для всех курсов и не переписывать остальные дни механически.
Количество материалов и решение об их объединении относятся к содержанию
конкретного курса, а не к этому контракту.

## 15. Первый день текущего Мастер-класса

- Программа курса объясняется во вступительном видео и не дублируется отдельной
  статьёй.
- Первый обязательный пункт — визуальный адаптивный туториал интерфейса, а не
  текстовый материал.
- Авторские изображения остаются внутри статьи на исходных смысловых местах.
  Слайдер является явной настройкой конкретного материала и сейчас используется
  только в справочнике DQS.
- Анкета и привязка мессенджера остаются отдельными обязательными последовательными
  материалами общего списка. Тексты задания и его обязательные галочки этим
  решением не меняются.

## 16. Единый источник карточек дополнительных продаж

Продукт хранит пользовательское название, короткое маркетинговое описание и
необязательное расширенное описание в одном каталоге. Карточка конкретной точки
продажи хранит только ссылку на продукт, цену/ступень и правило состава; она не
копирует название и описание продукта.

- Одиночное предложение показывает название продукта, короткое описание,
  необязательное расширенное описание, цену, выгоду и кнопку. Блока «В составе» и
  списка с галочками у него нет.
- Комплект показывает собственное название и описание, затем блок «В составе».
  Каждая строка состава получает название и описание входящего продукта из того же
  каталога.
- Список «В вашем тарифе» также приходит от сервера готовыми пользовательскими
  названиями. Клиентский JavaScript не поддерживает параллельный словарь названий.
- В первый день `expires_at` отсутствует: интерфейс показывает только цены. Таймер
  появляется лишь после отдельного серверного триггера соответствующей ступени.
