# Реестр модулей Telegram

Статус: `current`
Проверено: 25.08.2026
Назначение: объяснить границу Telegram-реестра без второй ручной копии перечня.

## Где находится перечень

Единый верхнеуровневый список module id, parent и связей находится в
`../../../modules.toml`. Человекочитаемые названия, назначение, функции и статусы
находятся в карточках `../catalog/messaging.telegram*.md`. Автоматическая проекция
доступна в `../../../generated/module-map.md`.

Этот файл больше не перечисляет те же модули вручную. Новый Telegram-модуль одним
изменением добавляется в общий registry, получает карточку и ownership; отдельную
строку здесь добавлять нельзя.

## Что остаётся runtime-источником

Исполняемые sequence versions, steps и edges в PostgreSQL определяют фактический
порядок сообщений. `telegram-bot/service/app/graph.py` визуализирует runtime graph,
но не владеет отдельным продуктовым перечнем. Seed создаёт начальные runtime-данные,
а не документационный канон.

Уровни не нужно смешивать:

- общий registry отвечает «какие функциональные модули существуют и как связаны»;
- карточка отвечает «зачем модуль нужен и что умеет»;
- канонический документ модуля описывает входы, ветки, выходы и продуктовый смысл;
- runtime graph отвечает «что именно исполняет развёрнутая ревизия»;
- generated map и админка только показывают эти источники.

## Что не становится отдельным модулем

Ссылка, UTM, tag, отдельный Telegram API method, таблица, media helper, delay и
scheduler являются компонентами подходящего модуля. Новый module id нужен только
для процесса с самостоятельной целью, входами/выходами и жизненным циклом.

Обязательный порядок проектирования и проверки находится в
`MODULE_DEVELOPMENT_STANDARD.md`.
