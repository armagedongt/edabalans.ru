# Домены, Caddy и сеть

Завершает HTTPS и направляет публичные пути к разрешённым внутренним сервисам.

## Функции

Перенос завершён 18.10.2026. `SITE_DOMAIN` задаёт основной hostname Caddy, его `www` и
`admin` напрямую, параллельно с совместимыми старыми host. Корень `admin`
внутренне открывает существующий `/admin`; отзывы — `/media/reviews/*`.

- публиковать новые страницы и приложения только путями `похудение-это-есть.рф`,
  административные интерфейсы — на `admin.похудение-это-есть.рф`;
- сохранять совместимые старые app/api-входы до отдельного решения; старый
  blog-host отвечает 410. Фактические остатки, включая go-переходы, медиа и
  preview другого проекта — [доменный runbook](../../../DOMAIN_CUTOVER_RUNBOOK.md);
- не публиковать PostgreSQL и внутренние порты напрямую;
- не публиковать NocoDB в интернет; доступ оставлять только через loopback и SSH-туннель;
- раздавать разрешённые публичные медиа владельца из отдельных read-only
  каталогов VM, не помещая клиентские изображения в Git;
- публиковать readiness-маршруты Telegram и MAX для внешнего мониторинга;
- передавать Telegram Bot API через отдельный закрытый Cloudflare relay, не
  зависящий от нестабильного маршрута между российской и европейской VM;
- хранить готовый аварийный runbook возврата на выключенную европейскую Squid VM
  в [`infra/telegram-proxy/README.md`](../../../../infra/telegram-proxy/README.md),
  включая согласованное переключение внешнего watchdog;
- принимать канонический публичный вход интенсива `/intensive` на едином origin
  без промежуточного HTTP-редиректа и с сохранением query-атрибуции;
- отдавать изолированный `noindex,nofollow` preview Щербаковой только на точном пути
  `app.edabalans.ru/sherbakova/*`, не передавая этот путь backend или другим сервисам;
- отдавать единые корневые favicon-пути на действующем сайте и совместимых
  API/app/go-входах; выведенный blog-host отвечает 410 на всех путях;
- сохранять старый вход бота `app.edabalans.ru/docs` (с завершающим `/` и без него)
  относительным переходом на `/legal`, сохраняя host и query-параметры;

Публичный блог и профиль автора открываются путями основного сайта. Старые
blog-host handlers для favicon и `/author/*` выведены вместе с отдельным блогом;
они не являются текущей конфигурацией Caddy.

Для временной проверки Robokassa go-домен имеет явные страницы и старты
`/robokassa-test` и `/robokassa-live-probe`, ResultUrl2, точные страницы возврата
и `GET` статуса с числовым `InvId`. Первый маршрут проверяет тестовую операцию,
второй — изолированную реальную оплату 10 ₽ под отдельным runtime-флагом. Совместимый
`/api/*` также проксируется в backend; go не является отдельной изоляцией общего
checkout. Его проверки и включение остаются на backend. Deploy проверяет тестовую страницу на
публичном go-домене; после эксперимента вся эта временная граница удаляется одним
выпуском.

## Граница

Совместимое зеркало из `PUBLIC_DOMAIN` и его `www` исключены из индексации
HTTP-заголовком `X-Robots-Tag: noindex` на уровне Caddy. Это не блокировка
пользователей, API или выдачи страниц. Основной `SITE_DOMAIN` не получает этот
заголовок от правила зеркала. Роботу оставлен доступ для чтения `noindex`;
глобальный `Disallow: /` для зеркала не добавляется. При смене основного домена
следовать матрице настроек в доменном runbook, чтобы новый основной адрес не
остался в роли `PUBLIC_DOMAIN`.

Не владеет авторизацией приложений или содержанием страниц.
Исходящий DNS и правила мониторинга/восстановления принадлежат `operations.health`:
[единый README](../../../runtime-health/README.md).

## Источники истины

Caddyfile, compose/network config и `docs/OPERATIONS.md`. Повторяемый порядок
смены единого публичного origin хранится в `docs/DOMAIN_CUTOVER_RUNBOOK.md`.

Технические файлы, routes, таблицы, migrations и программные символы не
перечисляются вручную в карточке: они подставляются из generated inventory.
