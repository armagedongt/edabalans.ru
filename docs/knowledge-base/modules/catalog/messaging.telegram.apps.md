# Приложения в Telegram

Разделяет право на приложение и момент его показа. Покупка сразу создаёт
`user_accesses`, но кнопка в «Моих приложениях» появляется только после
соответствующего материала Мастер-класса.

## Функции

- принимать короткие общие `/start` payload: `apps`, `dqs`, `training`,
  `metabolism`, `recipes`;
- связывать новый контакт текущего бота с уже известным Telegram ID без создания
  второго пользователя;
- перед показом каждой кнопки проверять одновременно действующий доступ к
  ресурсу и событие `app_revealed_*`;
- открывать тот же нативный экран как Telegram Mini App; сервер повторно проверяет
  подписанный Telegram `initData` и право на приложение;
- при прямом вызове ещё не показанного приобретённого приложения объяснять, что
  оно появится после соответствующего материала, не отнимая само право;
- использовать тот же отфильтрованный список для MAX;
- по кнопке «Обновить» пересчитывать права и редактировать исходное сообщение, а
  не присылать новое;
- работать во время общего режима ремонта бота, не запуская welcome или другую
  маркетинговую цепочку.

## Граница

Модуль не выдаёт права и не определяет состав продукта. Он читает активные
`user_accesses` и доменные события Мастер-класса. Прямая web-страница остаётся
ручным резервным входом и проверяет право, но не управляет видимостью кнопки в
боте. Массовая рассылка ссылок людям остаётся отдельной операцией и без явного
запуска владельца не выполняется.

## Источники истины

`user_accesses`, `resources`, `masterclass_events`, `messenger_accounts`,
Telegram/MAX runtime и продуктовые маршруты `/dqs`, `/training`, `/metabolism`,
`/recipes`.
