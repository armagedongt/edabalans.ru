# Авторизация приложений и админок

Проверяет вход администратора и собственную серверную сессию клиента в один кабинет.

## Функции

- создавать общую 30-дневную admin session для поддоменов edabalans.ru через
  основной вход и вход Telegram-админки; на независимых доменах сохранять
  host-only область cookie без распространения на Tilda;
- проверять email и хеш пароля для новых покупателей; для паролей, созданных после
  включения админского просмотра, рядом с хешем хранить зашифрованную копию,
  доступную только из карточки клиента с обязательной записью просмотра в журнал;
  session token по-прежнему хранить только как хеш;
- принимать простую самостоятельную регистрацию по email: она создаёт только
  пустой серверный кабинет и запускает тот же одноразовый путь
  email → Telegram/MAX → пароль, но не создаёт оплату или продуктовое право;
- помнить вход на одном устройстве 30 дней и отзывать конкретную сессию при выходе;
- после повторной покупки не перевыпускать пароль: в мессенджере показывать дату
  его первоначальной выдачи и ссылку на личный кабинет;
- открывать через оба адаптера один `user_id`, один набор продуктовых прав и одну
  версию материалов;

## Граница

NocoDB имеет отдельный вход. Восстановление и смена пароля выполняются вручную
Сергеем из CRM. Смена завершает активные клиентские сессии. Старые пароли,
созданные до зашифрованной копии, не восстанавливаются: в карточке для них один
раз задаётся новый пароль. Автоматическую почтовую процедуру этот этап не добавляет.

Для самостоятельной регистрации email не становится паролем и не открывает
материалы. До получения одноразовой ссылки из письма и её открытия в выбранном
мессенджере у человека нет учётных данных; после этого он получает обычный
логин-пароль и видит только доступные ему продукты.

Все клиентские приложения определяют пользователя только по защищённой серверной
сессии. Email из query-параметра, формы или localStorage не является основанием
для чтения данных и выдачи доступа.

## Источники истины

`backend/app/auth.py`, `backend/app/app_auth.py`,
`backend/app/account_auth_routes.py`, `backend/app/account_security.py`,
`docs/ADMIN_ARCHITECTURE.md` и правило переходного входа в `AGENTS.md`.

Технические файлы, routes, таблицы, migrations и программные символы не
перечисляются вручную в карточке: они подставляются из generated inventory.
