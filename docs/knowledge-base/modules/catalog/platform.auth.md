# Авторизация приложений и админок

Проверяет вход администратора и два переходных входа клиента в один кабинет:
старый профиль Tilda и собственную серверную сессию.

## Функции

- создавать общую admin session для поддоменов edabalans.ru;
- проверять Tilda-профиль и продуктовый доступ без второго клиентского логина;
- при отсутствии профиля отправлять клиента на штатный вход Tilda без ручного
  ввода email внутри приложения;
- после штатного входа возвращать клиента только на сохранённый внутренний путь,
  с которого потребовалась авторизация;
- читать существующий Tilda-профиль и на публичной странице приложения, чтобы
  возврат по прямой ссылке не создавал цикл через личный кабинет;
- завершать клиентскую сессию штатным механизмом Tilda из главного экрана ЛК;
- проверять email и хеш пароля для новых покупателей, хранить только хеш пароля
  и хеш непрозрачного session token;
- помнить вход на одном устройстве 30 дней и отзывать конкретную сессию при выходе;
- открывать через оба адаптера один `user_id`, один набор продуктовых прав и одну
  версию материалов;

## Граница

NocoDB имеет отдельный вход. Восстановление и смена пароля пока выполняются
вручную Сергеем; автоматическую почтовую процедуру этот этап не добавляет.

Новый вход на `go.*` привязывает любой переданный в API email к пользователю
серверной сессии и отклоняет попытку запросить чужой кабинет. Старые маршруты
`app.edabalans.ru`, которые Tilda открывает с email своего клиентского профиля,
временно остаются совместимым legacy-адаптером. Они не считаются новой границей
безопасности и должны быть закрыты для прямого клиентского использования после
перевода прежних пользователей с Tilda.

## Источники истины

`backend/app/auth.py`, `backend/app/app_auth.py`,
`backend/app/account_auth_routes.py`, `backend/app/account_security.py`,
`docs/ADMIN_ARCHITECTURE.md` и правило переходного входа в `AGENTS.md`.

Технические файлы, routes, таблицы, migrations и программные символы не
перечисляются вручную в карточке: они подставляются из generated inventory.
