# MAX: сообщения, старт и атрибуция

MAX подключён как второй канал общей системы сообщений. Первый вход сохраняет
пользователя и источник, затем запускает тот же опубликованный Welcome-граф,
который используется в Telegram: четыре части интенсива, проверки открытий,
напоминания, промежуточные материалы, медиа и персональные ссылки. Telegram-
проверка подписки в MAX не выполняется, финальный пост в личном MAX-диалоге не
закрепляется. Start payload типа `account_credentials` вместо интенсива связывает
MAX с уже оплаченным `user_id` и выдаёт логин и пароль к единому личному кабинету.
Короткие payload `iz1`, `iz2` и `iz3` выдают утверждённые копии заданий первых трёх
частей непосредственно в MAX, без промежуточной web-страницы. Повтор одного webhook
не отправляет сообщение второй раз. Если MAX принял сообщение, но ответ потерялся,
состояние помечается как неопределённое; новый явный переход пользователя по кнопке
создаёт новую попытку. Общие массовые и послепокупочные рассылки пока остаются
Telegram-only и не выбирают MAX-контакты.

Подробный канонический контракт: `docs/knowledge-base/modules/max/START_AND_ATTRIBUTION.md`.
