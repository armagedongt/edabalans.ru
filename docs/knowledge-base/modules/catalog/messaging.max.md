# MAX: сообщения, старт и атрибуция

MAX подключён как второй канал общей системы сообщений. Первый вход сохраняет
пользователя и источник, затем запускает тот же опубликованный Welcome-граф,
который используется в Telegram: четыре части интенсива, проверки открытий,
напоминания, промежуточные материалы, медиа и персональные ссылки. Telegram-
проверка подписки в MAX не выполняется, финальный пост в личном MAX-диалоге не
закрепляется. Start payload типа `account_credentials` вместо интенсива связывает
MAX с уже оплаченным `user_id` и выдаёт логин и пароль к единому личному кабинету.
Короткие payload `iz1`, `iz2` и `iz3` выдают утверждённые копии заданий первых трёх
частей непосредственно в MAX, без промежуточной web-страницы. Повтор одного webhook
не отправляет сообщение второй раз. Если MAX принял сообщение, но ответ потерялся,
состояние помечается как неопределённое; новый явный переход пользователя по кнопке
создаёт новую попытку. Общие массовые и послепокупочные рассылки пока остаются
Telegram-only и не выбирают MAX-контакты.

Короткие payload `apps`, `dqs`, `training`, `metabolism`, `recipes` открывают в
MAX тот же каталог приобретённых и уже показанных в Мастер-классе приложений.
Кнопка типа `open_app` передаёт payload в одну MAX Mini App; backend проверяет
подписанный MAX `initData`, связанную MAX-идентичность и действующее продуктовое
право, после чего создаёт обычную серверную сессию. Право без события показа не
выводит кнопку раньше нужного материала курса.

Callback-кнопки поддерживают переходы общего sequence-движка и отдельные личные
диагностические цепочки. В одноразовой цепочке активна только кнопка последнего
сообщения: при первом нажатии строка состояния блокируется в PostgreSQL, клавиатура
исходного сообщения удаляется и следующее сообщение отправляется один раз.
Повторный callback не продолжает цепочку, даже если клиент MAX ещё показывает
старую кнопку. Диагностическая цепочка запускается только операторской CLI для
одного уже существующего MAX-контакта и не меняет его Welcome-run.
Production webhook обязан быть подписан как минимум на `bot_started`,
`bot_stopped`, `dialog_removed`, `message_created` и `message_callback`.

Рекламная посадка выдаёт MAX отдельные одноразовые journey для кнопки и QR.
Фактический старт переносит `journey_id` и способ входа в общий tracking event,
поэтому потери после кнопки или сканирования считаются так же, как для Telegram.
