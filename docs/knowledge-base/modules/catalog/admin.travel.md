# Личный план путешествия

Закрытый инструмент `/admin/travel` использует существующую admin-сессию.
Это личный инструмент владельца, а не второй кабинет клиентов.

## Источник и границы

Исследовательская библиотека находится вне Git. Приложение видит только
`/srv/sergey-travel/calculator`, смонтированный в backend с правом записи.
Библиотека исследований целиком не монтируется и не отдаётся через HTTP.
В репозитории находятся только движок, документация контракта и обезличенные тесты.

`plan.md` содержит JSON frontmatter с `title`, `settings`, `returnFlight`,
`phaseIds`. Каждый `phases/<id>.md` содержит frontmatter фазы с датами,
входящим перелётом, ставкой за ночь и расходами. Тело Markdown разбивается
заголовками `## item-id | Название` на спойлеры одного уровня.
Поддерживаемые поля проверяются в `travel_service.validate`.

Сохранение создаёт неизменяемый каталог `releases/<uuid>`. Текстовый файл
`current` атомарно переключается на UUID. Старые версии сохраняются.
Совпадение revision обязательно: устаревшая вкладка получает 409.

## Расчёт без повторного учёта

- Проживание: оплачиваемые ночи × ставка; включённые в пакет ночи вычитаются.
- Еда с кофе и бытовые покупки: недельные ставки на все календарные дни.
- Незапланированный городской транспорт: только дни постоянных остановок.
- Досуг города: максимум недельного лимита и стоимости выбранных занятий;
  показываются лимит, выбранное, свободное и превышение.
- Отдельные поездки, известные трансферы и достопримечательности коротких фаз:
  точные статьи `fixed`. Дни отдельного выезда исключаются из городских лимитов.
- Рестораны: заданные ужины заменяют соответствующее число средних посещений.
- Спорт, шоппинг и общие расходы показываются отдельно и входят в итог один раз.
- `included` описывает уже включённые услуги и не увеличивает итог.
- Неизвестная доплата не объявляется бесплатной: сохраняется признак `unknown`.

PNG имеет вертикальный формат 900 px с крупным текстом: цветной общий итог,
последовательные этапы, обратный билет, отдельные статьи и компактные ставки.
Служебные комментарии и пояснения лимитов остаются в калькуляторе, не в PNG.

Формулы и экспорт PNG используют один модуль `static/travel/calc.mjs`.
Дата выезда одной фазы равна заезду следующей. Последний календарный день
учитывается в повседневном бюджете, но не создаёт лишнюю гостиничную ночь.

## Обновление без сборки приложения

`backend/scripts/publish_travel_plan.py <directory> --check` локально проверяет
пакет. Без `--check` публикует через существующий защищённый API. Логин и
пароль берутся только из `TRAVEL_ADMIN_USERNAME` и `TRAVEL_ADMIN_PASSWORD`.
Данные и секреты не добавлять в Git. Изменение ставок в браузере сохраняет
Markdown; публикация MD сохраняет новую версию без CI и пересборки образа.

API: GET/PUT `/admin/api/travel/plan`, GET `/admin/api/travel/phases/<id>`,
POST `/admin/api/travel/publish`. Запись требует `X-Travel-Write: 1`;
браузерный Origin должен совпадать. Ответы не кешируются.

## Выпуск и восстановление

Перед первым запуском создать каталог калькулятора на хосте с владельцем
UID 100/GID 101 (проверить `id` действующего backend). Подкаталоги версий и
`current` должны быть доступны app; соседние личные каталоги не открывать.
Прежний backend без mount не затрагивает эти данные. Для отката содержимого
переопубликовать сохранённый пакет с актуальной revision через API.
Для переноса сохранять весь каталог калькулятора, включая releases и current.
Правки браузера не синхронизируются автоматически на локальный диск. После
значимых правок скачать новый независимый снимок командой
`publish_travel_plan.py <new-directory> --export`. Экспорт запрещает перезапись
существующей папки; пакет можно проверить и переопубликовать обычным способом.
Текущий план также скачивается JSON-кнопкой и восстанавливается импортом.
Резервное копирование PostgreSQL этот личный каталог не покрывает.
Обычный выпуск приложения — по `docs/OPERATIONS.md`, миграции БД не требуются.

## Проверки

`PYTHONPATH=backend python -m pytest backend/tests/test_travel.py`
проверяет границы API, сохранение MD, конфликт версий, XSS и лимит тела.
`node --test backend/tests/travel-calc.test.mjs` проверяет расчёты и даты.
Проверка браузером покрывает редактирование, сохранение, фазу и PNG.

## Связи

Авторизация — `platform.auth`; навигация — `admin.control`; выпуск —
`operations.delivery`. Личные суммы и решения принадлежат серверным MD.
