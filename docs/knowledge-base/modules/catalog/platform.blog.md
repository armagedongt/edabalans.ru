# Публичный блог

Типографика каталога, статей, кнопок и оглавления использует общий Manrope из
[единого источника](../../SITE_TYPOGRAPHY.md); отдельный Inter не подключается.

Единый вход в контур статей, SEO, аналитики и публикации:
[README блога](../blog/README.md). Основной поток — «Публикация в Блоге».
Названия и действующие ссылки всех опубликованных статей — в
[таблице статей](../../../../content/author-voice/source-selection/article-source-registry.md#канон-в-блоге);
владелец реестра происхождения и семей — `platform.content`.

По решению владельца 18.10.2026 блог переезжает в `похудение-это-есть.рф/blog` и связан с основным публичным сайтом
общей навигацией и стандартным подвалом.

Старый поддомен `blog.похудение-это-есть.рф` по решению владельца от
18.10.2026 отключён: все пути отвечают HTTP410 без перенаправлений. TLS сохранён,
чтобы посетитель и поисковый робот получили корректный ответ об удалении.
По отдельному поручению владельца 18.10.2026 в
[Telegram-посте №465](https://t.me/Fitness_Talks/465) ссылка заменена через Bot API на
`https://похудение-это-есть.рф/blog/pochemu-yapontsy-hudye`; текст, форматирование
и фотография сохранены. Материалы доступны на основном домене. Старые адреса статей отменены без redirects и дублей. Правила будущих адресов и постоянных внутренних ключей — в [редакционном workflow](../../BLOG_EDITORIAL_WORKFLOW.md#адрес-и-название-статьи).

## Функции

Ссылки из каналов помечаются `from=tg|max`: неизвестному посетителю
inline/popup подписки скрыты, свежий подтверждённый статус «не подписан»
на канал-источник разрешает показ. Метка действует только на текущий URL,
не является идентичностью и не сохраняется в cookie; точный контракт —
[READER_INSERTIONS](../blog/READER_INSERTIONS.md#вход-с-fromtg-или-frommax).

- открывать каталог из публичной навигации через постоянный вход
  `похудение-это-есть.рф/blog`, со статьями `/blog/<slug>`, профилем `/blog/author/sergey-vorontsov` и sitemap `/blog/sitemap.xml`;

- показывать главную с каталогом статей и рубриками;
- искать из шапки по заголовкам и текстам публичных статей, используя выпущенную
  API-редакцию либо Git fallback, но не черновики и служебные материалы;
- показывать распознанному администратору на той же странице закрытую редакцию
  со служебными и находящимися на модерации материалами;
- автоматически открывать в закрытом редакторе зарегистрированные
  manifest-статьи, хранить версии Markdown, позволять выбрать карточную обложку
  из медиа статьи с точным предпросмотром `16:9` и давать безопасный предпросмотр;
- явно выпускать сохранённую редакцию существующей статьи без deploy, не
  позволяя API создать неизвестный slug;
- хранить description и отдельный поисковый seo_title в том же Markdown и
  штатных версиях; поисковый заголовок не меняет H1, адрес или тело статьи;
- публиковать индексируемые страницы статей с оглавлением, локальными медиа,
  одной закрытой CTA-вставкой и тремя связанными материалами;
- выдавать `sitemap.xml` и `robots.txt` для публичного домена;
- сохранять выбранную светлую или тёмную тему на устройстве;
- подключать единое публичное уведомление о cookie без локальной копии разметки
  или логики;
- вести посетителя на основную главную и напрямую в бесплатный интенсив, а
  контакты раскрывать в шапке без прокрутки к подвалу;
- использовать общий `site-footer.js` без второй реализации подвала.

05.10.2026 профиль автора дополнен согласованным описанием опыта (поле `bio`
в `content/blog/author.json`, только на странице автора). Для двух материалов
с неизвестной исторической датой manifest хранит доказанную дату появления в
блоге отдельно как `blog_published_at`; интерфейс использует общую подпись «Опубликовано».
Выбор дат составных материалов и provenance — по `blog/SEO_EDITORIAL.md`.

Верх статьи компактный: хлебные крошки, заголовок, круглая аватарка 32×32, имя и роль автора,
короткие даты «Опубликовано ДД.ММ.ГГГГ» и «Обновлено ДД.ММ.ГГГГ» без двоеточий.
Отдельные «Все статьи» и повтор рубрики над заголовком не выводятся;
рубрика остаётся в карточках и хлебных крошках. Даты и автор сохраняются в SEO-разметке.
В статье о Японии начальный портрет скрыт, карточная обложка сохранена.

Временно для выбора favicon модуль также отдаёт три пустые `noindex`-страницы
`/blog/favicon-tests/{black|blue|face}`. Маршруты и три разрешённых ассета собраны
изолированно в `blog_routes.py` и `static/blog/assets/favicon-test-*`, чтобы после
выбора удалить их одним изменением без касания главной и статей.

Тело статьи использует общую палитру ЛК по
[ARTICLE_STANDARD](../../ARTICLE_STANDARD.md), с адаптацией тёмной темы.
Шапка, рубрики, CTA и рекомендации сохраняют профиль блога.

## Текущий дизайн-контракт

Утверждён Сергеем 19.10.2026 после локального просмотра ПК и мобильной версии.

- Общая шапка каталога, статьи и профиля: голубая надпись Unbounded 800 в две
  строки, мозг слева; ссылка ведёт на `/`. Высота мозга почти равна двум строкам.
  В desktop рядом разделы сайта, на телефоне остаются поиск, тема и меню.
  На desktop «Контакты» раскрываются также в шапке; список берётся из общего меню.
  Боковая панель сохраняет все переходы и сразу раскрытое содержание статьи.
- Меню использует существующие `site_menu.py` и `public-site-assets/site-menu.*`.
  В каталоге меню показывает рекомендованную шестёрку; внутри статьи одна кнопка
  «Содержание» открывает общий лист с переходами/контактами сверху и оглавлением
  ниже. Прежние параллельные controls не выводятся; подробности — READER_INSERTIONS.
  Открытие поиска закрывает меню и наоборот. Поиск — GET `/blog?q=…` по всему
  опубликованному корпусу, включая опубликованные API-редакции, с последующей
  пагинацией по15. Черновики не участвуют. Регистр и е/ё нормализуются;
  все слова запроса должны встретиться. Выдача `noindex, follow` с canonical `/blog`.
- В hero один H1 в две строки: «Блог о похудении» и «Сергея Воронцова».
  Прежний авторский анонс сохранён; справа круглая яркая аватарка с булкой
  и пальмами из принятой версии канала (`sergey-author-bright.webp`). На мобильном
  диаметр60px, боковые отступы24px. Плашки рубрик высотой34px, текст по центру.
- На первой общей странице — закрытый `details` «Рекомендую начать с этих статей»
  с подписью «Раскрыть» и шевроном. Шесть статей берутся из опубликованного каталога
  по `content/blog/homepage.json`: desktop карточки3×2, мобильный текстовый список.
  Запасные мобильные миниатюры включаются `mobile_thumbnails` в том же файле.
  На следующих страницах, в рубриках и поиске подборка не повторяется.
- Основная лента определяется редакционным порядком manifest, а не популярностью.
  Начало: Япония,12 изменений, ПП-рецепты, план, питание/тренировки,30 растений.
  Остальные статьи остаются доступными; сервер выдаёт до15 на страницу без дублей.
  Рубрики и страницы — обычные ссылки, работающие без JavaScript.
- Все обложки каталога и рекомендаций помещаются целиком в единую область16:9
  с нейтральными полями. Исходники, адаптивные `srcset` и выбор файла в редакторе
  сохраняются. Сохранённое `card_fit` не меняет этот единый публичный показ;
  режим кадрирования остаётся данными редактора и не обрезает публичные карточки.
- Одна внешняя рамка объединяет картинку и текст. Теги — светло-голубые с синим
  текстом; заголовки графитовые, при наведении цвет сохраняется. На ПК карточка
  слегка поднимается с тенью, изображение не увеличивается. Reduced motion учтён.
- Галочка «Прочитано» появляется после достижения75% высоты тела статьи нижним
  краем окна. Это локальная отметка глубины просмотра, не доказательство чтения
  и не серверная аналитика. Slug сохраняется в `edabalans-blog-read-v1` в
  localStorage этого браузера. При недоступном хранилище статья остаётся читаемой.
- Автор, даты, хлебные крошки, типографика статьи Manrope, колонка760px,
  содержание из опубликованных заголовков, подписные вставки, CTA, footer и cookie сохраняются.
  Их владельцы — ARTICLE_STANDARD, READER_INSERTIONS и соответствующие runtime.
- Тёмная тема сохраняется на устройстве; новые поверхности используют её токены.
- Шрифты берутся из общего `/assets/site-typography.css`, отдельные копии не заводятся.

## Граница

Автор статьи ведёт на постоянный профиль `/blog/author/sergey-vorontsov`.
Профиль, подпись автора и Person используют один `content/blog/author.json`;
биография не дополняется неподтверждёнными квалификациями. Видимые хлебные крошки
связывают блог и существующую рубрику без повтора H1; структурированная
SEO-цепочка BreadcrumbList сохраняет блог, рубрику и статью. Подтверждённая дата исходника
отдельна от даты опубликованной API-редакции; новый draft не обновляет дату
публичного материала. Неизвестные даты не вычисляются.

Модуль владеет публичной оболочкой, реестром manifest-идентичностей, Git fallback,
версионным внутренним происхождением полного Telegram-материала в metadata MD
и его читательской плашкой (без назначения по анонсам),
а также cookie-узнаванием для подписных приглашений без входа в кабинет
(API и привязка существующих персональных `/m/`/`/p/` переходов;
подписной popup и необязательные смысловые inline-слоты),
черновыми и опубликованными версиями Markdown и выбранной карточной обложки
существующих статей и
типизированной сборкой публичных CTA от владельцев продуктов. Сохранение draft
не меняет public; выпуск требует отдельного version-gated действия. Создание
новой identity отложено в `docs/plans/BLOG_NEW_ARTICLE_API.md`. Авторский голос, редакционные правила и
маршрутизация писателя принадлежат `platform.content`; продуктовые обещания и
условия CTA остаются у соответствующего продукта. Домен и HTTPS принадлежат
`operations.proxy`.

Закрытая редакция использует существующий вход администратора и открывается на
`https://admin.похудение-это-есть.рф/blog`. Административная cookie остаётся
host-only; публичная выдача основного домена не получает её автоматически.
Закрытые API проверяют существующую admin-сессию, изменения из браузера —
same-origin. На публичном домене блог открывает читательские страницы.


## Источники истины

Подписная карточка использует общий версионный документ сайта: статья+подписка
или только подписка, с исключением покупателей и учётом чтения>75%.
Конечная CTA статей — мастер-класс с названием активного продуктового каталога.
Контракт и приоритет from/Telegram-origin —
[READER_INSERTIONS](../blog/READER_INSERTIONS.md#подписка).

- `content/blog/manifest.json` — порядок, рубрики, разрешённые media, обложки по
  умолчанию, видимость заставки, CTA, связанные статьи и канонические опубликованные
  идентичности семей; `inline_related_pool_source_ids` — единственный состав
  редакционного продуктового пула для внутреннего «Читайте ещё»;
- `content/blog/articles/*.md` — seed и fallback до первого API-выпуска;
- description берётся из опубликованного Markdown: явный начальный блок либо
  первые два предложения, без добавления пробелов на границах выделений и ссылок.
  Формат ручной правки — в `BLOG_API_AUTHORING.md`;
- `backend/app/blog_content.py` — валидация каталога и безопасный renderer;
- `backend/app/public_cta_catalog.py` — типизированная сборка разрешённых CTA;
- `backend/app/blog_routes.py` — публичные маршруты, metadata, sitemap и media;
- `backend/app/blog_draft_service.py` — seed, draft/public версии и publish boundary;
- `backend/app/blog_draft_routes.py` — owner-only API, редактор и предпросмотр;
- `docs/knowledge-base/BLOG_API_AUTHORING.md` — контракт Markdown → API;
- `docs/knowledge-base/BLOG_EDITORIAL_WORKFLOW.md` — устойчивый маршрут новой статьи;
- `docs/knowledge-base/modules/blog/SEO_EDITORIAL.md` — согласование поисковых metadata, архив, даты и редакционные границы;
- `docs/knowledge-base/modules/blog/READER_INSERTIONS.md` — согласованные вставки, подписка, происхождение и новое содержание; границы локального образца и интеграции;
- `docs/knowledge-base/ARTICLE_STANDARD.md` — общая типографика статей.
