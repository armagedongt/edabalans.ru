# Библиотека и карта контента

Общий серверный слой, через который любой новый чат может получить
актуальную карту авторского и технического знания, а затем адресно прочитать только
нужные полные источники.

## Функции

- индексировать канонические источники без создания второй копии канона;
- хранить provenance, версии, права доступа, связи и статус проверки;
- различать оригиналы, точные дубли, смысловые совпадения и неиспользованные фрагменты;
- предоставлять карту и адресные ресурсы через MCP/API;
- направлять исполнителя сначала выбрать ближайшую принятую авторскую основу, а
  полные raw-предки открывать для пробелов, контекста, provenance и конфликтов;
- вести очередь решений Библиотекаря и события фактического использования;
- связывать редакционный прогон с исходниками, принятой версией и публикацией;
- явно объяснять пустую стартовую выдачу: число источников в сводке не означает,
  что интерфейс автоматически выводит весь каталог без поискового запроса;
- различать пустой результат, пустую очередь решений и ошибку загрузки с повтором.

MCP принимает точные host основного и административного кириллического домена
(в IDNA, с портом 443 и без него). Прежний host временно сохраняется для
совместимости; bearer-проверка остаётся обязательной, wildcard не добавлен.

## Граница

Не заменяет Project Knowledge, каталог контента, приватный авторский корпус или
канонические документы продуктов. Не пишет материалы, не публикует их, не объединяет
смысловые совпадения и не обезличивает консультации без решения владельца.

Каталог публикаций и авторский корпус принадлежат `platform.content`, техническая
карта проекта — `admin.project-knowledge`. Библиотека читает их как владельцев и
не создаёт независимые копии.

## Источники истины

Карточки `kind=image`, `metadata.catalog=site-images` принадлежат `platform.content`.
Библиотека предоставляет их поиск и версии по [IMAGE_CATALOG](../../../IMAGE_CATALOG.md).
При повторном использовании дополняется та же карточка; совпадение по смыслу
не означает доказанный дубль, а доступ к карточке не открывает защищённый файл.

Пользовательский и межмодульный контракт описан в
`docs/knowledge-base/EDITORIAL_PRODUCT_SYSTEM.md`. Канонические тексты, продуктовые
правила и технические документы остаются у своих текущих module owners; серверный
реестр хранит их URI, версии, provenance и права, а не независимое содержание.

Исполняемый контракт, URI, таблицы, API, MCP, импорт и эксплуатация описаны в
`docs/KNOWLEDGE_LIBRARY.md`. Владелец работает с очередью через `/admin/library`,
а Codex — через MCP `edabalans_knowledge` и project skill `edabalans-librarian`.

Технические файлы, routes, таблицы, migrations и программные символы не
перечисляются вручную в карточке: они подставляются из generated inventory.
