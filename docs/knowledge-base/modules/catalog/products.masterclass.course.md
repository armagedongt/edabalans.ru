# Структура и материалы мастер-класса

Рецепты связываются с приложением и базой продуктов через
[контур рецептов](../../RECIPE_CONTOUR.md). Формат статьи, точные данные MD,
карточки и их рабочая сборка принадлежат
`content/masterclass/recipes/README.md`; вычислительный оригинал и личные копии —
`products.recipes`. Одиночные фото карточки занимают полную ширину с естественной
высотой, без повторного вписывания вертикального кадра в квадрат.
Одна опубликованная статья переиспользуется учебными маршрутами.

Определяет содержание, дни, шаги и редакторские версии структуры 20-дневного курса.

## Функции

Административный API материала возвращает точные `source_content`, `source_format`
и `source_provenance`; новые редакции сохраняют исходник в той же версии рядом
с производным HTML. Читательский API этих полей не выдаёт. Старый HTML не
превращается в выдуманный Markdown; Git-особые файлы сохраняют прежнего владельца.
Профиль сервера подключает существующий Git-оригинал `day-01-article-02` к тому же
файлу постоянной папки и ID материала; завершение публикации проверяется по runtime
hash. Исторические Git-рецепты дня 7 остаются архивами, текущие — по ID дня 15.
Постоянная рабочая копия и границы публикации — [единая редакционная папка](../../EDITORIAL_VAULT.md).
Её файл названий меняет только заголовки существующих дней и материалов;
ID, порядок и правила прохождения сохраняются. Изменение структуры остаётся
адресной задачей Codex по продуктовому договору.

Полный оригинал рецепта дня 15 подключается только после проверки hash и
совпадения опубликованного HTML. Обычная правка абзаца и восстановление полной
MD-версии сохраняют материал и вычислительный оригинал одной транзакцией;
числа, карточки, медиа и структуру меняют существующим workflow рецептов.
Подробный договор — `content/masterclass/recipes/README.md`.

- отдавать отдельно разрешённые рецепты по прямым публичным ссылкам
  `/recipe-preview/<slug>`, без входа и добавления в программу/каталог; закрытый
  список и канон Markdown описаны в `content/masterclass/recipes/README.md`;
  заправки для салатов образуют одну статью с отдельной карточкой каждого варианта;

- публиковать и восстанавливать версию структуры курса;
- показывать в каталоге дня 15 самостоятельные версии материалов с переходами
  между ними и карточками для скачивания у рецептов; первая подборка дня 7
  ссылается на эти же материалы, прежние версии дня 7 сохраняются в истории;
- различать в этом каталоге рецепты с карточкой и обычные посты категории
  «Способы обработки продуктов» без карточки/таблицы БЖУ; правила типов и
  необязательных рекомендаций принадлежат `content/masterclass/recipes/README.md`;
- показывать единый порядок дней и материалов во всех представлениях;
- оформлять оболочку курса общим `course-visual.css` по согласованному паспорту:
  постоянное оглавление без шапки на ПК, выдвижное на телефоне, единые состояния;
  каркас и актуальное оформление находятся в этом едином CSS, без прежнего
  встроенного оформления в HTML и без зависимости от способа открытия курса;
- сохранять введённые через Enter переносы строк без HTML-кода в редакторе;
- задавать каноническую структуру страницы статьи и её компактного оглавления без
  второго набора заголовков;
- редактировать подключённые оригиналы в постоянной папке и публиковать выбранные
  материалы через API; специальный пакет `content/masterclass/editorial/`
  сохраняется для согласованного структурного выпуска, прежние `days/` — архив;
- редактировать первый пилотный материал через защищённый Git-backed экран:
  отдельный draft, точный preview, diff, явная публикация, Git history, rollback и
  SHA-защита от перезаписи;
- публиковать обычный текстовый материал отдельной версией по стабильному
  `step.id`, не меняя структуру и не выполняя code deploy;
- публиковать выбранный диапазон дней без повторной публикации уже принятых
  соседних дней; для DQS переносить из Markdown две подписи действий и пояснение,
  а отправку постоянной ссылки оставлять существующему runtime;
- восстанавливать предыдущую редакцию одного материала без отката курса;
- безопасно рендерить продуктовые вставки `slider(...)` и
  `dqs_score_table(...)` из Markdown материала;
- сворачивать большую необязательную справку через безопасный `spoiler(...)`,
  не помещая HTML и код интерфейса в авторский текст;
- показывать незаконченный материал на его месте в программе неактивной карточкой
  «Скоро» по метке `placeholder: true`, не открывая черновой текст и не включая
  материал в обязательное прохождение;
- открывать вложенные статьи рецептурной подборки по прямым ссылкам из родительского
  материала, не добавляя их в линейное оглавление, время дня и обязательный прогресс;
- переводить прежнюю 21-дневную runtime-версию на утверждённые 20 дней, сохраняя
  первые пять дней и прогресс по стабильным `step.id`;

## Граница

`course.json` не является active runtime после появления DB revision.

## Источники истины

Active `managed_document_versions` — runtime truth структуры;
`content/masterclass/course/course.json` — seed; смысловой контракт —
`COURSE_STRUCTURE_CONTRACT.md`; изменяемые размеры, отступы и цвета —
`COURSE_VISUAL_SYSTEM.md`.

Постоянная папка [EDITORIAL_VAULT](../../EDITORIAL_VAULT.md) содержит рабочие файлы
подключённых оригиналов и их серверные основы. Codex редактирует эти же файлы;
`content/masterclass/editorial/` сохраняет специальный пакет прежнего публикатора
и не заменяет текущую принятую редакцию.
Для дальнейшей редактуры уже выпущенного материала исходной авторской основой
считается его актуальная опубликованная версия, полученная через API, а не старый
локальный MD или транскрипт. Рабочий MD синхронизируют с ней до адресной правки.
Для незавершённого материала сохраняются принятый черновик и исходники с
происхождением; публикация принятой версии обновляет основу следующих правок.

Команда
`backend/scripts/publish_masterclass_editorial.py --publish` создаёт новую active
revision структуры и отдельные versioned-редакции обычных статей. Не вошедшие в
программу прежние шаги не удаляются, а остаются скрытыми.
Для согласованного частичного выпуска `--through-day 5` ограничивает изменения
днями 1–5; структура, тексты и редакторские поля более поздних дней сохраняются.

Для `day-01-article-02` Markdown из `content/masterclass/editorial/materials/` уже
является одновременно authoring и runtime truth после deploy. Экран
`/admin/courses/masterclass-21/materials/day-01-article-02/editor` читает и пишет
тот же файл через GitHub Contents API. Ветка `content-drafts` не развёртывается;
`main` публикуется обычным CI/deploy. GitHub token хранится только в серверном `.env`.
В allowlist того же Git-backed маршрута сохранены восемь прежних рецептов дня 7;
они являются архивами, а текущие рецепты редактируются по ID дня 15 через API.
Другие статьи не переводятся на этот маршрут автоматически.

При частичном выпуске `--exclude-day` и `--exclude-step` сохраняют указанные дни
и материалы из active runtime без изменений. Заглушки не публикуются как статьи.
Видео внутри статьи задаётся закрытым компонентом `video(...)` из продуктового
каталога: HTTPS MP4 с учебным плеером либо канонический Boomstream с плеером
провайдера; короткий служебный заголовок, без подписи или ссылки и без автозапуска.
Голосовое внутри статьи задаётся `audio(...)`: HTTPS-аудиофайл, аватарка,
автор и длительность. Закрытый плеер на всю ширину статьи использует оформление
голосовых главной страницы, без автозапуска; исходный звук и аватарка не входят в Git.

`content/masterclass/source-current/` хранит миграционные исходники прежней
редакции и после первичного переноса не является местом новой редактуры. Пока
обычная статья не имеет DB-версии и её активный шаг ссылается на существующий MD,
серверный профиль позволяет принять полный оригинал с проверкой исходного hash.
Далее новые редакции и восстановление сохраняют полный MD и профиль той же
DB-версии; старый Git fallback её не перезаписывает. Порядок —
[редакционная папка](../../EDITORIAL_VAULT.md#полный-исходник-source-current). Для DQS
прежний полный исходник — `13-dqs-system.md`; `.txt` сохранён как неизменяемый
legacy-источник. Повторно используемые авторские вставки и код
находятся в `content/masterclass/components/`: код слайдера отделён от ссылок на
изображения, а таблицы получают данные из одного продуктового allowlist. Локальные
изображения опубликованных авторских материалов поставляются из
`editorial/assets/`, а прежние миграционные изображения остаются в
`source-current/assets/`. Оба каталога выдаются только через ограниченный маршрут
`/course-assets/masterclass/media/*`; Markdown-публикатор заменяет относительные
префиксы `../assets/` и legacy `assets/` на этот маршрут. Страница
курса загружает CSS и JavaScript напрямую из этого каталога через
`/course-assets/masterclass/article-components.*`; копии runtime-кода в HTML нет.
Сырой HTML статьи не получает доверенные component-классы и `data-*` атрибуты:
их может добавить только закрытый Markdown renderer продукта.

Технические файлы, routes, таблицы, migrations и программные символы не
перечисляются вручную в карточке: они подставляются из generated inventory.
