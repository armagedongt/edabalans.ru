# Исполняемый контур Калорийного курса

Статус: `current`
Состояние внедрения: локально реализован и проверяется; migration и production
ещё не применялись
Владелец содержания: Сергей Воронцов
Модуль: `products.calories`

## Вход и доступ

Курс запускается в существующем личном кабинете на закрытой странице Tilda.
Email берётся только из авторизованного профиля Tilda. Backend сопоставляет его с
`user_id` и каждый раз проверяет действующий `ACCESS_CALORIES`. Второй пароль,
почтовый код и отдельная пользовательская сессия не создаются.

До выполнения обоих условий запуска — все видимые статьи опубликованы и
`launchReady = true` — пользовательские course API отвечают
`course_preparing`. Поэтому прямой URL не обходит закрытую карточку кабинета и
не показывает редакционные заглушки участнику.

Прямые ссылки используют `calories_stage` и `calories_material`. Кабинет сначала
проверяет доступ, затем открывает приложение `calories-course` и передаёт ему
маршрут. Адрес возврата очищается от параметров обоих курсов.

## Правила прохождения

Ниже описана прежняя пятиэтапная реализация. Утверждённое 25.09.2026 изменение
для новой редакции находится в разделе «Новая редакция: три модуля». Оно ещё
не применено к runtime и не меняет существующий прогресс одной записью в документации.

1. Этап 1 открывается при первом запуске.
2. Обязательные шаги этапа завершаются сверху вниз явным действием читателя.
3. После всех обязательных шагов открывается чек-лист задания.
4. Этап завершается после всех обязательных галочек.
5. Следующий этап становится доступен сразу; календарного таймера нет.
6. При первой фиксации этапа сохраняются ID обязательных шагов и заданий активной
   редакции. Скрытие материала не ломает уже начатое прохождение.
7. Структура и обычные статьи версионируются отдельно.
8. Между двумя текстами этапа 3 открывается существующее приложение
   `metabolism`; оно использует то же состояние калькулятора, что и вне курса.
   Пользовательский API калькулятора проверяет завершение Мастер-класса и действующий
   `ACCESS_CALORIES`: купленный Калорийный курс не открывает инструмент раньше своей
   очереди. Карточка приложения в ЛК показывает условие до разблокировки.
   Персональный `fully_unlocked` для `ACCESS_CALORIES` открывает калькулятор без
   ожидания завершения Мастер-класса, но не заменяет
   действующее право и согласия. Ремонт курса этим правилом не снимается.

## Данные

- `managed_document_versions`, ключ `calories` — редакции структуры;
- `content_items` и `content_item_versions`, источник
  `calories-course-materials` — статьи;
- `course_stage_progress` — открытие, задание, галочки и завершение этапа;
- `course_step_progress` — завершённые шаги;
- `course_events` — идемпотентные факты прохождения.

Все три таблицы прохождения содержат `course_code`, чтобы не создавать новый тип
таблиц для каждого будущего этапного курса. Сейчас их первый владелец —
`products.calories`.

## API

- `GET /api/calories/course/manifest?email=...` — активная структура;
- `GET /api/calories/course?email=...` — доступность и прогресс;
- `GET /api/calories/course/materials?email=...` — опубликованные статьи доступных
  этапов;
- `POST /api/calories/course/days/{stage}/open` — открыть этап;
- `POST /api/calories/course/days/{stage}/steps/{index}/complete` — завершить шаг;
- `POST /api/calories/course/days/{stage}/task/open` — открыть задание;
- `PUT /api/calories/course/days/{stage}/checks/{index}` — сохранить галочку.

Внешний путь пока сохраняет слово `days`, потому что клиентская оболочка общая с
Мастер-классом; предметный payload одновременно отдаёт `stages` и совместимый
алиас `days`. В интерфейсе пользователь видит только этапы.

## События и сообщения

Runtime записывает:

- `calories_course_opened`;
- `calories_stage_opened`;
- `calories_material_completed`;
- `calories_stage_assignment_opened`;
- `calories_stage_completed`;
- `calories_course_completed`.

События не содержат дневник, вес или ответы пользователя. Dispatcher и цепочка
бота не подключены. Решения о сообщениях принадлежат Telegram-модулю после
утверждения текста и условий.

## Публикация материалов

Обычная статья публикуется через общий административный API курса с
`course_code = calories` либо `tools/publish_course_material.py --course calories`.
Публикация статьи не меняет структуру и прогресс. До готовности текстов шаги
остаются заглушками из `course.json`.

Кабинет считает курс готовым только когда опубликованы все видимые статьи и в
активной структуре включён `launchReady`. Статический каталог держит продукт
закрытым по умолчанию; вычисляемая готовность применяется только к карточке
Калорийного курса. Переключатель находится в редакторе структуры, а список курсов
показывает число опубликованных статей.

Migration `20260828_0028` создаёт таблицы прогресса и событий. Применять её на
production можно только после отдельного подтверждения владельца.

## Новая редакция: три модуля

Решение владельца: 25.09.2026. Состояние реализации: `planned`.
Редакционный состав — 12 учебных статей и три самостоятельных завершающих
материала, всего 15 позиций: 5 + 6 + 4.

| Модуль | Учебные статьи по порядку | Завершающий материал |
|---|---|---|
| Учёт калорий | Введение; приложение для записи еды; как считать точно; как упростить учёт | Задания: учёт калорий |
| Расход, активность и дефицит | Из чего складывается расход калорий; дневник повседневной активности; как учитывать тренировки; активность без «тренировок»; дефицит, скорость и корректировки | Задания: расход и дефицит |
| Питание без постоянного подсчёта | Блоки в питании; собственный каталог; перевести цифры в действия | Что дальше |

В боковом меню сразу показаны материалы. Название модуля — некликабельный
разделитель прописными буквами; отдельной страницы дня/модуля нет.
Оформление групп и статей наследует визуальную систему МК.

В конце каждой учебной статьи помещается обычный заголовок
«Что я хочу от вас после прочтения этого материала» и краткий маркированный
список: обычно 1–2 пункта, максимум 3–4 при реальной необходимости.
Это ожидаемые действия или понимание, не интерактивные галочки и не плашка.
Не добавлять новое упражнение только ради заполнения блока.

Три завершающих материала содержат краткий сохраняемый чек-лист модуля,
без зелёного контейнера. «Что дальше» сначала содержит этот чек-лист, затем
короткое заключение, переход к тренировочной теме и существующий универсальный
модуль дополнительных продаж. Это часть «Что дальше», не шестнадцатая позиция
меню. Формулировки заданий уточнены владельцем 25.09.2026: во введении человек
записывает план учёта с учётом прошлого опыта; начать дневник предлагается в
завершении первого модуля. В инструкции приложения — установка и сохранение
старых выгрузок; расчёт сложного блюда относится к статье о точности.

Следующий модуль доступен только после обязательных материалов и всех
обязательных галочек, затем паузы до 06:00 по местному времени участника.
Точный календарный расчёт и серверное сохранение времени переиспользуются из
МК — §12 общего структурного контракта, без собственной трактовки «ближайших
шести утра». Галочки не устанавливаются за чтение автоматически.
Существующее административное полное открытие не отменяется этим решением.

Галочка может подтверждать понимание, пробу или начало действия, если именно
это написано в пункте. Она не требует недельного результата, которого пункт
не обещает, и не означает проверку преподавателем. Прохождение не содержит
обязательной отправки личных дневников.

Уточнение владельца 25.09.2026 заменяет прежнее решение «без допродаж»:
универсальный модуль предложений подключается в конце «Что дальше» при общем
выпуске курса. Цены, доступные продукты и право покупки приходят из существующего
коммерческого контура, не копируются в текст и не переопределяются редактором.
Не открывать продажу незавершённого продукта одной вставкой блока.
Упоминания тренировочного мини-курса используют единый межкурсовой pop-up:
[общий контракт, §17](../masterclass/COURSE_STRUCTURE_CONTRACT.md#17-ссылки-на-другие-курсы-внутри-материалов).
Новая структура и таймер требуют реализации и проверки до публикации;
само наличие этой записи не означает выпуск курса.
