## Готовность и границы

Решения владельца реализованы и проверяются в **локальном прототипе**, не в
публикационном backend. Общая библиотека: [content/article-components](../../content/article-components/README.md).
Прототип читает её CSS непосредственно; это не скопированная тема каждой статьи.
Специальные компоненты МК остаются отдельными продуктовыми адаптерами.
Не изменены реальные тексты курсов, DQS, анкеты, интенсив, база или production.

Целевой контракт один для статей блога и текстовых материалов курсов/интенсивов.
Это не означает, что их текущие API и оболочки уже одинаковы. Подключение каждого
публикационного маршрута выполняется отдельно, с проверкой sanitizer и оболочки.
Особые формы, анкеты, приложения и продажи не превращаются в статьи автоматически.

## Разметка и результат

| В исходнике | Семантический результат | Источник оформления |
|---|---|---|
| Один `# Название` в начале | Название карточки/страницы; без второго h1 в теле | Оболочка + ARTICLE_STANDARD |
| `## Раздел` | h2, пункт штатного плавающего содержания | Оболочка + ARTICLE_STANDARD |
| Обычные абзацы; `**…**`, `*…*` | p, strong, em | ARTICLE_STANDARD |
| `~~…~~`, `==…==` | del того же цвета; mark | formatting.css |
| `%%…%%` вне кода | Редакторский комментарий: исключить из публикации | Переводчик |
| `- Пункт`, `1. Пункт` | ul/ol | ARTICLE_STANDARD |
| `- [x] Пункт`, `- [ ] Пункт` | Положительный ✓ / отрицательный × | status-list.css |
| `> Текст` | blockquote, боковая линия, без фона | ARTICLE_STANDARD |
| `> [!NOTE]` и тело с `>` | article-note-accent, одна общая плашка | note.css |
| `> [!NOTE]- Подробнее` и тело | details.article-spoiler, закрытый по умолчанию | Существующий article-spoiler |
| Тройные обратные кавычки и текст | pre/code в article-copy-block + Copy | copy.css + md-copy.js |
| `---` отдельной строкой | hr | formatting.css |
| Markdown-таблица с шапкой | Одна таблица, на телефоне карточки строк | table.css |
| `![Описание](https://…/image.webp)` | img с alt в месте вставки | Оболочка + formatting.css |
| Прямой HTTPS URL картинки отдельной строкой | Та же img; автоматический alt «Иллюстрация к материалу» | Переводчик |
| Callout LINK со ссылками | Группа обычных ссылок, оформленных как кнопки | actions.css |

Новый основной формат использует только h1 и h2. h3 остаётся совместимостью
старых материалов, не новым обязательным уровнем. Содержание **не пишется как
спойлер в MD**: штатная кнопка оболочки собирает его из h2. Добавлять заголовки
ради наполнения содержания запрещено.

Строчный код сохранён в старом парсере для совместимости, но не входит в новый
редакторский набор и не имеет отдельной кнопки копирования. Для текста,
который читатель должен забрать, используем только отдельный блок кода.
Это не код, исполняемый сайтом: HTML, комментарии и MD внутри показываются
буквально; копирование сохраняет переносы строк. Язык после кавычек не включает
подсветку синтаксиса. Запрет копирования всей статьи этим механизмом не реализован.

## Плашка и спойлер

```md
> [!NOTE]
> **Мысль.** Текст плашки.
>
> Второй абзац.

> [!NOTE]- Подробнее
> Текст спойлера.
```

NOTE без минуса: фон сейчас #FFF6C9, без декоративного заголовка, значка,
рамки или боковой полосы. Заголовок после `[!NOTE]` — редакторская метка, на сайт
не выводится; важный текст пишется в теле. NOTE-minus: заголовок обязателен по
смыслу; при отсутствии используется «Подробнее». Белый закрытый спойлер —
существующий компонент, не новое содержание материала.
В теле поддержаны абзацы и строчные выделения/ссылки. Вложенные callout,
списки/таблицы/код внутри callout не входят в этот этап; их не обещаем автоматически.
Между блоками пустая строка без `>`; внутри блока пустая строка `>` делит абзацы.
NOTE+ и другие типы callout пока отклоняются, не подменяются другим стилем.

## Кнопки: обычный callout, не HTML

LINK — наша зарезервированная роль внутри нативного callout Obsidian, **не встроенная
кнопка сайта Obsidian**. Неизвестный тип в Obsidian выглядит как note; на сайте
его обрабатывает наш переводчик. Шаблоны находятся в
[obsidian-templates](../../content/article-components/obsidian-templates/).

```md
> [!LINK]
> [Получить материал](https://example.com/material)
> [Вернуться к курсу](/apps/masterclass-course.html)
```

- Пустой заголовок LINK: слева, одна под другой.
- `[!LINK] В строку`: строка с переносом на широком экране; на телефоне столбец.
- `[!LINK] По центру`: столбец по центру; на телефоне доступная ширина.
- От одной до четырёх кнопок, порядок точно как в файле; одна ссылка на строке.
- Подпись — непустой обычный текст, без HTML, картинок и вложенной MD-разметки.
- Адрес — абсолютный http/https с именем сайта либо путь от `/` на текущем сайте.
  Не использовать `//`, javascript/data, обратные слеши или управляющие символы.
- Прочий текст в LINK, неизвестный режим и повреждённая ссылка дают ошибку 422.
- Это переходы по ссылкам, не обработчики оплаты, отправки формы или API-команды.
  В прототипе ссылки открываются в новой вкладке согласно старому course sanitizer;
  окончательное поведение внутренних/внешних ссылок согласует интегратор.

Окончательные высота, ширина, радиусы, цвета и состояния принадлежат общей теме
«Дизайна». Сейчас actions.css показывает размещение, а не новую тему LK.

## Таблицы и изображения

Обычная таблица с шапкой и одинаковым числом колонок: на desktop таблица;
до 620px — карточка каждой строки с подписями из шапки. В HTML сохраняются
thead/th/td, шапка не удаляется, только визуально скрывается на телефоне.
Для сложной матрицы возможна горизонтальная прокрутка вместо карточек, но
это отдельное явно выбранное оформление, не второй авторский текст.
Важное ограничение карточек: хуже сравнивать значения разных строк; длинные
матрицы лучше отдельным специальным компонентом. DQS таблицы не меняются.

Предпочтительна `![Описание](URL)`: видно картинку в Obsidian и есть осмысленный alt.
Голая ссылка поддержана для удобства, если путь заканчивается jpg/jpeg/png/webp/gif/avif;
query допустим. Изображения с адресом без расширения вставлять через `![]()`.
Нужен стабильный публичный HTTPS адрес изображения. Ссылка Google Drive на
страницу просмотра, локальное `C:\…`, `![[файл]]` или временный подписанный URL
не заменяют публикацию картинки. Существующий root-relative `/course-assets/…`
может использоваться после проверки наличия файла на сервере.
Прототип не скачивает файлы, не загружает их и не проверяет авторские права.
Исключение текущего блога: `BLOG_EDITORIAL_WORKFLOW.md` требует локализовать
медиа в `content/blog/media/<source_id>/` и whitelist manifest; внешние
hotlink-картинки запрещены. Там отдельно hero/card, одна CTA и три related,
а Markdown тела без h1. Эти правила не отменены прототипом: общий source может
содержать название/картинку, но blog-adapter обязан отделить metadata и
локализовать медиа. Произвольная группа LINK не заменяет утверждённую blog CTA.
Для новой локальной картинки сначала отдельно загрузить её утверждённым
публикационным путём и получить стабильный URL; затем публиковать текст.

## Общие и оригинальные компоненты

Общие адаптивные роли: quote, note, spoiler, copy, divider, image, table,
status-list и actions. Меняется один источник компонента, не каждый материал.
Имена CSS технические; автор не вставляет свои классы в исходник.

Оригинальные компоненты МК зарегистрированы в
`backend/app/masterclass_article_components.py`, каталог —
`content/masterclass/components/README.md`. Сейчас есть именно вызовы:

```text
slider(
https://example.com/first.webp
https://example.com/second.webp
)

spoiler(
Подробнее
Первый абзац.
)

dqs_score_table(
plants
)
```

Точные варианты DQS: full, plants, protein, fats, side-dishes, unhealthy.
Этот этап **не меняет DQS материал или renderer**. NOTE-minus использует ту же
структуру существующего spoiler, но удобную авторскую запись Obsidian.
Нового формата `[произвольный-код]` не вводим. Существующий вызов выбирает
только зарегистрированный renderer; не импортирует путь, JavaScript или HTML
из MD. Неизвестные имена/варианты, неправильное число аргументов и незакрытые
вызовы — ошибки, а не команда создать компонент молча.
Новая оригинальная вставка требует отдельной разработки, регистрации,
проверки безопасности и deploy кода. После этого текстовые параметры могут
меняться через разрешённый API; наличие специального компонента не означает,
что весь материал всегда надо деплоить заново.

Отдельный закрытый CTA-адаптер блога — `content/author-voice/article-component-router.md`
и `backend/app/public_cta_catalog.py`: это продуктовый `blog_cta(...)`,
не новая общая LINK-кнопка. При добавлении surface проверять её собственный
зарегистрированный catalogue, не переносить все оригинальные вставки повсюду.

## API: имеющийся маршрут и подключение нового контракта

Подтверждённые источники: `backend/app/course_material_routes.py`,
`course_material_service.py`, `article_markup.py` и `masterclass_article_components.py`
в Git `origin/main` при исследовании 16.09.2026. Это кодовый аудит, не проверка
ответа текущего production. Воспроизводимые refs прототипа — в demo/serve_demo.py.

Имеющийся API МК, только для разрешённых article-step (не tutorial):

1. Авторизация существующим административным маршрутом; секреты не в MD/Obsidian.
2. `GET /admin/api/courses/masterclass-21/materials/{step_id}` получает version.
3. Проверить файл, картинки, разрешённые блоки и результат локального рендера.
4. По отдельной команде владельца выполнить `PUT` того же адреса:

```json
{"expected_version": 3, "format": "markdown", "content": "# Название\n\nТекст материала."}
```

`3` — пример, не фиксированная версия. `step_id` связывает материал с курсом,
не имя файла или название. API принимает markdown/html, ограничивает контент,
нормализует в безопасный семантический HTML и сохраняет новую серверную версию.
Сейчас названия/краткие описания принадлежат структуре курса, не обновляются
материальным PUT: изменение `#` в файле не гарантирует изменение карточки.
Интегратор должен отдельно связать идентификатор/заголовок со структурным API,
не плодить заголовки и не заявлять единый атомарный запрос до реализации.

При 409 кто-то уже изменил материал: получить свежую версию, показать разницу,
свести изменения; **не повторять с новой версией вслепую**. Одинаковый очищенный
HTML не создаёт лишнюю версию. `GET …/{step_id}/versions` — история;
`POST …/{step_id}/versions/{version_no}/restore` с expected_version возвращает
содержимое как новую актуальную редакцию, не стирает историю.
После PUT заново прочитать версию и открыть пользовательский путь с обычной
авторизацией, проверить текст/кнопки/картинки/содержание и права доступа.
Ошибка загрузки картинки — незавершённая публикация, даже если PUT успешен.

**Новые NOTE-minus/LINK/статусы/копирование нельзя сейчас отправить в этот API и
ожидать полный результат прототипа.** Для интеграции сначала перенести безопасный
адаптер из demo в общую библиотеку, подключить его в renderer API, обновить
фиксированный allowlist sanitizer и общие CSS/JS всех целевых оболочек. Проверить
обычную публикацию, историю и restore: повторная sanitization не должна удалять
признанные компоненты. Не разрешать произвольные классы, обработчики или scripts.

На первом этапе владелец редактирует MD и просит Codex опубликовать; файловое
сохранение само не публикует. Git commit/push хранит MD отдельно, не вызывает PUT.
Кнопки публикации в Obsidian, автоматический watcher и новый API в этой задаче
не создаются. Blog/intensive требуют своих имеющихся либо отдельно разработанных
маршрутов; course endpoint не публикует туда. Политики/оферты требуют отдельной
проверки юридической версии и места показа, не механического обновления курса.

## Приёмка интеграции

Сначала один тестовый материал, затем явно выбранные обычные статьи. Проверить
выделения, скрытые комментарии, безопасные ссылки, картинки, два callout,
копирование с отказом Clipboard, таблицу, все режимы CTA и ✓/×; h1 не дублируется,
оглавление по h2 штатное, нет внешнего скролла на 360/430/768/1440px.
Проверить XSS, повреждённую MD, 409, restore, доступ ученика, отсутствие публикации
при простом сохранении файла. Не массово импортировать и не менять особые анкеты
или интенсив автоматически. Тексты при переносе не переписываются.

Для «Дизайна»: [точка передачи](../../content/article-components/DESIGN_HANDOFF.md).
