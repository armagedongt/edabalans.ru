# Общий стандарт приложений курсов

Этот документ обязателен при создании нового курса и при изменении общей оболочки,
загрузчика, авторизации или навигации существующего курса. Содержание и порядок
конкретного курса принадлежат его продуктовому модулю; здесь хранится только общий
технический контракт.

## Первая полезная отрисовка

1. Первый экран курса ожидает только минимальные данные, без которых нельзя
   безопасно показать программу: структуру и пользовательский доступ с прогрессом.
   Эти данные можно вернуть одним ответом или запросить параллельно.
2. До первой отрисовки запрещено загружать тексты всех материалов курса, содержимое
   закрытых дней, каталог предложений, состояние мессенджера и другие данные, не
   необходимые текущему экрану.
3. Опубликованные тексты доступных материалов подгружаются после первой отрисовки
   либо при открытии конкретного материала. Резервный источник также загружается
   только для запрошенного материала.
4. Пустая область вместо контента не считается состоянием загрузки. Если целевой
   материал ещё не получен, оболочка сразу показывает его заголовок и короткое
   понятное состояние загрузки.

## Вход и внутренняя навигация

- Полная проверка пользовательского входа выполняется при входе в личный кабинет.
  Переход между курсом, днём, материалом и встроенным приложением внутри уже
  открытого кабинета не запускает повторный frontend-вход.
- Каждый защищённый API-запрос всё равно проверяет действующую серверную сессию и
  продуктовый доступ. Эта серверная проверка не должна требовать повторного ввода
  логина или отдельной перезагрузки кабинета.
- Прямая ссылка на день или материал проходит тот же контроль доступа, но загружает
  только нужный маршрут, а не весь корпус курса.

## Кеширование и повторные запросы

- Уже полученная структура, текст материала и HTML приложения повторно используются
  в пределах открытой страницы.
- Одновременные запросы одного ресурса объединяются в один ожидаемый запрос.
- Ошибка фоновой загрузки не ломает оглавление и прогресс. При открытии материала
  допускается повторная попытка или загрузка его разрешённого резервного источника.
- Медиа первого экрана и медиа ниже него следуют общему контракту загрузки из
  `ARCHITECTURE.md`: критический элемент загружается сразу, остальное — лениво.
  Lazy load изображений не заменяет отложенную загрузку самих текстов и API-данных.

## Общий загрузчик

Реализация — `backend/app/static/embed.js`, владелец компонента `products`.
Загрузчик не вставляют в Markdown или копию T123: серверный embed подключает его
сам. Белая поверхность, три точки (голубые и золотая), неподвижная область текста
над анимацией; при `prefers-reduced-motion` точки статичны. Статус доступен через
`role=status` и `aria-live`. Авторизация, страница, оформление и материалы — этапы
реальной работы, а не искусственные задержки. Переход внутри курса не показывает
повторную авторизацию. Ошибка останавливает анимацию и даёт кнопку «Повторить».

Полноэкранный экран закрывает начальную загрузку. Для mount с
`data-edabalans-inline="true"` и встроенных фреймов курса загрузчик локален:
родительское оглавление остаётся доступным. Контент скрыт до готовности CSS,
скриптов, зарегистрированного первичного запроса приложения и шрифтов. Медиа
не являются условием готовности всей страницы.

Асинхронное приложение синхронно при запуске регистрирует минимальную готовность:

```js
EdabalansEmbed.waitUntilReady(root, initialScreenRequest);
```

Promise должен завершаться после отрисовки первого полезного экрана; не включать
в него фоновую загрузку корпуса. Сейчас регистрацию используют ЛК и Мастер-класс.
Остальные приложения получают общий экран подключения HTML/CSS/скриптов;
их внутренние асинхронные загрузки остаются продуктовыми до отдельного внедрения
этого lifecycle. Не утверждать, что все формы, админки и подписочные страницы уже
переведены. Форма входа `/lk` использует тот же компонент на время своего запроса.

Локальная загрузка текста материала может использовать
`EdabalansEmbed.loadingHtml('Загрузка материала')`. Это та же анимация, не новая
плашка статьи. Публичные функции `beginLoading`, `finishLoading`, `failLoading`
используются оболочкой входа; её ошибка не считается выходом из сессии. HTML и
запросы CSS объединяются по ресурсу в пределах открытой страницы, не между
пользователями и не вместо серверного контроля доступа.

Мастер-класс запрашивает опубликованное тело только открытого материала через
защищённый `/api/masterclass/course/materials?step_id=...`. Фильтр пересекается
с доступными днями и допустимыми статьями; он не открывает закрытый материал.
Старт дня не запускает общий запрос тел всех статей.

Проверка браузерной границы:
`backend/tests/browser/embed-loading.e2e.mjs` — медленные CSS/данные, отсутствие
неоформленного кадра, общий запрос prefetch/load, повтор после ошибки,
неблокирующее медиа и юридическое подтверждение DQS; настоящая оболочка входа,
готовность ЛК/прямой статьи/анкеты, локальная загрузка встроенного приложения,
повтор после ошибки проверки сессии и режим уменьшенного движения. Проверка
выполняется также в production CI (`test:embed-loading`).

## Приёмка

Перед выпуском нового либо существенно изменённого курса проверить:

1. текущий день появляется до завершения фоновой загрузки материалов;
2. стартовый маршрут не запрашивает тексты всех дней;
3. открытие одного материала не загружает остальные закрытые материалы;
4. повторное открытие материала использует уже полученные данные;
5. медленный или временно недоступный резервный текст не оставляет пустой экран;
6. переходы внутри курса не повторяют полный frontend-вход;
7. прямая ссылка сохраняет тот же доступ и прогресс, что обычная навигация.

Эталон текущей реализации — оболочка Мастер-класса в
`backend/app/static/masterclass-first-days-preview.html`. Продуктовые исключения
фиксируются в runtime-документе конкретного курса и не переписывают этот общий
контракт молча.
