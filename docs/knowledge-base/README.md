# База знаний проекта

Статус: `draft`  
Назначение: человеко- и машиночитаемая память бизнеса edabalans.ru.

Сейчас это навигатор и правила наполнения. Полноценная база знаний ещё не собрана.
ТЗ на её поэтапное создание находится в
`../plans/PROJECT_KNOWLEDGE_BASE_SPEC.md`.

## Модули платформы

| Модуль | Подмодули | Канонический вход |
|---|---|---|
| Telegram-бот | ссылки и источники; start/welcome; цепочки; подписка; рассылки; медиа | `modules/telegram/README.md` |
| Мастер-класс | программа; серверные лекции; прогресс; доступы; точки связи с ботом | `modules/masterclass/README.md` |

Раздел модуля одновременно объясняет владельцу возможности системы и даёт ИИ
маршрут к логике, коду, API и таблицам. Для уже описанного вопроса раздел базы
знаний является каноническим. Старые документы после переноса должны ссылаться на
него, а не поддерживать независимую копию правил.

## Разделы, которые предстоит наполнить

- `POSITIONING.md` — главные тезисы, обещания, ограничения обещаний и стиль коммуникации;
- `METHOD_DQS.md` — каноническое описание «Баланса продуктовых категорий»;
- `modules/masterclass/README.md` — каркас программы, приложения и точки
  взаимодействия мастер-класса с ботом; детальные темы дней ещё предстоит добавить;
- `CONTENT_CATALOG.md` — каталог всех постов и созданных материалов со ссылками;
- `REVIEWS_CATALOG.md` — каталог отзывов и подтверждений;
- `MARKETING_CHANNELS.md` — площадки, рекламные кабинеты, кампании и креативы;
- `SERVICES.md` — используемые сервисы, назначение, владелец и безопасная инструкция
  доступа без хранения паролей и токенов.

Эти файлы не следует заполнять догадками. До подтверждения владельцем новый материал
получает статус `draft`; будущий продукт или решение — `planned`.

## Безопасность и персональные данные

GitHub не должен содержать пароли, токены, ключи, приватные выгрузки, телефоны и email
клиентов. Для отзывов в GitHub допускаются обезличенный ID, публичное имя при наличии
согласия, ссылка на защищённое хранилище и комментарий владельца. Оригинальные
скриншоты и контактные данные должны находиться в закрытом российском хранилище или
CRM с контролем доступа.
