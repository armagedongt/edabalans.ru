# Единый стандарт статей

Статус: `current`  
Владелец: `platform.content`  
Зафиксировано: 26.08.2026

## 1. Область действия

Этот документ определяет структуру и оформление всех текстовых статей сайта:
материалов курсов, страниц интенсивов и следующих форматов статей. Продуктовая
оболочка может добавлять навигацию, служебную строку, прогресс и действия, но не
создаёт второй набор правил для текста статьи.

Специализированное приложение, анкета или интерактивная таблица не становится
статьёй только потому, что открыта внутри той же оболочки.

## 2. Базовая структура текста

- Заголовки и подзаголовки берутся из авторского текста: из заданной структуры
  либо из уже существующей фразы, выражающей смысл раздела. Новые заголовки только
  ради оформления или оглавления не придумываются.
- Один абзац раскрывает одну мысль. Сплошные полотна и искусственный перенос каждой
  фразы на новую строку не используются.
- В авторском Markdown между соседними абзацами оставляются две пустые строки:
  одна завершает абзац, другая даёт рабочую паузу перед следующим. Это правило
  применяется ко всем готовым материалам; фактический интервал на сайте задаёт
  единая визуальная система статьи.
- Маркированный список нужен для равноправных пунктов, нумерованный — только когда
  важен порядок действий или этапов.
- Каждый пункт списка начинается с прописной буквы. Полные предложения
  заканчиваются точкой; короткие однородные формулировки используют одинаковую
  пунктуацию во всём списке.
- Вложенные списки по умолчанию не создаются. Иерархия сначала разделяется
  подзаголовком, затем отдельным списком.
- Изображение вставляется по заданной ссылке без обязательной отдельной подписи.
- Спойлеры по умолчанию не используются. Один большой справочный блок можно
  свернуть, если Сергей явно решил оставить подробности в статье, но не хочет
  прерывать ими основной текст.
- Таблицы, формулы, сравнения «до/после», галереи и другие разовые элементы можно
  предложить для конкретного места, но нельзя вставлять без явного решения
  владельца.

## 3. Разрешённые выделения

В обычной статье используются четыре способа выделения:

1. **Жирное начертание** — ключевая фраза внутри абзаца. Оно сохраняет размер и
   цвет окружающего текста и не превращает каждый абзац в отдельный элемент.
2. **Ссылка** — заметный синий текст со смысловой подписью; голый URL в основном
   тексте не используется без необходимости.
3. **Единая цветная плашка** — один общий визуальный вариант для любых повторяемых
   или разовых акцентов. Семантических цветов «пример», «действие», «ошибка» и
   других отдельных вариантов нет.
4. **Цитата** — самостоятельная сильная фраза с вертикальной акцентной линией.
   Например: «Цель наблюдения — не оценить себя, а увидеть повторяющиеся решения,
   которые действительно влияют на питание».

Правило заголовка цветной плашки:

- если в статье повторяется один тип данных, в заголовке используется его
  фактическое название, например «Размер порций» в материалах DQS;
- если это разовое привлечение внимания, используется заголовок «Важно»;
- другой заголовок применяется только по явному указанию владельца;
- повторяющиеся элементы с одним смыслом получают одинаковый заголовок и один
  визуальный формат.

Этого набора достаточно по умолчанию. Новый постоянный тип выделения не создаётся
для одной статьи: сначала он согласуется и добавляется в этот стандарт.

## 4. Типографика и отступы

Статьи используют `Inter` и только насыщенности `400`, `600` и `800`.

| Элемент | Размер | Насыщенность | Цвет | Межстрочный интервал |
|---|---:|---:|---|---:|
| Основной текст и список | 18 px; на телефоне 17 px | 400 | `#252525` | 1.65 |
| `h1` | адаптивно 38–62 px | 800 | `#252525` | 1.05 |
| `h2` | 29 px; на телефоне 25 px | 800 | `#252525` | 1.2 |
| `h3` | 23 px; на телефоне 21 px | 800 | `#252525` | 1.25 |
| Жирное внутри текста | размер окружающего текста | 600 | `#252525` | как у текста |
| Ссылка | размер окружающего текста | 600 | `#1769D2` | как у текста |

Единые интервалы:

- между соседними абзацами — `18 px`;
- перед `h2` — `44 px`, после него — `14 px`;
- перед `h3` — `32 px`, после него — `10 px`;
- после `h1` до первого содержательного элемента — `28 px`, на телефоне `22 px`;
- у списка сверху и снизу — `20 px`, отступ маркера — `26 px`, между пунктами —
  `8 px`;
- после изображения или основного медиа — `28 px`;
- между двумя соседними плашками — `14 px`, между плашкой и обычным текстом —
  `24 px`.

## 5. Единая плашка и цитата

Цветная плашка использует один централизованный набор токенов:

| Свойство | Значение |
|---|---|
| Фон | `#FFF0E8` |
| Заголовок | `#934329`, 16 px, `600` |
| Основной текст | `#3A2A24`, 17 px, `400`, интервал `1.6` |
| Внутренний отступ | `18 px 20 px`; на телефоне `16 px` |
| Скругление | `16 px` |

Значения заменяются централизованно в этом стандарте, а не отдельно для конкретной
статьи или продукта. Общий runtime-набор токенов для всех поверхностей сайта пока
не реализован; до его появления изменение документа само по себе не обновляет
страницы. При внедрении стандарта реализации обязаны перейти на один общий набор
токенов, а не копировать эти значения в несколько независимых файлов.

Цитата не имеет цветного фона. Слева используется линия `4 px` цвета `#C95B3D`,
отступ текста от линии `20 px`, текст `22 px / 600 / 1.45`, на телефоне `20 px`.
Текст цитаты сохраняет основной цвет `#252525`.

## 6. Техническое представление

Содержание и визуал разделены. Писатель или редактор передаёт Markdown либо
семантический HTML, а публикационный контур сохраняет только разрешённые элементы:
`h2`, `h3`, абзацы, списки, `strong`, `em`, ссылки, цитаты, единую плашку,
изображение и подпись. Главный `h1` берётся из карточки материала и не дублируется
в теле статьи. CSS-классы, размеры и цвета из присланного текста не становятся
источником дизайна; плашка всегда нормализуется к общему классу оболочки.

В Markdown плашка записывается закрытой конструкцией:

```text
:::note [Ориентир]
Текст плашки.
:::
```

Обычные сравнительные данные записываются стандартной Markdown-таблицей. Renderer
оборачивает её в горизонтально прокручиваемый контейнер, поэтому на телефоне
колонки не слипаются и текст статьи не превращается в HTML-код:

```text
| Блюдо | Ккал | Белки, г |
|---|---:|---:|
| Овсянка | 496 | 33,2 |
```

Таблица используется только когда читателю важно сопоставить повторяющиеся поля.
Обычный перечень не превращается в таблицу ради оформления.

Заголовок необязателен; по умолчанию используется «Важно». Соседние строки
одной цитаты `>` образуют один блок с переносами внутри. Обычные строки между
пустыми строками — один абзац, а не набор отдельных `<p>`.

В разделе «Источники» весь текст каждого пункта является ссылкой. Если название
нужно визуально оставить в квадратных скобках, они экранируются внутри подписи:

```text
- [\[Оригинальное название источника\]](https://example.com/source)
```

Скрипты, iframe, обработчики событий и произвольные стили публикационный API
удаляет. Это не редакторская правка текста, а постоянная граница безопасности.
Ссылки, жирное начертание, уровни подзаголовков, списки, цитаты, плашки,
изображения, alt и подписи при этом сохраняются.

В публичном блоге изображения до публикации переносятся в `content/blog/media/`
и объявляются в manifest. Внешние hotlink-изображения и произвольный HTML
блокируют выпуск. Обложка хранится отдельно от тела и не повторяется первой
картинкой внутри статьи.

Большая необязательная справка в материале Мастер-класса записывается закрытым
компонентом. Первая строка — видимый заголовок, остальные строки раскрываются по
нажатию:

```text
spoiler(
Составы блюд и граммовки
**Овсянка:** хлопья — 50 г; банан — 70 г; мёд — 5 г.
)
```

## 7. Пересборка унаследованных материалов в Markdown

Этот режим применяется, когда нужно перенести уже существующий материал курса из
Tilda HTML, опубликованной версии или локального исходника в удобный для правки
Markdown. Его цель — сделать исходник редактируемым, а не написать материал заново.

### Источники и порядок доверия

1. Для уже опубликованного материала сначала снимается его текущая версия через
   course-material API: она определяет фактический текст, медиа и разметку, которые
   видит ученик.
2. Для ещё не опубликованного материала берётся исходный HTML из согласованной
   папки либо явно названный авторский файл.
3. Транскрипт видео используется как контекст и источник недостающего текста только
   после того, как его место в программе и связь с материалом доказаны.
4. Если файл нельзя однозначно сопоставить с `step_id`, он фиксируется в реестре
   кандидатов с кратким объяснением, но не вставляется в курс самостоятельно.

### Обязательный реестр пересборки

Для каждого материала в рабочем реестре указываются: `step_id`, название,
источник и его путь, тип источника (текущая опубликованная версия / HTML /
транскрипт), причина соответствия, наличие медиа и состояние: `исследуется`,
`MD собран`, `готов к просмотру`, `опубликован`.

### Что разрешено менять

Пересборка выполняется в режиме `structure_only`, если Сергей явно не поручил
содержательную редактуру:

- текст, порядок авторских мыслей, ссылки и медиа сохраняются;
- HTML превращается в семантический Markdown: заголовки, абзацы, списки, жирное,
  курсив, цитаты и разрешённые плашки;
- длинные полотна делятся на абзацы, склеенные техническим извлечением слова и
  предложения исправляются только по исходному визуальному материалу;
- заголовки берутся из существующих фраз, а не придумываются ради оформления;
- повторяемые визуальные блоки заменяются понятным редакторским вызовом только при
  наличии уже поддерживаемого публикационного преобразования.

### Последовательность работы

1. Собрать инвентарь файлов и карту соответствия шагам курса.
2. Сохранить текущую опубликованную версию как rollback-снимок до любых изменений.
3. Собрать MD и отдельно зафиксировать, какие визуальные элементы перенесены.
4. Проверить, что видимый текст, порядок, ссылки и медиа совпадают с выбранным
   источником; служебные комментарии, код редактора и мусор извлечения не могут
   попасть в публикационный файл.
5. Открыть готовый MD для локального просмотра. Публикация происходит только по
   прямой команде Сергея, создаёт новую версию материала и не требует code deploy.
6. После публикации один раз проверить номер версии, статус и наличие ожидаемых
   визуальных блоков. Предыдущая версия остаётся доступной для восстановления.
