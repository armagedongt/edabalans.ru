# Статистика единой статьи интенсива

Статус: `current`

Модуль: products.intensive. Техническая редакция: 7 октября 2026. Канонический вход единой статьи: /intensive; архив прежнего меню: /intensive/archive. Счётчик: 97331502; источником будущих анонимных отчётов служит Метрика, не личный прогресс курса. Данные появляются только после реальных открытий; наличие целей не означает запуск рекламы.

## Что измеряется

| Событие intensive_onepage_* | Что означает |
|---|---|
| open | Запустился трекер статьи. Без JS/при блокировщике этот вход может не попасть в счётчик. |
| ready | DOM статьи готов; dom_ms — время до DOMContentLoaded. |
| loaded | Сработал window.load; ttfb_ms/dom_ms/load_ms и число загруженных изображений. Ленивые картинки ниже экрана могут загружаться позже. |
| media_error | Картинка не загрузилась. Передаётся её номер, без полного адреса. |
| view_10 /25 /50 /75 /90 | Эта доля текстовых блоков фактически побывала в видимой области, без области под шапкой. Процент приблизительный, по символам и видимой доле абзацев. Это не доказательство прочтения/понимания. |
| reading_start | Не менее 10 активных секунд и не менее 1% текста показано. Рабочий признак знакомства со статьёй, не доказательство чтения. |
| heading | Конкретный заголовок полностью появился в видимой области ниже шапки: heading_id, heading_title, heading_level. Пропущенные при прыжке заголовки не засчитываются. |
| section | Видна граница раздела; параметр section: block-1/block-2/block-3/actions. |
| end | Конец статьи появился на экране. Переход сразу в конец не выдаёт view_90. |
| active_60 | Накоплена минута на активной видимой вкладке. После 60 секунд без взаимодействия таймер останавливается; фон, потеря фокуса и открытое содержание не считаются. Заголовки закрытой меню статьи тоже не засчитываются. |
| navigation | Нажат раздел шапки или содержания. target — якорь, source — header/contents. |
| contents_open | Открыто содержание. |
| telegram_click / max_click | Нажата соответствующая кнопка. Это ещё не подписка и не покупка. |
| session | Снимок каждые 15 активных секунд и при уходе/скрытии: active_seconds, viewed_percent, max_depth_percent. Повторное чтение может дать несколько обновлённых снимков; их не суммировать. Последняя отправка может теряться при закрытии браузера. |

В каждом событии: page_key=intensive-onepage, article_revision (хеш текущего MD), разрешённые UTM, yclid и alias; visit_id — случайный UUID одного открытия документа, не идентификатор человека. В снимках heading_id/title — последнее показанное место, furthest_heading_id/title — самый дальний показанный заголовок. Каждая процентная отметка и граница раздела — один раз за открытие документа. Новое открытие — новое событие; отчёты по людям/визитам не равны количеству достижений.

Проценты аналитики не связаны с декоративным ускорением полосы сверху. Максимальная глубина прокрутки также отдельный параметр: прыжок в конец может дать 100% глубины при 5% просмотренного текста. Отчёт по section показывает показ границы, а не прочтение блока целиком.

## Как смотреть отчёт

| Строка воронки | Значение | Как считать |
|---|---|---|
| Открыли статью | Появится после публикации | Визиты с open и page_key=intensive-onepage |
| Текст стал доступен | Появится после публикации | Визиты с ready / визиты с open |
| Просмотрели 25%,50%,75%,90% | Появится после публикации | Визиты с соответствующей целью / визиты с open |
| Провели активную минуту | Появится после публикации | Визиты с active_60 / визиты с open |
| Увидели конец | Появится после публикации | Визиты с end / визиты с open |
| Перешли в Telegram / MAX | Появится после публикации | Визиты с кликом / визиты с open; отдельно / визиты с end |

Срезы: источник/канал трафика, utm_campaign, utm_content (объявление), устройство и article_revision. Загрузку смотреть по параметрам loaded: распределение load_ms/ttfb_ms, а не только среднее. Ошибки картинок — по media_error и image_index. Не смешивать старые четыре дня с единой статьёй.

В Метрике использовать отчёт «Конверсии» для целей и «Параметры событий» для дополнительных полей. Цели доступны Директу через тот же счётчик; назначения целей в действующих рекламных кампаниях этим изменением не меняются. Ни один клик не переименовывать в подписку или подтверждённого лида.

## Персональные события для будущих напоминаний

Анонимная статья использует только Метрику. Для подтверждённой сервером сессии дополнительно отправляются факты в существующий /api/intensive/events: intensive_onepage_open, intensive_onepage_section, intensive_onepage_end, intensive_onepage_messenger_click, а также intensive_onepage_reading_start, intensive_onepage_heading, intensive_onepage_progress. Сервер подставляет user_id и platform из подписанной cookie; сохраняет только разрешённые поля. Новые события содержат article_revision, visit_id, viewed_percent, max_depth_percent, active_seconds и заголовки. Названия заголовков сервер берёт из канонического MD; переданное клиентом название и user_id игнорируются. Текущая редакция, UUID открытия, числовые границы и heading_id проверяются. Старая редакция требует перезагрузки. Каждый показанный заголовок и начало — одна запись на открытие; progress — один обновляемый снимок на открытие. Повторы не дублируются, запоздалый снимок не уменьшает накопленные показатели. Новые таблицы не нужны; старые дни, задания и скидка не запускаются.

В `/admin/marketing` → поиск по имени/username/user_id → действия человека видны «Открыл статью», «Начал знакомиться», «Увидел заголовок» и «Просмотр текста»: реальный процент, самый дальний заголовок и активное время. Открытие без reading_start не считается начавшим читать. Без персональной cookie человек остаётся анонимным визитом Метрики; склеивать его с Telegram по догадке нельзя.

Это данные для последующей настройки VSL, а не включённая рассылка. end означает появление конца на экране, не чтение 90%. Нельзя называть такой факт гарантированным прочтением или покупкой. Публичная статья не привязывает анонимного посетителя к боту задним числом. Бот использует уже существующую персональную ссылку i/token; сервер восстанавливает сессию и делает 303 на тот же /intensive с UTM/from/entry, удаляя только секретный код до загрузки аналитики.

При интеграции в серверную оболочку не добавлять второй init/hit для уже подключённого счётчика. Здесь готовый/ожидающий init переиспользуется. Собственный hit получает только разрешённые параметры URL и referrer; это не фильтр автоматических запросов библиотеки Метрики. Поэтому на внешнем адресе с персональным параметром i или token в URL или referrer трекер вообще не запускает аналитику. Обычные рекламные ссылки с UTM и yclid отслеживаются. Канонический персональный вход сначала очищается серверным редиректом; ранний отказ SDK остаётся дополнительной защитой прямых небезопасных URL. Уже запущенный чужой счётчик этим трекером не отключается: при публикации проверить всю оболочку. Общий cookie-компонент и серверный доступ остаются у существующей оболочки.
