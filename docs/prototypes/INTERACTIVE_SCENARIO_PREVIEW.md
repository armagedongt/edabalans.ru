# Интерактивный предпросмотр условных экранов

Статус: рабочий шаблон для согласования до production-разработки.

## Когда применять

Использовать, когда один экран зависит минимум от двух условий: тарифа, этапа,
покупок, доступов, тега или состояния пользователя. Владелец проекта должен иметь
возможность сам переключать состояния и сразу видеть итоговый пользовательский
экран без деплоя.

## Обязательная структура

1. Сверху — только влияющие на результат переключатели.
2. Ниже — один актуальный экран, а не несколько вариантов рядом.
3. Кнопка тестовой покупки меняет состояние и повторно строит экран.
4. Клик по продукту открывает подробное описание в той же области.
5. На странице описания закреплена большая кнопка возврата к выбору и оплате.
6. Временное предложение показывает точную дату окончания и живой таймер.
7. Предпросмотр не выполняет checkout, не пишет в production и не использует
   персональные данные.

## Эталон

`masterclass-offer-simulator.fragment.html` — согласованный пример для предложений
во время мастер-класса. Его не подключать к production напрямую: продуктовые цены,
сроки и доступы в настоящем приложении должны приходить из backend и повторно
проверяться перед оплатой.

При следующих сложных экранах Codex должен сам предлагать такой предпросмотр до
написания production-кода, если это заметно ускорит согласование логики.
