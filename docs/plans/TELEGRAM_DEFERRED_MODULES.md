# Отложенные модули Telegram после первого запуска

Статус: `planned`  
Владелец содержания: Сергей Воронцов  
Проверено: 24.08.2026

Этот файл не описывает уже работающие функции. Он фиксирует сознательно
отложенные части, чтобы они не попали скрытыми ветками в запускной граф.

## Разовые рассылки

Нужен отдельный модуль draft → preview → test recipient → schedule/send → results.
Редактируются текст, медиа и кнопка; сегмент и число получателей обязательно
показываются до запуска. Повторный запуск создаёт новую версию, а не изменяет
историю. До разработки владелец отправляет разовые сообщения через отдельную
команду в рабочем чате; существующий экран админки не считается утверждённым.

## Входящие сообщения в CRM

Желаемое поведение: сообщение, которое клиент пишет боту, появляется в едином
timeline CRM; ответ администратора из CRM уходит тому же человеку через бота.
Не нужна новая таблица диалогов: расширить существующий `tg_manual_messages`
направлением `incoming/outgoing`, Telegram update ID, статусом и reply-to. Файлы
хранятся в российском media storage, а в таблице — ссылка и метаданные. До
реализации нужно утвердить уведомления Сергею и правила рабочего времени.

## Пользовательский timeline и аналитика

Первая версия использует только факты, которые сервер действительно знает:

- first Start и источник;
- назначенные source/post/campaign теги;
- проверки подписки и их результат;
- запланированное и фактически отправленное сообщение;
- нажатие inline-кнопки;
- отслеживаемый переход `go.`;
- доменные события мастер-класса, покупка, доступ, возврат и ошибка доставки.

Telegram не сообщает боту, прочитал ли пользователь сообщение или посмотрел ли
видео, поэтому такие факты нельзя рисовать как достоверные. Новую таблицу событий
не создавать без необходимости: объединить `tg_tracking_events`,
`tg_step_deliveries`, `masterclass_events`, `masterclass_notifications`, payments
и access history в read-only timeline API.

## Сайт, cookie и checkout

Для связи перехода из поста с будущей покупкой нужен first-party browser ID:
отслеживаемая ссылка сохраняет анонимный идентификатор в cookie, а checkout
передаёт его серверу вместе с заказом. Это не требуется для прямого `/start` и не
блокирует запуск бота. Подключение скрипта в шапку Tilda, политика cookie,
30-дневное окно атрибуции и backfill старых событий выполняются отдельной задачей
по `WEBSITE_CLICK_PURCHASE_ATTRIBUTION.md` после явного разрешения владельца.

## Channel invite и чистовой бот

Код создания и приёма уникальных invite links существует. Живой тест и привязка
канал → бот выполняются после переключения на `Fitness_Talks_bot`, когда именно
этот bot token имеет права администратора канала. Смена username/token и основной
бот не входят в текущую разработку каркаса.

## Не входят

Лотерея, тесты, опросы, MAX и новые мини-приложения — самостоятельные будущие
модули. Для каждого сначала создаются канонический текст и Mermaid-схема.
