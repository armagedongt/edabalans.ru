# Очередь будущих изменений

Статус: `current`
Проверено: 25.08.2026
Назначение: только то, что владелец явно решил реализовать позже.

## Что считается планом

План появляется после прямой команды «положи в планы» или ясного решения «это делаем
потом». Фразы «интересная идея», «может быть», исследование, незаконченная ветка и
не выполненный deploy автоматически планом не становятся.

Короткое пожелание добавляется в `QUICK_NOTES.md`; крупная задача получает отдельный
файл. Можно спросить «Что у нас в планах?» — Wiki/чат сгруппирует активные записи по
`module_id`.

## Обязательные метаданные нового плана

```yaml
---
document_status: planned
date: 2026-08-25
module_id: products.masterclass.offers
origin: owner-explicit
---
```

Вместо `module_id` допускается `cross_project: true`, если решение действительно
затрагивает всю платформу. Нельзя ставить `origin: owner-explicit` без явного решения
владельца. `planned` означает будущее, а не текущее состояние реализации.

Когда работа начинается, активный контекст живёт в `work/`. После реализации
устойчивый факт переносится в module card/канонический документ, а plan получает
`document_status: archived` и ссылку на новый источник истины. Историческая
подробность может остаться в архивном файле; её не нужно стирать или выдавать за
production status.

## Исторические документы

Старые plan-файлы появились до обязательных metadata. Их источники и классификация
зафиксированы в `PLAN_SOURCES_AUDIT.md`. При первом содержательном изменении такой
файл нужно либо подтвердить с владельцем и привести к схеме выше, либо архивировать
как историю. Нельзя молча приписывать старому документу `owner-explicit`.

ТЗ прежней ручной Wiki и ручной карты закрыты текущей модульной системой:

- `PROJECT_KNOWLEDGE_BASE_SPEC.md` — archived, заменён Git-backed карточками и Wiki-view;
- `PROJECT_DOCUMENTATION_SYSTEM.md` — archived, заменён registry, generator и CI audit.

Остальные исторические статусы не нормализуются вслепую: отдельно сохраняются
`document_status` и пояснение о состоянии внедрения, чтобы не потерять полезный
checkpoint.
