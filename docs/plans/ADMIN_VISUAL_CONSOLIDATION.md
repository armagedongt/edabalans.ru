# Следующий этап: единый вид административных экранов

Владелец попросил отдельно проработать CRM и админки: единый фон, каркас и
визуальные правила вместо разрозненных интерфейсов. Это будущая работа, не
заявление о выполненном редизайне и не новая предметная база данных.

## Граница

Вход — `../ADMIN_ARCHITECTURE.md` и карточка `admin.control`. CRM сохраняет
владельца `platform.crm`, вход/сессии — `platform.auth`, цены/оплаты —
`platform.commerce`, курс — его продуктовый модуль. Общие визуальные предпочтения
принадлежат `platform.web_design`. Нового модуля «всё административное» не создаём.
Состав поверхностей берётся из `../modules.toml` (`admin_catalog`) и фактических
переходов экранов, а не из ещё одной ручной карты.

## Порядок

1. Сверить маршруты, общий CSS/компоненты, локальные исключения и активные потоки.
   Отдельно различить экраны, API публикации и предметную логику.
2. Найти прежние решения в архивном `ADMIN_UX_UNIFICATION_SPEC.md`;
   не трактовать его историческую отметку «реализовано» как подтверждение качества
   текущего визуала. Ничего не проектировать заново без проверки существующего.
3. Показать владельцу один общий каркас и согласовать фон, шапку/навигацию,
   типографику, формы, таблицы, статусы, кнопки и мобильное поведение.
4. После выбора определить владельцев переиспользуемых компонентов и переводить
   экраны последовательно. Не копировать CSS каждой админке и не вмешиваться в
   продолжающуюся работу дизайна/цен/платежей.
5. Проверить навигацию, авторизацию, чтение/сохранение и адаптивность. В той же
   работе обновить каноны и карточки затронутых модулей; старые реализации удалять
   только после перевода потребителей и проверки ссылок/данных.

## Не входит автоматически

- смена входа, платежной настройки или прав пользователей;
- изменение/удаление данных CRM, версий курса или прогресса;
- удаление редакторских API из-за отказа от их экранов;
- редизайн внешнего NocoDB и создание его копии;
- удаление веток, рабочих копий и архивирование продолжающихся задач.

Результат — общий визуальный набор и согласованные исключения при сохранении
предметной логики отдельных модулей. Объём первого выпуска определяется после
сверки экранов и согласования, не этим предварительным планом.
