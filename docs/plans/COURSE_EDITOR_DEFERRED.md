# Отложенные функции редактора курсов

Статус: `planned`

Первая рабочая версия редактора намеренно меняет только атрибуты существующей
структуры. Ограничения ниже приняты владельцем, чтобы быстрее запустить безопасный
редактор без миграции уже сохранённого прогресса участников.

## Пока выполняется через чат

- добавление и удаление материалов;
- перестановка материалов и дней;
- создание и изменение технического типа системных шагов, приложений и офферов;
- массовая перестройка правил прохождения после изменения состава программы;
- редактирование полного тела статьи.

Материал можно скрыть и вернуть из редактора. Скрытие не удаляет запись и прогресс,
не сдвигает позиционные индексы и сразу исключает материал из клиентского интерфейса
и обязательных условий прохождения.

## Сверка с действующим кодом на 17.09.2026

Часть исходного списка уже не является будущей работой:

- публикация Markdown/HTML и восстановление версий материалов реализованы в
  `backend/app/course_material_routes.py`; CLI — `tools/publish_course_material.py`;
- общий редактор структуры обслуживает МК и калорийный курс через
  `backend/app/course_structure_routes.py`;
- версионный продуктовый каталог имеет собственный маршрут
  `backend/app/product_catalog_routes.py`; цены принадлежат `platform.commerce`.

Это проверка текущего принятого кода, не отдельное подтверждение server revision.
Структурный редактор, API публикации текста и интерфейс редактуры — разные
компоненты. Новую визуальную админку или кнопку Obsidian нельзя считать готовыми
на основании наличия API; не создавать повторно уже реализованный publisher.
Текущий канон — карточка `products.masterclass.course` и её источники.
Пути к коду выше относительны к корню проекта.

## Оставшиеся расширения

1. Отдельный удобный интерфейс редактуры тел материалов с безопасной публикацией
   и предпросмотром, если владелец сохраняет этот запрос. Наличие API/CLI не
   закрывает запрос интерфейса; его место следует согласовать с рабочим форматом
   Markdown и новым этапом унификации админок.
2. Добавление/удаление/перестановка материалов после перехода прогресса на схему,
   устойчивую к изменению состава курса, либо через управляемую миграцию.
3. Подключение остальных курсов, если они появятся в согласованном составе.
   Уже подключённый калорийный курс повторно реализовывать не требуется.

Эти расширения не должны добавляться в текущий редактор частично или вторым источником
данных. Перед реализацией нужно определить влияние на runtime, прогресс, продажи и
зависимые события.
