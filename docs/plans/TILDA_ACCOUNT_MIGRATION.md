# Перевод прежних пользователей Tilda в собственный вход

Это отдельный будущий этап. Текущий запуск новых покупателей не рассылает
сообщения старым пользователям и не отключает их вход через Tilda Members Area.

## Маршрут

1. Получить из существующей CRM перечень прежних пользователей и их единый
   `user_id`; не импортировать права из Tilda повторно.
2. Для каждого пользователя без собственных credentials создать одноразовую
   24-часовую ссылку выбора Telegram или MAX.
3. Разослать ссылку по подтверждённому каналу связи после отдельного разрешения
   Сергея на массовую отправку.
4. Выбранный мессенджер выдаёт логин и пароль к тому же кабинету и тем же правам.
5. После подтверждённой миграции пользователя перестать показывать ему Tilda как
   основной вход; старые необновляемые материалы оставить отдельной ссылкой.
6. Когда мигрированы все нужные пользователи, заменить старый вход редиректом на
   канонический `/lk`. Старые URL должны продолжать приводить к работающему входу.
7. Закрыть прямые legacy API с email-параметром на `app.edabalans.ru`, оставив
   доступ к материалам только через серверную сессию.

## Черновик сообщения

**У личного кабинета появился новый вход.**

Ваши покупки, доступы и прогресс никуда не пропали. Нажмите кнопку ниже и
выберите Telegram или MAX — бот пришлёт логин и пароль от того же личного
кабинета.

Ссылка действует 24 часа. Если она перестала работать или что-то не получилось,
напишите Сергею.

## Обязательные проверки перед рассылкой

- свежий backup PostgreSQL и проверенное восстановление;
- тест на одном аккаунте Сергея;
- отсутствие второго `user_id` и дублирования прав;
- работа старого входа Tilda во время перехода;
- отдельное явное подтверждение массовой рассылки.
