# Telegram-бот: изменения следующих версий

Статус: `planned`  
Фактическое текущее поведение: `../TELEGRAM_BOT_CURRENT_LOGIC.md`.

## Надёжность логики

- Связать перестановку шагов с фактическими `tg_sequence_edges`, чтобы визуальный
  порядок и исполняемый маршрут не расходились.
- Запретить прямое изменение опубликованной версии: править draft, валидировать и
  публиковать новую версию; уже запущенные пользователи остаются на старой версии.
- Добавить отдельную команду публикации и запрещать публикацию при ошибках карты:
  недостижимые блоки, отсутствующие ветки, битые переходы, контент или задержки.
- Формировать описание условий запуска цепочки из фактических маршрутов и условий, а
  не из захардкоженного поясняющего текста.

## Пользователь и покупки

- Реализовать безопасное объединение Telegram-ID и покупателя, найденного по email.
- Согласовать статусы `paid` и `confirmed` для проверок мастер-класса.
- Наполнить и опубликовать `postpurchase_masterclass` с допродажами рецептов, калорий и
  консультации.
- Добавить безопасные действия из CRM: пауза, продолжение, остановка и перезапуск
  цепочки выбранного пользователя.
- Добавить повтор упавшей доставки и аудит каждой ручной команды: администратор,
  пользователь, действие, время и результат.
- Определить поведение импортированных старых пользователей: использовать ли
  `main_scenario_seen_at`/исторический тег первого посещения для показа оглавления без
  повторного приветствия.
- После любой подтверждённой покупки централизованно назначать бизнес-тег
  `Стоп - До покупки мастер-класса`, завершать активную цепочку до покупки и не
  дублировать этот блок во всех источниках продаж.
- Поддержать независимый ручной тег `Стоп - После покупки мастер-класса` для
  остановки послепродажной цепочки.
- Зеркалировать компоненты подтверждённой покупки в видимые теги `Мастер-класс`,
  `Рецепты`, `Калории`, `Консультация`, `Сопровождение`, `Тренировки`,
  `Записи консультаций`.

## Подписка и аналитика

- Реализовать настоящую проверку подписки через Telegram Bot API для чистового бота.
- Добавить ветку подписан/не подписан, пост-приманку и продолжение без блокировки
  основной цепочки.
- Перенести результат проверки в `messenger_accounts.subscription_status` и
  `subscription_checked_at`.
- При каждой проверке синхронизировать взаимоисключающие видимые теги `Подписан`,
  `Не подписан`, `Отписался`.
- При первом входе различать `Первое посещение - Уже подписан` и
  `Подписался после просьбы бота`; условия назначения должны быть видны на карте.
- Связать tracking token с `attribution_events`, покупкой и выручкой; добавить
  статистику по площадке, размещению и кампании.
- Разрешить правилам tracking link явно назначать бизнес-тег и выбирать стартовую
  опубликованную цепочку без скрытых условий в Python.
- При необходимости добавить защиту уникальности кликов без хранения лишних
  персональных данных.

## Первое сообщение и навигация

- При первом входе отправлять редактируемое приветственное и навигационное
  сообщение, сохранять его `message_id` и закреплять в личном чате с ботом.
- Позволить менять текст и кнопки из админки, после публикации обновлять сохранённое
  сообщение у пользователя через Telegram API.
- Ошибку редактирования или закрепления показывать в журнале, не останавливая
  основной сценарий.

## Коммуникации и каналы

- Сохранять входящие сообщения и показывать историю диалога в общей CRM.
- Сделать полноценную сегментацию рассылок по тегам, покупкам и доступам.
- Добавить независимый MAX-адаптер поверх общей бизнес-логики после отдельного
  проектирования интерфейса каналов.
