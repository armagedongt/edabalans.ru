# Telegram: атрибуция пути «ссылка → канал → бот»

Статус: `approved_draft`, **ещё не реализовано**  
Дата фиксации: 22.08.2026  
Связанный модуль: `TELEGRAM_START_LINKS_SPEC.md`

## 1. Цель

Определить источник человека, который сначала вступил в Telegram-канал по
отслеживаемой ссылке, а спустя время открыл основного Telegram-бота. Источник
должен связаться с тем же CRM-пользователем по стабильному Telegram user ID.

Это отдельный тип назначения ссылки `channel_invite`, но управляется в общем
приложении `Ссылки и источники`.

## 2. Как Telegram позволяет это сделать

1. Наш бот назначается администратором канала с правом приглашать пользователей.
2. Через Bot API `createChatInviteLink` бот создаёт дополнительную уникальную
   invite-ссылку канала для источника/размещения.
3. При вступлении через неё Telegram может прислать `chat_member` с полем
   `invite_link`. Бот должен быть администратором канала и явно подписаться на
   update `chat_member`.
4. Более строгий вариант создаёт ссылку с `creates_join_request=true`. Telegram
   присылает `chat_join_request`, содержащий пользователя и `invite_link`; бот с
   правом `can_invite_users` может сразу одобрить заявку.
5. Система находит правило по точной invite-ссылке и сохраняет Telegram user ID,
   источник, размещение, кампанию, настроенный тег и время вступления.
6. Когда этот же человек позднее запускает `@Fitness_Talks_bot`, совпадает
   Telegram user ID. Сохранённая атрибуция присоединяется к его общему `user_id`.

Официальная основа Bot API:
`https://core.telegram.org/bots/api#chatmemberupdated`,
`https://core.telegram.org/bots/api#chatjoinrequest`,
`https://core.telegram.org/bots/api#createchatinvitelink`.

## 3. Что работает и что не работает

Работает:

- человек реально вступил по уникальной invite-ссылке;
- либо отправил join request по такой ссылке;
- бот является администратором канала и сам создал/контролирует ссылки;
- позднее пользователь запускает бота под тем же Telegram-аккаунтом.

Не гарантируется:

- простой просмотр публичного канала без вступления;
- переход по обычному `https://t.me/Fitness_Talks` без уникальной invite-ссылки;
- человек уже состоит в канале: повторное открытие другой ссылки не создаёт новое
  событие вступления;
- человек вступил до подключения функции и события не было в нашей базе;
- переход с одного Telegram-аккаунта и запуск бота с другого.

Система не должна обещать атрибуцию клика по каналу. Она фиксирует подтверждённое
вступление/заявку и последующий старт бота.

## 4. Рекомендуемый режим

Сначала проверить на тестовом канале обычную дополнительную invite-ссылку и update
`chat_member`: это не добавляет пользователю этап подтверждения.

Если Telegram не передаёт invite-link достаточно стабильно для фактического типа
канала, включить режим join request:

```text
короткая ссылка
→ уникальная invite-ссылка с заявкой
→ chat_join_request с user ID и invite_link
→ сохранить источник
→ автоматически одобрить
→ пользователь читает канал
→ позднее открывает бота
→ источник связывается по Telegram user ID
```

Join request надёжнее для атрибуции, но создаёт дополнительный пользовательский шаг,
поэтому не включать его всем без сравнительного теста.

## 5. Как будут выглядеть ссылки

Telegram сам выдаёт invite-ссылку вида `https://t.me/+<длинный_код>`. Её можно
использовать напрямую, но для публикации владелец хочет короткую брендированную
форму.

Рекомендуемый адрес:

```text
https://go.похудение-это-есть.рф/<короткий_код>
```

Он мгновенно перенаправляет в соответствующую Telegram invite-ссылку канала.
Отдельный `/c/` или `/b/` не требуется: назначение кода (`channel_invite` либо
`bot_start`) хранится в БД. Для открытия бота может использоваться тот же формат:

```text
https://go.похудение-это-есть.рф/<короткий_код>
```

Так сохраняется публичный бренд сайта, но динамический redirect работает на нашем
сервере. Основной домен сейчас обслуживается Tilda, поэтому произвольный путь
`https://похудение-это-есть.рф/t/<код>` нельзя направить на FastAPI одним DNS:
DNS не маршрутизирует отдельные URL-пути. Поддомен `go.` — простое независимое
решение. Альтернатива — `go.edabalans.ru`.

## 6. Одна запись — только нужные формы

Создание правила не обязано генерировать и показывать все возможные URL. В форме
владелец выбирает назначение:

- `Открыть бота`;
- `Открыть канал и запомнить источник`;
- позднее другой внешний URL.

И отмечает нужные формы вывода:

- оригинальная Telegram-ссылка;
- короткая через `go.похудение-это-есть.рф`;
- при необходимости короткая через `go.edabalans.ru`.

В базе остаётся одна запись правила и одна фактическая Telegram invite/deep link.
Неиспользуемые формы можно вообще не показывать. Сотни ссылок для рекламы — обычные
строки данных, но интерфейс должен группировать их по площадке/кампании, архивировать
завершённые и не смешивать с постоянными главными ссылками.

## 7. Данные и события

Нужны сущности примерно следующего назначения:

- правило ссылки: код, назначение, источник, размещение, кампания, теги, активность;
- Telegram invite: chat ID, полная invite-ссылка, режим join request, creator,
  срок/лимит, revoked;
- событие канала: Telegram user ID, правило, `join_request`/`joined`/`left`, время;
- отложенная атрибуция: Telegram user ID до первого запуска бота;
- связь с `attribution_events` CRM после появления/нахождения общего `user_id`.

Теги источника, размещения и кампании назначаются идемпотентно и не
перезаписываются. Вступление по другой ссылке добавляет её канонические теги и
событие атрибуции, но не создаёт дубли. Отдельное поле `последнее касание` не нужно.

## 8. Раздел приложения

В `Ссылки и источники` добавить отдельную вкладку:

```text
Переходы в канал
├── создать источник/размещение
├── создать Telegram invite
├── скопировать выбранную короткую форму
├── вступили / позже запустили бота
├── конверсия вступление → бот
└── архивировать / отозвать invite
```

Ссылка на конкретный старый пост хранится как комментарий/placement, а не как
отдельная логика сценария.

## 9. Текущие пробелы реализации

- `TelegramClient.get_updates()` сейчас запрашивает только `message` и
  `callback_query`; события `chat_member` и `chat_join_request` не принимаются.
- бот ещё не настроен администратором чистового канала для этой функции;
- нет таблиц invite-ссылок, событий вступления и отложенной атрибуции;
- нет API создания/revoke invite-ссылки и обработки join request;
- нет вкладки приложения и статистики `вступил → запустил бота → купил`.

## 10. Что уточнить перед реализацией

1. Добавлять в администраторы канала основного production-бота или отдельного
   служебного бота. Рекомендация: основной бот, чтобы не плодить инфраструктуру.
2. Сначала тестировать обычное вступление или сразу join request. Рекомендация:
   обычное вступление, затем резервный тест join request.
3. Подтвердить публичный короткий домен. Рекомендация:
   `go.похудение-это-есть.рф`.
4. Определить срок хранения активных рекламных invite-ссылок. Архивирование не
   должно удалять исторические события.
5. Для каждой записи автоматически создавать или переиспользовать выбранные теги
   источника, размещения и кампании; специальный общий тег `Пришёл через канал`
   не требуется.

## 11. Проверки будущей реализации

- два источника создают разные invite-ссылки и разные события;
- неизвестная invite-ссылка не назначает выдуманный источник;
- повторное событие идемпотентно;
- уже подписанный пользователь не считается новым вступлением;
- Telegram user ID связывается при старте бота спустя любое время;
- первый источник не перезаписывается;
- отозванная ссылка не теряет историю;
- потеря прав администратора даёт видимую ошибку мониторинга;
- бот не отправляет сообщение человеку без обычного `/start`, кроме отдельно
  согласованного поведения join request.
