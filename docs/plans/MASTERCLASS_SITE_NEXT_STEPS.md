# Серверный Мастер-класс: статус и точка возврата

Статус: `current_status_with_planned_followups`
Зафиксировано: 23.08.2026
Владелец содержания: Сергей Воронцов

## Что уже работает в реализации

- единая Tilda-вставка приложения и общий вход с проверкой `ACCESS_MASTERCLASS`;
- программа на 21 день с заметными редакционными заглушками;
- строгий порядок статей, анкеты, приложений и выделенных предложений;
- серверный прогресс дней/шагов, задания, ручные галочки и 20-часовой таймер;
- DQS завершается первым успешным серверным сохранением;
- анкета и саморевью завершаются после отправки;
- приложения рецептов и динамические предложения встроены в программу;
- точки предложений дней 1, 15, 17, 19 и 21 получают персональное состояние,
  актуальные товары, цены и сроки с backend;
- события курса сохраняются для будущего `postpurchase_masterclass`, но реальная
  Telegram/MAX-отправка выключена;
- `content/masterclass/course/course.json` стал единственным исполняемым источником
  порядка; HTML и Python больше не содержат отдельные списки дней и шагов;
- сайт создаёт due-сигналы `course_stalled_72h` и `sales_last_chance_due`, а
  Telegram-приёмник повторно проверяет доступ, прогресс и покупки; dispatcher
  остаётся выключенным;
- манифест и материалы доступны клиентскому frontend по email закрытой страницы
  Tilda только после серверной проверки `ACCESS_MASTERCLASS`.

## Следующая работа по сайту после Telegram-заготовок

1. Разнести наполнение на стабильные идентификаторы материалов и отдельные
   опубликованные/черновые версии; сохранить текущие URL Tilda CDN без скачивания.
2. Добавить административный просмотр структуры и прогресса; редактирование
   текстов оставить отдельным безопасным этапом draft → preview → publish.
3. Заменять заглушки по мере получения авторских материалов, не меняя ID и
   порядок соседних шагов без отдельного решения.
4. Подставить настоящий URL главной Members Area в короткий код Tilda и проверить
   один штатный `ST100` на странице.
5. Отдельно решить идею открытия в 06:00 по местному времени. До решения остаётся
   серверное правило 20 часов.
6. Позднее отдельной задачей перенести изображения с Tilda CDN в object storage;
   первый запуск это не блокирует.

## Граница с Telegram/MAX

Сайт и курс создают факты и вычисляемые due-сигналы. Messaging backend решает,
нужно ли сообщение, выбирает канал и шаблон, повторно проверяет покупки и хранит
доставку. Каноническая заготовка приёмника находится в
`docs/knowledge-base/modules/telegram/POST_PURCHASE_MASTERCLASS.md`.

## Что не делать при продолжении

- не включать production dispatcher из задачи сайта;
- не создавать вторую таблицу пользователей или прогресса в Telegram;
- не хранить цены, тексты сообщений и задержки во frontend;
- не менять production Tilda, hooks или клиентские данные без отдельного
  подтверждения владельца.
