Статус: НЕ ВНЕСЕНО В ПРОДАКШЕН


1. Защита от открытия приложения без активного пользователя или даты старта


Добавить единый guard перед основным рендером.


Предлагаемая функция:


function ensureValidSession() {
  if (!currentUser || !currentUser.email) {
    showLogin();
    return false;
  }


  if (!currentUser.startDate) {
    showStartDate();
    return false;
  }


  return true;
}


И добавить проверку в начало renderCurrentView():


function renderCurrentView(preserveScroll = true) {
  if (!ensureValidSession()) return;


  const y = window.scrollY;


  if (currentView === 'scores') {
    renderScores();
  } else {
    renderDiary();
  }


  if (preserveScroll) {
    requestAnimationFrame(() => window.scrollTo(0, y));
  }
}


Задача: даже при редком сбое состояния приложение не должно пытаться отрисовать дневник без currentUser/email или startDate. Поведение должно быть строго таким:
— нет активного пользователя/email → экран входа;
— пользователь есть, но startDate нет → экран выбора даты;
— есть пользователь и startDate → основной интерфейс.


2. Защита от запоздалого ответа saveDay после выхода или смены пользователя


При начале saveDayToGoogle() сохранить email/идентификатор текущей сессии в локальную переменную. После возврата ответа от Apps Script перед изменением appDays, dirtyDays, saveStatusText и вызовом renderCurrentView() проверить, что текущий пользователь всё ещё существует и его email совпадает с email, для которого был начат запрос.


Задача: сценарий «сохранение началось → пользователь нажал Выйти → старый запрос вернулся позже» не должен менять состояние уже закрытой/новой сессии.


3. Убрать лишний текст из справки категорий


В openCategoryHelp() удалить нижнюю строку:


«Если забудете, как пользоваться DQS, инструкцию всегда можно снова открыть по ссылке „Как пользоваться“ внизу дневника.»


То есть убрать блок .dqs-help-reminder из HTML справки категорий. Саму ссылку «Как пользоваться» в общем футере приложения оставить.


Примечание: после удаления этой строки CSS-класс .dqs-help-reminder станет неиспользуемым; при чистке кода его тоже можно удалить.


4. Автоматически определять email пользователя из авторизации Tilda Members Area


Проверочная схема работает: на закрытой странице Tilda Members Area можно автоматически определить email уже авторизованного пользователя без отдельной авторизации внутри DQS.


Целевая логика для следующего обновления клиентского DQS:
— страница DQS доступна только авторизованным пользователям нужной группы Tilda;
— фронтенд автоматически определяет email текущего пользователя из данных страницы / Members Area;
— пароль Tilda нигде не читается, не передаётся и не используется;
— отдельное поле ручного ввода email в DQS больше не нужно как основной сценарий;
— на промежуточном экране показать: «Вы входите как: user@email.ru» и кнопку «Войти»;
— после нажатия кнопки использовать автоматически определённый email для существующего openUser();
— Apps Script по-прежнему обязан отдельно проверить этот email через Allowed_Emails — доступ к странице Tilda не заменяет backend-проверку;
— если email автоматически не определён, показать понятное сообщение об ошибке и предложение написать Сергею; не пытаться открывать дневник без email;
— после стабильной проверки промежуточный экран подтверждения можно полностью убрать и открывать DQS автоматически.


Задача: использовать единую авторизацию Tilda для всех клиентских сервисов и не заставлять пользователя повторно вводить email/пароль в каждом приложении.


Важно для безопасности: email, полученный фронтендом, является удобным идентификатором пользователя, но backend не должен доверять ему без собственной проверки Allowed_Emails.


5. Собственная кнопка профиля Tilda вместо плавающего кружка


Добавить в код клиентского DQS собственную кнопку открытия профиля Tilda через ссылку:


<a href="#openmembersbar">...</a>


Наличие такой ссылки на странице должно использоваться вместо стандартной плавающей кнопки Members Area, чтобы круглая кнопка Tilda не перекрывала интерфейс приложения.


Требования к расположению и виду кнопки:
— разместить кнопку профиля в верхней панели DQS справа, правее блока/заголовка DQS;
— основной блок DQS при необходимости немного сдвинуть влево, чтобы справа освободилось место под кнопку;
— использовать обычную стандартную иконку человека/профиля, не emoji;
— иконка должна быть визуально нейтральной, компактной и соответствовать общей цветовой схеме приложения;
— по нажатию кнопка должна открывать стандартное меню профиля Tilda Members Area через #openmembersbar.


Также обновить туториал DQS: добавить короткое пояснение, что кнопка с иконкой профиля в правом верхнем углу открывает меню профиля внутри сайта.


Задача: убрать мешающую обзору стандартную плавающую кнопку Tilda, при этом сохранить пользователю быстрый доступ к меню профиля непосредственно из интерфейса DQS.
