# Шаблон редакционного MD рецепта

Модуль: `platform.content`. Применять вместе с
[протоколом рецептов](recipe-authoring-v1.md).
Ниже каркас для копирования, а не готовый материал. Удалить указания в квадратных
скобках и незаполненные необязательные разделы. Данные карточки заполнить по
`content/masterclass/recipes/README.md`, не создавать новую схему.

```markdown
# [Название блюда]

[Что за блюдо, почему стоит попробовать, чем отличается и какую задачу решает.
Один предметный абзац: точное преимущество блюда, без повторения заголовка/состава и пересказа приготовления
и декоративного обещания вкусного результата.]

**Роль в конструкторе:**

- [x] Белок
- [ ] Гарнир
- [ ] Объём
- [x] Вкус
- [x] Сочность
- [ ] Топпинги

recipe_card(
[Проверенный путь существующей согласованной карточки]
[Название на карточке]
)

## [Что это за блюдо / объяснение идеи — если нужно]

[Краткое объяснение незнакомого блюда или формата перед действиями.

## Как приготовить

1. [Первое действие и нужный контроль.]
2. [Следующее действие.]
3. [Доведение и подача.]

[Если есть выбранные фотографии приготовления — поставить здесь изображения
без отдельного заголовка и поясняющих подписей. Если фотографий нет — убрать.]

## Что добавить

[Для блюда/основы с недостающими частями: что добавить для основного приёма
пищи. Отдельно — необязательные вкусовые акценты. Добавки вне состава не входят

блок использования/порции; если раздел не нужен — убрать.]

## Как подать

[Подтверждённые варианты подачи с учётом недостающих частей: что смешать,
что положить рядом, какую оболочку использовать. Если не требуется — убрать.]

## Особенности

конкретный аргумент пищевой ценности, если уместен. Здесь же — действительно
важные нюансы хранения и разогрева этого блюда, без одинаковых банальных
советов. Без повторения карточки, шагов и приписок о примерном весе/порциях.
Убрать, если не нужен.]
```

Для этапа «только MD» без готовой карточки вместо `recipe_card(...)` оставить
скрытый комментарий `<!-- Карточка ожидает согласованных фото и сборки. -->`;
точный расчёт и текст «Коротко» уже вести в данных этого MD. Не создавать
пустую ссылку на несуществующий WebP. Редактору передать данные карточки вместе
с читательским текстом; Сергею отдельно показать нерешённые части.

Статусы в примере даны для мясной основы; заполнить их по конкретной порции,
не копировать готовые отметки в другой рецепт. Использовать `- [x]` / `- [ ]`
без эмодзи по существующему Markdown-контракту. Форма подачи не часть этого списка.
В MD сохранять этот порядок одним списком; на компьютере показывать в три
колонки, на телефоне — в две. Назначение не дублировать отдельной строкой после
списка; необходимые дополнения объяснять в «Что добавить». Короткий аргумент
выбора продукта допустим рядом с ролью без отдельного заголовка.

В семействе рецепт/вариант получает свою карточку и следующие за ней шаги,
без повторной общей мотивации перед каждым вариантом. Способ обработки продукта
оформляется как текстовая инструкция по продуктовому стандарту: без этой
карточки и без выдуманного КБЖУ.

Происхождение, список изменений, кандидаты фото и review хранить в приватных
редакционных артефактах. Публичное тело не заканчивается внутренним отчётом.
