# Контракт библиотеки авторских приёмов v1

Статус: `current`  
Модуль: `platform.content`

Это контракт хранения и поиска доказательств, а не второй свод правил письма.
Нормативное поведение писателя определяет только `writer-contract-v1.md`.

## Назначение

Библиотека хранит проверенные функциональные части авторских текстов и помогает
писателю найти несколько разных способов выполнить конкретную работу: начать,
создать узнавание, нарастить ставку, развернуть аргумент, объяснить, пошутить,
доказать компетентность, привести к продукту, вызвать комментарий или закончить.

Она не является словарём для автоматической вставки и не заменяет полные
эталоны. Текст используется как source-linked доказательство механики.

## Два разных слоя

### Candidate layer

Дешёвая локальная нарезка по всему пригодному корпусу. Статус только
`candidate_unreviewed`. Кандидат может быть бесполезным, неправильно ограниченным
или зависеть от соседнего абзаца.

### Reviewed layer

Фрагмент прочитан вместе с контекстом и получил функцию, механизм, границы
применения и provenance review. Только этот слой доступен писателю по умолчанию.

Имя файла, таблицы или поля не должно создавать видимость semantic review для
механических кандидатов.

## Правила поиска

1. По умолчанию искать только `semantic_reviewed` и owner correction chains.
2. Площадка — мягкий фактор ранжирования, а не отдельный голос.
3. Возвращать 3–5 разных механик, а не верхние почти одинаковые фразы.
4. Всегда показывать источник, соседний контекст, функцию, границу и
   медиа-зависимость.
5. Непроверенный кандидат доступен только явным режимом исследования.

## Корректирующий кейс

Correction chain хранит:

```text
запрос → retrieval pack → версии ИИ → замечания владельца
→ owner final → функциональное объяснение → область действия
```

Финал владельца имеет `owner_final`, но опечатки и пунктуационные ошибки
нормализуются отдельно и не становятся голосовыми правилами.

## Экономия

Локально выполняются извлечение, дедупликация, хэширование и выбор партии.
Семантический review кэшируется по `text_hash + taxonomy_version +
review_prompt_version`. Насыщение фиксируется по новым механикам; бесконечное
расширение и повторный обход источников запрещены.
