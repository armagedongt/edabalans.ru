## С чего начинать

**Для любого чата, который пишет или правит текст, главный вход —
[edabalans-writer/SKILL.md](skill/edabalans-writer/SKILL.md).** Это и есть
инструкция Писаря, не ещё один агент с собственной памятью. Этот README — карта
существующего контура для человека и выбор дополнительных источников для навыка.
Ни весь каталог, ни вся история ниже не загружаются в каждую задачу.

- [Маршруты реальных задач](#маршруты-реальных-задач) — что подключать к Писарю.
- [Адаптация по площадкам](platform-adaptation-v1.md) — Telegram, MAX, Pikabu,
  сайт, уроки, бот, VSL и реклама; читать нужную ветвь, не весь контур.
- [Источники и библиотеки](#источники-и-библиотеки) — что считается фактом,
  голосом, примером или историей.
- [Публикация и готовность](#публикация-и-готовность) — что уже работает,
  что осталось прототипом.
- [Предыдущие разборы и продолжение](#предыдущие-разборы-и-продолжение) — откуда
  взяты решения; это не новый свод правил.

## Маршруты реальных задач

Сначала профиль и разрешения по [рабочим профилям](authoring-work-profiles-v1.md)
и [режимам редактуры](editing-modes-v1.md), затем поверхность из таблицы. Строки
не создают новые профили. Во всех содержательных маршрутах действует один
[контракт голоса](writer-contract-v1.md), а работа с наборами материалов ведётся
по [общему протоколу таблица + MD](../../docs/knowledge-base/CONTENT_COLLABORATION_STANDARD.md).

`author_workflow.py` в таблице означает существующие `prepare → validate`, а
назначенные ручные checks закрываются через `review`. Это механическая проверка
границ и сохранности, не автоматическое написание текста скриптом.

| Задача | Профиль / разрешения | Дополнительный источник и владелец | Инструмент / доставка |
|---|---|---|---|
| Корректура готового текста | `develop_existing / proofread` | Исходник и точная граница, без загрузки всего голоса | `author_workflow.py`, без публикации от одного сохранения |
| Структурировать готовый текст | `develop_existing / proofread` → `structure / structure_only` | Режимы редактуры; для статьи — [стандарт статьи](../../docs/knowledge-base/ARTICLE_STANDARD.md) | Два узких pack; защищённые цитаты остаются дословными |
| Исправить отдельный блок / только слова | `develop_existing / targeted_edit` либо `text_only` | `editable_scope` либо защищённый каркас из режимов редактуры | `author_workflow.py`, без попутной правки соседей |
| В одном исходнике «оставь / раскрой / найди / удали» | `develop_existing / rewrite`, затем структура при необходимости | `block_instructions` в режимах редактуры | Поиск только назначенных пробелов, потом проверка каждого защищённого блока |
| Голосовой набросок или видео → статья / сценарий | `transcript_to_article / rewrite` | Полная расшифровка, роль `article_source` / `video_script`, якоря и разрешённые удаления | `author_workflow.py`, лёгкий retrieval; новую расшифровку делает существующий локальный контур, не Писарь |
| Текст рядом с видео без пересказа видео | Профиль целевого текста, `transcript_role=context_only` | Оболочка дня / страницы и соседний материал | Контекст видео не становится скрытым `source_text` |
| Новый пост Telegram, личный, познавательный, продающий | `new_material / draft`, обычно `original_composition` | [Оформление, CTA и перелинковка](editorial-linking-v1.md); при продукте — [факты](product-fact-router.md) | `author_workflow.py`; готовый пост не означает отправку в канал |
| Подводка к статье, продолжение, серия, CTA | Профиль по наличию исходника | Перелинковка + адресный поиск прошлых постов; `platform.content` | `search_author_voice.py`, `author_workflow.py`; сохранить смысловую связь, не придумывать URL |
| Pikabu: самостоятельный пост, ответ, проверка старого прогноза | Профиль по исходнику, поверхность `pikabu_article` | Единый Писарь; дополнительный `edabalans-pikabu` — только по явному вызову владельца | Существующий [структурный адаптер](pikabu-structure-adapter-v1.md); обычное письмо для Pikabu не требует ручного вызова адаптера |
| Статья блога, перенос из Tilda / Pikabu / Telegraph | `develop_existing` с узким разрешением для переноса либо `new_material` | [Блоговый маршрут](../../docs/knowledge-base/BLOG_EDITORIAL_WORKFLOW.md), `platform.blog`; общий стандарт статьи | Чистое тело MD, manifest и локальные медиа; текущий выпуск — Git + deploy, не course API |
| Обычная статья МК | Профиль по исходнику, `masterclass_material` | [Редакционный вход МК](../masterclass/editorial/README.md), контекст дня; `products.masterclass.course` | Отдельная статья: `publish_course_material.py list/get/publish`; стабильный `step_id`, pass и версия |
| Дни МК, названия, порядок, подводки, время, задания | Профиль по исходнику, контекст всего набора | [program.md](../masterclass/editorial/program.md), редакционный вход МК; `products.masterclass.course` | Существующий `scripts.publish_masterclass_editorial` из backend; проверка, затем явная публикация набора. Старые `days/` и `source-current/` не редактируются вместо программы |
| Анкета МК, саморевью, предложение, DQS / приложение | Режим по назначенному текстовому слою | Редакционный вход МК, существующие коды вопросов / EMBED; профильный продукт владеет логикой | Поддержанные поля — публикатор редакционного набора, не CLI обычной статьи. Новая логика формы, покупок или приложения — отдельная разработка |
| Материал / день интенсива | Профиль по исходнику, `intensive_article`, для базовых блоков `authored_blocks_first` | [Контур интенсива](../../docs/INTENSIVE_PAGES.md), `products.intensive` | Существующий versioned intensive API для поддержанных блоков; разовые белые блоки и механика не переделываются общим MD-правилом |
| Полный курс, калорийный, тренировочный, рецепты | Профиль по исходникам; `course_continuity`, обычно `authored_blocks_first` | Карточка соответствующего продукта через `docs/modules.toml`, действующая программа и ближайшие принятые тексты | Писарь пишет текстовую часть; порядок, доступы и публикация остаются у продукта, единого API для всех курсов не объявлять |
| Welcome, до / после покупки, рассылка Telegram / MAX | Профиль по исходнику, контекст шага и CTA | [Сообщения Telegram](../../docs/knowledge-base/modules/telegram/MESSAGE_CONTENT_AUTHORING.md), карточка нужной цепочки; `messaging.telegram.*` / `messaging.max` | Рабочий MD по общему протоколу; технический CLI принимает Telegram HTML. MAX проверяется своим адаптером. Обновление текста не меняет граф и не разрешает массовую отправку |
| VSL, лендинг, реклама, продуктовая презентация, тексты кнопок | Профиль по исходнику, факты / CTA по необходимости | [Продуктовые факты](product-fact-router.md), актуальное ТЗ поверхности, [банк формулировок](marketing-thesis-bank-v1.md) как память; продукт / `marketing` / дизайн владеют своими ограничениями | Писарь не меняет цены, аудиторию рекламы, пиксели, платежи или CSS; доставку определяет существующая поверхность |
| Политика, оферта, юридическая страница | Преимущественно узкая адресная правка | Действующий юридический документ и его связи с согласиями / оплатами из карточки владельца | Не course API и не обычная статья без проверки версии и мест применения; юридическая формулировка не должна автоматически становиться голосовым эталоном |
| Найти нейрослоп, сравнить с голосом, без переписывания | Диагностика, не авторский рерайт | Глобальный `edabalans-neuroslop-auditor`; критерии принадлежат контракту голоса | Отдельный аудит по запросу; после команды исправить — снова Писарь и разрешённая граница |
| Новые источники, повторы, библиотека, развитие самого Писаря | Это обслуживание / исследование, не `draft` | `edabalans-librarian`, [библиотека](../../docs/KNOWLEDGE_LIBRARY.md), контракт приёмов; `platform.knowledge` / `platform.content` | Адресный поиск и диагностика. Не перестраивать корпус, паспорт и индексы при обычном написании поста |

Неизвестный случай сначала классифицируется внутри этих существующих профилей и
продуктовой границы. Если необходимого адаптера нет, подготовить текст и явно
назвать неподключённую доставку, не выдумывать универсальный публикатор.

## Источники и библиотеки

| Что это | За что отвечает | Чего не доказывает |
|---|---|---|
| `writer-contract-v1.md` | Нормативный голос и аргументация | Цены, наличие продукта, текущие API |
| `voice-rules-v1.json`, эталоны, correction chains | Области действия и доказательства голоса | Отдельную политику поверх контракта |
| Приватный `voice-passport-v1.md` и отчёты | Производный снимок анализа корпуса | Новую редакцию канона лишь потому, что файл большой или называется паспортом |
| Локальный поисковый корпус | Фразы, прежние мысли, источники и история вариантов | Актуальные условия продукта и одинаковую пригодность всех записей для голоса |
| Reviewed-библиотека приёмов | Проверенные механики с контекстом, функцией и provenance | Разрешение автоматически копировать фразы |
| Candidate-нарезка и старые review batches | Материал для адресного исследования | Семантическую проверку, даже если кандидатов много |
| Серверная библиотека и каталог публикаций | Навигация, полные URI, версии, права, использование | Вторую копию писательского канона; опубликованность нельзя выводить из наличия файла |
| Продуктовые каноны и runtime | Текущий состав, цена, доступы, названия, условия | Новый голос автора |
| Внешние референсы / научные источники | Идеи с provenance / доказательство точного тезиса | Чужой голос как эталон Сергея или подтверждение соседнего утверждения |
| `work/`, старые чаты и передачи | Происхождение решений, прерванный checkpoint | Актуальное правило, внедрение либо факт публикации |

Границы использования платного и личного: [редакционно-продуктовый контракт](../../docs/knowledge-base/EDITORIAL_PRODUCT_SYSTEM.md).
Читать платные тексты для точности и сильных блоков можно; публиковать всю платную
систему в открытом посте нельзя. Консультации не обезличиваются молча. Личное
здоровье и Нейроцех не входят в поисковый корпус Писаря по умолчанию.

Если knowledge MCP недоступен, читать известные точные источники по существующим
путям и фиксировать отсутствие MCP/provenance-регистрации в отчёте. Не создавать
ещё один локальный каталог и не заявлять, что событие использования записано на
сервер. Приватные исходники и correction memory не копируются в Git или Wiki.

|---|---|---|

| NOTE, цитата, обычная таблица, существующие специальные вставки | Поддержка есть в принятых renderer; набор каждой поверхности проверяется отдельно | Общий стандарт, каталог компонентов и продуктовый адаптер |
| NOTE-minus, LINK-кнопки, copy-блок, ✓/×, карточки таблицы, комментарии и расширенные выделения | Согласованы и проверены локальным прототипом; общая production-интеграция не подтверждена | [Сохранённый контракт переноса](../../docs/knowledge-base/MARKDOWN_MATERIAL_TRANSFER.md), [шпаргалка](../article-components/OBSIDIAN_CHEATSHEET.md), [передача дизайну](../article-components/DESIGN_HANDOFF.md) |
| Отдельный Pikabu-адаптер и отдельный аудитор нейрослопа | Существующие установленные навыки; их ранее локальные источники сохранены в этом контуре. Это не новые голоса или новые движки | [Pikabu](skill/edabalans-pikabu/SKILL.md), [аудитор](skill/edabalans-neuroslop-auditor/SKILL.md); глобальные установки находятся в `C:/Users/Segey/.codex/skills/` |
| Калибровка нового голоса владельцем | Финальная приёмка по серии новых задач не подтверждена | [CALIBRATION_V1.md](CALIBRATION_V1.md) |

Это состояние реализации на момент сведения 17.09.2026, не вечный production-флаг.
Конкретный материал имеет [четыре независимых статуса](material-status-v1.md).
Сохранение MD, Git-коммит, pass валидатора, принятие Сергеем и публикация — разные
события. Коммит Писаря не публикует курс и не отправляет сообщение человеку.

Расширенный Markdown-контракт ниже сохраняется **как draft существующей работы**,
не подменяет текущий `ARTICLE_STANDARD.md` и не объявляет прототип установленным.
Новый авторский файл использует поддержанную разметку своей поверхности; если
потребовался ещё не подключённый блок, это задача адаптера, не повод вставить HTML.

В текущем сведении устранены старое автоматическое «Важно» в маршрутизаторе,
устаревший путь редактуры МК и принудительный `rewrite` для любой доработки.
Разведены рабочий MD и технический Telegram HTML, обычная API-публикация и
выпуск кода. Быстрый маршрут сохранён: без повторного содержательного сравнения,
но с существующим техническим publish gate и защитой версии.

Из прежней локальной редакции канона сохранены намеренные повторы существительных,
запрет мата на публичном сайте и согласованные входы в интенсив от 05.09.2026.
Их владельцы — контракт голоса / машинные доказательства и документ перелинковки,
не эта историческая заметка. Текущие локальные изменения темы статьи и дизайна
не перенесены поверх принятого оформления: их интегрирует дизайнерский поток.

Найденная приватная `pending-owner-editorial-notes.md` не удалена: это накопитель
отложенных замечаний владельца. Совпадающая граница раскрытия уже находится в
редакционно-продуктовом каноне; сам накопитель не загружается как второй закон.
Не заявляем, что прочитана вся история всех задач: карту продолжают по точным
ссылкам и подтверждённым изменениям, без бесконечного обхода чужих чатов.

## Нормативные источники и доказательства

Все правила письма изменяются только в этом модуле. `writer-contract-v1.md`
владеет голосом, аргументацией и продажами, `authoring-work-profiles-v1.md` —
выбором авторского маршрута, `editing-modes-v1.md` — разрешениями на изменение
исходника. Skill, индексы, JSON-правила, примеры и коррекционные
кейсы маршрутизируют и доказывают этот единый канон, но не создают параллельную
редакторскую политику.

- `writer-contract-v1.md` — обязательный runtime-контракт писателя;
- `authoring-work-profiles-v1.md` — четыре рабочих профиля: структура,
  транскрипт → статья, новый материал и развитие готовой статьи;
- `editing-modes-v1.md` — режимы правки и защищённые слои исходного текста;
- `skill/edabalans-writer/SKILL.md` — обязательная точка входа любой писательской
  задачи; навык маршрутизирует контекст, но не дублирует правила контракта;
- `product-fact-router.md` — карта текущих владельцев продуктовых фактов;
- `platform-adaptation-v1.md` — условное подключение площадочных правил и
  проверка ссылок/формата; общий голос и техническую доставку не дублирует;
- `docs/knowledge-base/ARTICLE_STANDARD.md` — единая структура и оформление
  статей сайта и материалов любых курсов; писатель применяет её по контексту, а
  не хранит отдельную копию правил внутри каждого продукта;
- `editorial-linking-v1.md` — Telegram-оформление, CTA-ссылки, комментарии,
  проверенные входы в интенсив и паутина материалов;
- `source-integration-pass-v1.md` — адаптивная цепочка карты авторского нажима,
  поиска, отбора, встраивания и проверки доказательных ссылок после сборки
  текста;
- `source-review-registry-v1.json` — дата, версия текста, версия политики,
  глубина и статус проверки источников; прежний проход хранится как `legacy`, а
  не приравнивается к текущему полному;
- `material-status-v1.md` — четыре независимые оси состояния материала:
  редакторский этап, проверка Сергеем, проверка источников и фактическая
  доставка; здесь же живут ledger замечаний и формат отчёта с до/после;
- `author-task.schema.json` — машинная форма новой авторской задачи;
- `article-component-router.md` — человекочитаемый маршрут безопасных вставок;
- `voice-rules-v1.json` — правила с областью действия, контрграницей и ID доказательств;
- `semantic-exemplars-v1.json` — отобранные ID эталонов и их композиционные роли.
- `CALIBRATION_V1.md` — пять задач и единый порог пользовательской приёмки.
- `telegram-linkout-review-v1.json` — проверенная полнота 36 Telegram-подводок к Pikabu.
- `semantic-review-log-v1.json` — покрытие расширенного ядра, явные overrides и
  оставшийся калибровочный gate.
- `rhetorical-library-contract-v1.md` — граница между механическими кандидатами
  и пофрагментно проверенной библиотекой.
- `marketing-thesis-bank-v1.md` — owner-reviewed банк сильных маркетинговых
  формулировок и смысловых ходов для сайта, интенсива, писем и Telegram; это
  память вариантов, а не второй свод правил голоса.
- `rhetorical-review-hook-001.json` — первая безопасная таблица решений по хукам;
  полные фрагменты по этим ID остаются в приватном корпусе.
- `rhetorical-review-reframe-001.json` — проверенные способы смыслового
  разворота и перехода от очевидного объяснения к авторскому критерию.
- `correction-nutritionists-law-v1.json` — безопасные метаданные эталонной
  correction chain; сами версии текста хранятся приватно.
- `cases/cutlets.md` и `cases/nutritionists-law.md` — два утверждённых учебных
  разбора правок; это доказательства контракта, а не альтернативные инструкции.

Полные публикации, цитаты, evidence pack, correction memory и SQLite-индексы находятся
вне Git: `C:\private\edabalans-content-authoring\voice\v1`. Исходники не изменяются.

Каноническая приватная память резервируется отдельно от Git зашифрованным архивом:
`tools/backup_author_memory.py` собирает `voice/v1`, correction chains и глобальный
workflow, добавляет манифест с SHA-256 и шифрует AES-256-GCM до отправки. В Object
Storage передаётся только зашифрованный архив, его checksum и безопасные metadata;
ключ хранится отдельно на компьютере владельца и в root-only конфигурации VM.

Correction memory — это не список коротких запретов, а наследие редакторской
работы для будущих моделей. Для существенной правки сохраняются точный запрос,
ссылки или хеши исходников, различающиеся версии ИИ, все раунды замечаний
Сергея, авторская редакция и финал, пары «до → после», положительные и
отрицательные примеры, примеры применения, контрграницы и объяснение функции правки. Промежуточная
неудачная версия не удаляется. Устойчивый вывод повышается в канон, а полные
тексты и история остаются приватными.

## Три слоя корпуса

- **Ядро голоса.** Полные проверенные тексты определяют устойчивые
  композиционные решения и имеют повышенный вес при подготовке нового текста.
- **Поисковый корпус.** Он используется для поиска фактуры, старых мыслей,
  редких заходов и подходящих примеров по теме. Он не голосует за правила всем
  массивом сразу, поэтому слабый старый пост не размывает сильное ядро.
- **Функциональные фрагменты.** Короткие подводки и самостоятельные детали могут
  дать хук, переход, CTA или формулировку, но не подменяют собой пример
  полноценного поста.

Актуальные количества принадлежат приватному индексу и его health/report
инструментам; в канонической документации они не фиксируются вручную.

Материал вне ядра влияет на конкретный текст только после адресного поиска. Если
он показывает устойчивый новый приём или лучше существующего эталона, его можно
поднять в ядро; простое наличие в архиве голос автоматически не меняет.

Материал можно повысить в ядро поверх механической фильтрации только сильным
семантическим review. Каждый такой случай имеет явный `eligibility_override` в
`semantic-exemplars-v1.json`; без него материализация не пропускает конфликтующий
ID. Текущий состав override берётся из этого реестра, а не из README.

Технические шаблоны конструктора остаются в индексе ради полноты каталога, но
автоматически помечаются и не передаются писателю в `topic_history`.

## Рабочий маршрут

1. По теме и задаче локально найти пропорциональный набор полных эталонов,
   упоминаний из поискового корпуса, подходящие
   `semantic_reviewed` риторические фрагменты и подтверждённые правки через
   `tools/search_author_voice.py`. Непроверенные кандидаты доступны только явным
   режимом исследования.
   Для нового текста `tools/author_workflow.py prepare` вызывает
   `tools/prepare_author_post.py` и собирает это в компактный
  retrieval pack вместе с проверяемым content contract. В пакет писателя
   входят полные тексты эталонов и correction chains; тематическая история
   передаётся компактными фрагментами. Связанные платформенные версии занимают
   один слот, а выбранная площадка получает мягкий, не абсолютный приоритет.
   Технические шаблоны конструктора остаются доступны явному поиску, но не
   попадают в `topic_history` писателя.
   Для базового материала с каркасом `author_reuse_mode=authored_blocks_first`
   дополнительно запускает отдельный поиск по каждому элементу `block_outline`:
   сильные авторские блоки становятся исходником для дословного переноса или
   минимальной правки краёв, а не референсом для нового пересказа. Рядовой новый
   Telegram-пост по умолчанию использует `original_composition`.
   Разные комментарии внутри одного исходника маршрутизируются в
   `block_instructions` по `editing-modes-v1.md`.
2. Взять факты из заметки пользователя и актуальных продуктовых источников, а не
   из старых рекламных публикаций.
3. До формулировок собрать маршрут эмоции и аргумента, выбрать рабочий профиль,
   затем режим `draft`,
   `targeted_edit`, `proofread`, `structure_only`, `text_only`, `rewrite` или
   `creative_rebuild`, затем применить
   `writer-contract-v1.md`, адаптировав длину и CTA под контекст площадки.
   Для статьи сайта или материала курса дополнительно применить единый стандарт
    статей и структурный/визуальный контракт оболочки курса. В `structure_only`
    голосовой retrieval не выполняется: формулировки защищены целиком.
4. Если материал содержит доказательные ссылки, отдельно и последовательно
   пройти `source-integration-pass-v1.md`: сначала ранжировать авторские поинты,
   затем найти кандидатов, оценить отбор и плотность и только потом встраивать
   ссылки. Результат каждого прогона меняет следующий. После завершения обновить
   `source-review-registry-v1.json` для точной версии текста.
5. Вернуть готовый текст. Не заставлять владельца заранее выбирать хук или
   эталон. Применить проверочную политику выбранного режима из
   `editing-modes-v1.md` или `writer-contract-v1.md`; retrieval pack только
   указывает на эту политику и не копирует её.
6. Существенную правку записать через `tools/record_author_correction.py`; цепочку
   из истории Codex можно сохранить без копирования полных текстов в Git через
   `tools/record_author_correction_from_codex.py`.

`tools/build_rhetorical_library.py` локально строит кандидатов из всего
согласованного корпуса, выбирает стратифицированные партии, применяет безопасные
решения review и ведёт приватный ledger. Статус `semantic_reviewed` нельзя получить
одной механической нарезкой.

Поиск принимает обычную русскую фразу. Полный архив в модель не загружается.

## Инструменты

**Runtime:** `author_workflow.py`, `prepare_author_post.py`,
`validate_author_draft.py`, `search_author_voice.py`.

Новая содержательная задача явно записывает `source_basis` и
`author_reuse_mode`. Транскрипт получает
роль `article_source`, `video_script` или `context_only`; отдельный материал
курса передаёт в pack оболочку дня и карту преемственности. Эти поля являются
маршрутизацией существующего канона, а не отдельным паспортом голоса.

**Обслуживание корпуса:** `refresh_author_workspace.py`,
`record_author_correction.py`, `materialize_author_voice.py`,
`build_rhetorical_library.py`.

После старого импорта, выполненного до синхронного обновления счётчиков, один раз
допустимо вызвать `record_author_correction.py --sync-derived --memory ...`.
Обычная запись correction обновляет semantic report и analysis state сама.

**Импорт:** `collect_public_site.py`, `collect_telegraph.py`,
`build_author_working_corpus.py`, `export_author_corpus.py`.

**Диагностика:** `report_author_corpus_health.py`, `report_voice_core.py`,
`verify_author_corpus.py`, `compare_author_texts.py`.

`refresh_author_workspace.py` и `report_author_corpus_health.py` всегда требуют
явный приватный `--voice`: успешный health без проверки correction memory,
SQLite-индекса, semantic report, analysis state и установленного skill невозможен.

## Обслуживание установленного skill

Канонический package находится в
`content/author-voice/skill/edabalans-writer/`. После изменения skill или любого
контракта из manifest запустить
`tools/install_edabalans_writer_skill.py --install`; `--check` только проверяет
управляемую runtime-копию, package version и SHA-256 всего комплекта. Установщик
не создаёт hard link на рабочий checkout: незакоммиченная правка одного чата не
должна менять правила другого. Эти действия относятся к
обслуживанию модуля и не выполняются внутри обычной писательской задачи.
