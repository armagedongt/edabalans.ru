# Correction log: совместная работа

Append-only журнал. Текущий протокол живёт в `collaboration-workflow.md`; здесь
сохраняется происхождение коррекции.

## 2026-08-30 · Один блок за цикл

**Было:** предложено сразу показать цельный фрагмент из hero, программы, продукта,
автора, тарифа и FAQ.  
**Коррекция Сергея:** обсуждать header, hero, программу, автора, тарифы, FAQ и
остальные части отдельно.  
**Правило:** один смысловой блок — один цикл принятия; сборка страницы начинается
после принятия составляющих.

## 2026-08-30 · Показ внутри чата

**Было:** текстовый wireframe и будущая отдельная preview-страница.  
**Коррекция Сергея:** на раннем этапе нужен небольшой запускаемый mobile mockup
прямо в чате, без локального сайта и переключения между поверхностями.  
**Правило:** ранние дизайн-итерации показываются inline; внешняя preview нужна
только после принятия блоков.

## 2026-08-30 · Два вида памяти

**Было:** решения и референсы сохранялись в одном рабочем контексте сайта.  
**Коррекция Сергея:** отдельно хранить устойчивые вкусы в дизайне и отдельно —
правила организации совместной работы; оба журнала обновлять после циклов.  
**Правило:** design memory и workflow memory не смешиваются; другой чат получает
обе вместе со статусом текущих блоков.

## 2026-08-30 · Живой референс до первого показа

**Было:** референсы были разобраны словами, а mockup собран без проверки
фактического mobile-блока.  
**Коррекция Сергея:** результат оказался лишь отдалённо похож на Нейроцех.  
**Правило:** если дан URL и назван конкретный блок, до показа открыть его,
проверить mobile-вид и снять основные визуальные параметры. Только затем
интерпретировать под содержание Сергея.

## 2026-08-30 · Визуальный паттерн не определяет содержание страницы

**Было:** после согласования синего паттерна работа ушла в перебор разных текстов,
которые можно поместить внутрь него, без привязки к общей архитектуре главной.
**Коррекция Сергея:** сначала дизайнер сам определяет смысловые блоки страницы,
функцию каждого текста и подходящую форму подачи; владелец не должен собирать
страницу из понравившихся декоративных элементов.
**Правило:** порядок работы — архитектура страницы → функция блока → содержание →
форма подачи → визуальный паттерн. После локальной визуальной развилки всегда
возвращаться к реестру страницы и вести Сергея к следующему решению.

## 2026-08-30 · Принятый основной вариант не заменяется экспериментом

**Было:** переключатель содержал основной VIP-вариант и старый светлый форк;
следующая визуальная идея могла восприниматься как новая замена всей версии.  
**Коррекция Сергея:** выбранный вариант нужно сохранять основным, старые ненужные
форки убирать, а новые идеи добавлять отдельным наследственным форком.  
**Правило:** основной вариант всегда открывается первым и остаётся неизменной
точкой сравнения; форк меняет только явно проверяемую визуальную гипотезу при том
же тексте и структуре.

## 2026-08-31 · Не строить интерфейс для запроса на отдельные ассеты

**Было:** вместо четырёх картинок появился полноценный preview личного кабинета с
переключателями вариантов.  
**Коррекция Сергея:** нужны только отдельные изображения, без страницы и
конструктора.  
**Правило:** если единица согласования — набор картинок или иконок, показывать и
сохранять именно ассеты. Не расширять задачу до страницы, навигации или выбора
вариантов без прямой просьбы.

## 2026-08-31 · Названный блок референса проверяется перед каждым новым макетом

**Было:** проектная память уже содержала ссылку на секцию `Интенсив ведет Егор
Соколов`, но перед созданием авторского блока была использована только общая
память о стиле Нейроцеха.  
**Коррекция Сергея:** перечитать все надиктованные указания и вернуться к точному
источнику, а не импровизировать поверх общего moodboard.  
**Правило:** если Сергей назвал конкретную секцию страницы, до кода заново открыть
её в desktop и mobile, зафиксировать порядок DOM-блоков, фон, сетку, положение
фото, текстовую плотность, акцент и нижние карточки. Эти параметры входят в brief
как обязательные. Общая дизайн-память не заменяет эту сверку.
