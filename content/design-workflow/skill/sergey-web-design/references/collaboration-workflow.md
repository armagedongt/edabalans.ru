# Workflow согласования web-дизайна с Сергеем

Статус: `current`  
Область: `cross_project: true`  
Обновлено: 30.08.2026

## Единица работы

Один цикл — один смысловой блок. Примеры: header, hero, программа, автор, продукты,
тарифы, гарантия, FAQ. Большой экран не считается одним блоком, если в нём несколько
независимых решений.

## Цикл блока

1. Собрать факты, назначение и обязательное содержание блока.
2. Отделить факты от рабочих формулировок и визуальных гипотез.
3. Если Сергей указал точный web-референс, перед первым mockup открыть его в
   целевом viewport, снять структуру, размеры, шрифты, веса, тени, радиусы и
   интервалы нужного блока. Словесный moodboard не считается такой проверкой.
4. Если есть реальная развилка, подготовить 2–3 различающихся варианта на одном
   содержании.
5. Показать один mobile-first inline mockup прямо в чате; варианты переключаются
   внутри него, чтобы Сергей не ходил между страницами.
6. Коротко назвать только решения, которые mockup помогает принять.
7. Получить реакцию: нравится, не нравится, что изменить, чего не хватает и почему
   выбран такой объём текста.
8. Исправить текущий блок и обновить design/workflow correction logs.
9. Зафиксировать статус блока: `draft`, `revision`, `accepted`, `deferred`.
10. Переходить дальше только после принятия либо явного откладывания блока.

После того как один вариант блока выбран основным, следующие визуальные гипотезы
не заменяют и не ослабляют его. Основной вариант остаётся первым и открывается по
умолчанию, а каждая новая гипотеза показывается рядом как отдельный именованный
форк на том же содержании.

## Формат показа

- По умолчанию — телефон шириной около 360–390 px внутри разговора.
- Не создавать отдельный локальный сайт или боковую preview-страницу для раннего
  согласования.
- Mockup должен запускаться штатной кнопкой разговора и содержать только текущий
  блок.
- Первый экран полезен сразу; интерактив добавляется только для реального
  состояния: переключение варианта, accordion, slider, tooltip.
- Desktop-проверка идёт после принятия мобильной логики блока.

## Работа с текстом

- Сергей может спрашивать, почему текст короткий, длинный или стоит именно здесь.
  Отвечать через функцию блока: что человек должен понять и какое действие сделать.
- Не защищать рабочий текст как готовый. Отделять placeholder, структурную подпись
  и финальную авторскую копию.
- Для edabalans.ru финальный пользовательский текст проходит `edabalans-writer` и
  продуктовые источники; дизайн задаёт роль, лимит и место.

## Сборка страницы

После принятия блоков:

1. собрать их порядок и переходы;
2. проверить повторения, контраст, общий ритм и число CTA;
3. показать цельную mobile-страницу;
4. собрать desktop;
5. реализовать внешний `noindex` preview-loader;
6. после приёмки выпустить автономный production T123.
