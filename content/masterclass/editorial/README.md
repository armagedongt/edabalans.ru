# Редакторский канон Мастер-класса

Эта папка предназначена для прямой редактуры курса в Markdown без старой админки.
Пока владелец не дал отдельную команду на публикацию, изменения отсюда не попадают
на сервер.

## Что где менять

- `program.md` — единственный редакторский источник названий дней, порядка и
  названий материалов. В оглавлении показываются только номер, название и
  примерное время. Описаний карточек материалов больше нет.
- `days/` — тексты дня и задания. Исторические разделы «Перед вводным медиа»,
  «После вводного медиа» и «Перед заданием» при показе объединяются в один блок
  под медиа, перед материалами. Их содержимое не сокращается автоматически.
- `materials/` — текст каждого самостоятельного материала. Заголовок в начале
  файла повторяет название из `program.md` только для удобства чтения и при
  сборке проверяется на совпадение.

## Типы материалов

В начале каждого файла есть короткая служебная строка `Тип`:

- `статья` — после Markdown ничего автоматически не вставляется;
- `анкета` — после Markdown открывается указанная анкета;
- `приложение` — после Markdown открывается указанное приложение;
- `допродажа` — после Markdown вставляется универсальный блок дополнительных
  предложений. Текст до блока индивидуален и редактируется в этом файле;
- `заглушка доступа` — вместо закрытого дня показывается этот текст и кнопка
  покупки. Сами права доступа остаются в коде, а не в Markdown.

Строки внутри HTML-комментариев — техническая привязка к стабильным ID. Их не
редактировать: благодаря им переименование заголовка не сбрасывает прогресс
участников.

## Правила названий

- В конце названия материала точка не ставится.
- Описание материала в карточке не используется.
- Название в оглавлении, на странице дня и на странице материала берётся из
  `program.md` при сборке.
- Имя файла сделано читаемым, но техническая идентичность задаётся `step_id`, а
  не именем файла.

## Публикация

Сейчас папка является подготовленным редакторским каноном. Скрипт
`backend/scripts/bootstrap_masterclass_editorial.py` использовался только для
первичного копирования и никогда не перезаписывает уже существующие файлы. Старую
папку `source-current/` после этого считаем миграционным источником, а не вторым
местом редактуры.

Синхронизатор уже существует: `backend/scripts/publish_masterclass_editorial.py`.
Без `--publish` он только проверяет сборку; с этим флагом публикует структуру,
вводные тексты, специальные вставки и обычные статьи одной транзакцией. Он
сохраняет ID и переносит индексы прогресса, если порядок шагов изменился.
Запускать публикацию без прямой команды владельца нельзя. Нельзя запускать
`bootstrap` заново для восстановления или заменять эту папку миграционным seed.

Фактический экран читает опубликованные версии из БД: активную структуру
`course-structure/masterclass-21` и версии `masterclass-course-materials`.
`course/course.json` — seed/fallback, а не второй редактируемый оригинал.
17.09.2026 перед переносом визуала сверены 20 дней и 36 обычных статей: сравниваемые
названия, вводные тексты, задания, порядок/скрытость шагов и HTML статей совпали.
Сверка не означает повторную публикацию и не проверяет содержание всех специальных
приложений. Стабильные технические имена `masterclass-21` сохранены намеренно.

Название меняют в `program.md`; заголовок связанного файла материала должен ему
соответствовать (это проверяет валидатор). Все экранные названия берутся из одной
опубликованной структуры. После правки запустить валидатор и сухую сборку, затем
по команде владельца — существующий синхронизатор; проверить новую версию и экран.
Прямой PUT одного материала годится для тела обычной статьи, но не меняет название
её карточки или порядок: для таких правок нужен синхронизатор.

## Оформление без редактуры текста

Общий текстовый стандарт: `docs/knowledge-base/ARTICLE_STANDARD.md`.
Каталог повторяемых блоков: `content/article-components/README.md`.
Паспорт оболочки: `docs/knowledge-base/modules/masterclass/COURSE_VISUAL_SYSTEM.md`.
В MD не копируют цвета, CSS, HTML оболочки или JavaScript. DQS, слайдер и спойлер
используют существующие продуктовые вызовы из `content/masterclass/components/`.

В MD первых пяти дней прежние цитаты-акценты уже записаны как `[!NOTE]`:
23 блока в материалах об ограничениях и DQS, без изменения авторских слов,
ссылок и компонентных вызовов. Старые опубликованные версии пока показываются
жёлтыми через ограниченную совместимость; после следующей публикации оформления
это правило больше не участвует, потому что цвет определяется NOTE в самом MD.
Обычный `>` в будущих текстах остаётся цитатой. Перепубликация всех статей ради
выпуска CSS не производится.

После согласования того же перевода для дней 6–20 выполнена механическая
нормализация семи MD: 18 прежних цитат-акцентов стали явным NOTE, одна прежняя
`:::note` — обычной цитатой. Удалены семь пустых одиночных маркеров `>` в
путеводителе по зависимостям: они не содержали текста. Авторские слова, ссылки,
ID, порядок и компонентные вызовы не менялись. Материалы без старых выделений
не переписывались. Публикация этих MD в БД отдельно не выполнялась.

### Границы специальных шагов

У анкеты публикуется только подводка до `## Вопросы`. Список вопросов ниже —
справочная копия, не рабочий источник формы: сами вопросы пока принадлежат
`backend/app/masterclass_routes.py`. Их изменение требует отдельной реализации,
не только публикации MD. Не обещать владельцу автоматическое применение этих строк.
Два файла `07-00-приобрести-систему-рецептов.md` и
`15-00-приобрести-каталог-рецептов.md` пока не подключены синхронизатором:
текст закрытого recipe-gate остаётся у `masterclass.js`. Это подготовленные
редакторские материалы, не второй действующий источник экрана. Подводки обычных
номерных допродаж, напротив, публикуются через `special_prelude` до EMBED-маркера.

Для будущей редактуры ориентир единственного вводного блока — до 350 знаков,
один абзац или два коротких. Сейчас существующее содержание не сокращалось.
Функция блока — объяснить название дня, зачем ему посвящён отдельный день,
что примерно ждёт в материалах и почему это важно. Это не остаток после удаления
дублей: краткое повторение главного тезиса видео или материалов допустимо и нужно.
Подробные инструкции, развёрнутые задания, внешние ссылки и длинные пояснения
в короткий вводный блок не входят.
350–1000 знаков — показать владельцу кандидатом на сжатие/вынос; более 1000 —
обязательно показать кандидатом. Новые самостоятельные материалы автоматически
не создаются, длинные вводные пока остаются в том же блоке.

При будущей редактуре длинный фрагмент переносится в существующий материал,
если раскрывает его тему, либо становится обычным самостоятельным микро-материалом.
Его место определяется смысловым маршрутом, а не новым типом интерфейса.
Принятые редакционные кандидаты, ещё не созданные: завершающая практика дня 3
«Практика: что из “вредного” ограничить, а что оставить» после 03-01/02/03,
с двумя списками и дополнительными ссылками в конце; стартовый материал дня 7
«Как устроена Система рецептов». Эти примеры не являются командой создать
карточки или менять текущие авторские тексты при выпуске визуала.

Известное редакционное расхождение: день 8 ссылается на отсутствующий файл
`materials/08-02-дополнительные-материалы.md`. Не создавать текст или рабочую
карточку по этой ссылке автоматически; решение о материале остаётся у владельца.
