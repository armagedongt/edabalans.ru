# Правила библиотеки смысловых источников

Статус: `archived — заменено серверным контрактом`

Актуальные правила: [`docs/KNOWLEDGE_LIBRARY.md`](../../docs/KNOWLEDGE_LIBRARY.md)

Ниже сохранён исторический черновик первой инвентаризации. Его нельзя применять
к новым источникам. В частности, он устарел в двух критичных местах: raw нельзя
удалять только потому, что часть материала переработана, а консультации нельзя
обезличивать без прямой команды Сергея. Неясные совпадения, закрытие и права
теперь попадают в серверную очередь Библиотекаря.

## 1. Принять источник

Для любого нового файла/ссылки сначала определить:

1. что это: видео, аудио, стрим, урок, VSL, отзыв, голосовое, внешний источник,
   бизнес-решение или инсайт;
2. кто владеет актуальным фактом;
3. есть ли уже такой оригинал, версия, транскрипт, статья или публикация;
4. нужен ли источник как самостоятельный reference, или его смысл сразу должен
   жить в конкретном материале/плане.

До этой проверки ничего не переименовывать, не переносить и не удалять.

## 2. Подготовить смысл, а не голую копию

Видео и аудио получают полный структурированный текст: без потери содержания,
но с блоками, таймкодами и типами реплик. Для длинного эфира дополнительно
делается карта вопросов, где видны продажа, методология, история, Q&A и
неиспользованные идеи.

Учебное видео получает статью-компаньон, если его смысл нужен для курса, ответа
ученику или будущего использования. VSL, презентация и отзыв получают карту
назначения, а не автоматически становятся источником текущих цен и обещаний.

## 3. Выбрать один конечный дом каждой идеи

| Случай | Конечный дом |
| --- | --- |
| Смысл уже полностью оформлен для ученика | текущий материал соответствующего продукта |
| Идея нужна для нового ролика/раздела, но материала ещё нет | конкретная карточка будущего видео/плана |
| Стрим ещё содержит неразобранные полезные темы | структурированная расшифровка и карта стрима в библиотеке |
| Источник нужен только как контекст/история | библиотечный reference |
| Смысл не нужен | никуда не переносить; отметить причину закрытия |

Нельзя одновременно держать одну и ту же готовую мысль в материале, отдельной
статье и транскрипте без разных ролей.

## 4. Закрыть источник

Источник получает `decomposed_and_retired`, когда:

1. все полезные интервалы разнесены по конечным домам;
2. каждый такой дом записан в `links`;
3. оставшийся текст/видео точно не нужен для старого продукта, монтажа, истории
   или новых идей;
4. проверены внешние ссылки и сохранена резервная копия, если она нужна.

Тогда raw, структурированный текст и неиспользуемый медиафайл можно удалить.
В реестре остаются название, оригинальный путь/ID, версия, список сохранённых
частей и причина закрытия. Это память о происхождении, а не ещё одна копия.

## 5. Переименовать

Общий стем для связанных файлов:

```text
<дата> — <область> — <тип> — <тема> — <различие версии> — <длительность>
```

Пример:

```text
2025-06-20 — МК — стрим — Вредная еда — расширенная версия — 2ч37м13с.mp4
2025-06-20 — МК — стрим — Вредная еда — расширенная версия — 2ч37м13с — структурированный транскрипт.md
```

Дата и различие версии добавляются только когда они известны. При переименовании
обновляются все связи, а `id` реестра остаётся прежним.

## 6. Проверить и только потом чистить

Перед удалением обязательно проверить:

- точность/роль дубликата;
- ссылки текущего и старого продукта, Tilda, Boomstream и публикаций;
- есть ли у файла единственная версия;
- есть ли у каждого сохраняемого фрагмента конечный дом;
- есть ли резервная копия, если она нужна.

Выход каждого прохода — отдельная таблица: `сохранить`, `перенести`, `закрыть`,
`кандидат на удаление`, `неясно`. Удаление выполняется отдельной операцией.

## 7. Границы данных

Историческая формулировка этого раздела отменена. Персональные консультации и
анкеты хранятся только в закрытом серверном контуре с `restricted_personal` и
реальной связью с человеком. Обезличенная производная создаётся лишь по прямой
команде Сергея перед использованием в публикации. Живые цены и доступы остаются
у своих runtime-владельцев.
